- **Statement**: Re-drawn twice, the scene-constant 2 m map error leaves the benefit of registration + trust intact: in at least two of the three failure types, registered minus unregistered F1@1 (failure half, VAL failure series) is >= +0.015, and registered minus no map is >= +0.015.
- **Mechanism / why it was never controlled**: the map error is `crc32(scene) + 3`: one fixed draw per scene, never repeated. The loop-18 claim "registration recovers about half of the gap between no map and an exact map" (PROBLEM.md gap 4) rests on this single draw, 22 scenes, one registration run, 154 failure frames per type. Night: S none 0.651 / unregistered 0.643 / registered 0.664 / exact 0.676, so the S gate (none + 0.015) was missed by 0.004 and the recovery is 52 % in S, 64 % in F1@1; R2 - U2 F1@1 is +0.027 with the interval [+0.000, +0.059] (night) and +0.028 [+0.015, +0.044] (blur). Scene-wise bootstrap resamples scenes but not the map-error draw, so the interval understates the variance of a quantity that is one realisation per scene. An unregistered 2 m map is below no map in S (0.643 < 0.651), a fact that the "half the gap" wording hides. If a different draw moves the recovery from 50 % to 20 % the registration module is not worth its trust gate.
- **Prediction**: mean of the two new draws, night / blur / cam_front3_off: F1@1 R2 - U2 about +0.020 each (original +0.027 / +0.028), R2 - none about +0.025 (original +0.035 / +0.031); recovery fraction of (exact - none) in F1@1 between 0.40 and 0.70 for the pooled failure types. A shrink of 25 - 30 % from the original draw is expected (a selected favourable draw regresses).
- **Decision rule**: KEEP (gap 4 and the registration claim stand with a replicate) if both clauses hold in >= 2 of 3 types in the mean of the two draws, and each single draw has the same sign in every type that passes; CUT if R2 - U2 < +0.005 in at least two types (registration adds nothing beyond the draw it was reported on; PROBLEM.md gap 4 must be reworded, the module is a candidate for removal); TIE if between (+0.005 and +0.015): the module stays, the claim is "small". Noise band 0.010 in F1@1; the difference between the two draws of the same cell (the measured draw spread) is reported next to it and, if larger than 0.015, the rule is INCONCLUSIVE and a third draw is added.
- **Test design**: arms a (R2) and c (U2) on draws 1 and 2 (seed twin = the draws; draw 3 is the stored one and is the layer-1 reproduction), n (no map) and x (exact) are draw independent and reused from E213.b. Controls: matched reference = U2 and none on the same frames; null = none; oracle = exact (a bound only for the map, not for the chain); equal budget = the same chain and checkpoints (builder B + gate, `e17_map_b`, `regis_a`). Commands as `_run_r21b.sh`: `p18_regis_eval.py --regis regis_a --out regis_eval_a_d<k> --tags dark_gateB,blur_gateB,cam_front3_off_gateB --sigmas 2 --map_seed k` and `p17_eval.py ... --map_mode exact --map_sigma 2 [--reg ...] --map_seed k`. Fidelity rung: layer 3-4 on the loop-17 failure series (22 VAL scenes), paired scene bootstrap per draw.
- **Cost**: about 0.5 GPU h (two draws x [registration eval + U2 + R2 for three failure series], each cell ran 24 - 26 min for all sigmas and variants in E213.a / b; sigma 2 only is a third of it); coding 0.2 day for `--map_seed` through `sd_lib.py` / `MapWrap` / `RegMapWrap` / `p18_regis_eval.py` (default 3 = stored). Risk: low. The test of the plumbing: seed 3 reproduces the stored U2 / R2 cells (night S 0.643 / 0.664) within 0.001.
- **Kill criterion**: stop if seed 3 does not reproduce the stored cells; stop after draw 1 if R2 - U2 is already <= -0.01 in all three types (then add the diagnosis, not draw 2).
- **Inputs**: ready: chain checkpoints, `regis_a`, series features, baselines of E213.b (`runs/e17/e140_gateB`). To build: the `--map_seed` parameter (shared code in `training/data/sd_lib.py` and `training/models/p17_mapnet.py`, ar-reviewer pass in mode code).
