### 3.20 Loop 14: the planner interface of the learned chain, failure training and memory, route attribute learned from the planner loss (how the literature entered; what each element gave in our experiments)

Loop 14 asked four things: does the output of the learned chain (trace network, route head) work as an interface for a learned planner-side network, how does that interface behave under sensor failure with and without memory and failure training, do verifier probabilities or the step tokens help when they are handed over as inputs, and does the planner loss train the navigation module. The works below were looked up for this loop (arXiv abstract pages, 2026-10-19; (abs) = abstract only, nothing from the full text); all are 2025 or 2026. The last column is ours (nuScenes TEST, camera + radar BEV features, 21 scenes, simulated navigation map, synthetic failures; sections 7.42 - 7.45). Among the works found we did not see one that hands a lane graph with a per-element navigation attribute to a planner, and none for lane graphs from camera + radar; this is a statement about the search, not about the field.

**Building blocks of the interface, as used so far (short list; the catalogue is in section 3.15, the composition in 7.22).** (1) Convolutional network on the SD-map raster (route head). (2) Self-attention over a list of tokens (vertex tokens in the route head, edge tokens in the consumer). (3) Cross-attention that pulls from another list (vertex tokens from SD-map tokens; learned path queries from the edge tokens). (4) Learned queries as outputs (8 path points). (5) MLP verifiers on tokens (piece, junction), with a discrete edit (cut) or as soft attributes. (6) Memory at the input (ego-motion warp with a monitored hold or a per-pixel maximum with decay; a recurrent GRU-type memory was not part of this loop). (7) Gating and parallel paths (ego path next to the transformer; the learned gate of E115e stayed constant). (8) Loss coupling (planner loss through the sigmoid of the route head to its cross-attention; E119). Each block can be re-tuned to its function, for instance the cross-attention of the route head also receives the vertex token itself (gated fusion of input and cross-attention output, E104b).
