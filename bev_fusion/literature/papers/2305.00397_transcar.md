**What it does** [checked]: DETR3D-like camera queries (Hungarian loss, no NMS) are matched to radar by a transformer decoder whose cross-attention learns the soft association instead of a calibration-based gate. Radar processing: points filtered to the +-50 m BEV box; the previous 5 frames are accumulated and transformed into the current frame; the 18 nuScenes channels (x, y, z, vx, vy, compensated vx, vy, false-alarm probability, dynamic property, state flags one-hot) plus one time-offset channel give 36 channels per point; the offset "indicates the position offset" of each point. A position MLP on the radar positions gives P_r (M = 1500 points, C = 256 channels), features F_r by per-point MLPs, final F_radar = F_r + P_r.

**Results that matter** [checked]: nuScenes test 42.2 mAP / 52.2 NDS / 0.495 mAVE against DETR3D camera-only 41.2 / 47.9 / 0.845. Val, number of accumulated frames 0 / 1 / 3 / 5 / 10: NDS 42.2 / 44.3 / 44.9 / 46.4 / 46.3, mAVE 0.876 / 0.703 / 0.657 / 0.523 / 0.521. Without radar feature extraction (velocity removed) mAVE 0.523 to 0.906. No ablation of the time-offset channel.

**Transferable technique**: dt as a per-point input channel next to the compensated Doppler velocity, with the sweeps pooled: simple and already used by RCTrans (existing note). For the density w(cell) = g(..., dt) the useful fact is that velocity of a dynamic return can be integrated over dt to extrapolate the detection to the keyframe time (that is geometry, not learned). The sweep curve saturates at 5 to 10 frames.

**Cost and fit**: the paper is detection with a DETR decoder; only the radar point channel layout and the sweep curve transfer.

**Doubts**: no dt ablation, so the gain cannot be assigned to the offset channel; the ego-motion compensation method is not detailed; no code.
