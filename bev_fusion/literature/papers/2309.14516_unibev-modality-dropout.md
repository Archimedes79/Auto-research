**What it does** [checked]: camera and LiDAR BEV encoders output BEV maps of the same size; the fusion is a learned per-channel softmax-weighted average (CNW: a learnable N-dim vector per modality, N = 256, softmax over the AVAILABLE modalities, a single modality gets full weight), so a missing sensor needs no placeholder. Training with modality dropout (MD): with probability p_md = 0.5 the BEV features of one modality are dropped (zeroed for concatenation), of which LiDAR is kept with p_L = 0.5 and camera with p_C = 0.5, i.e. both sensors 50 %, LiDAR-only 25 %, camera-only 25 %. Per sample vs per batch is not stated, loss unchanged. 36 epochs, 4 x A40, about one week per model; backbones from FCOS3D and CenterPoint.

**Results that matter** [checked, nuScenes val mAP, as L+C / L only / C only]: p_L = 0, p_C = 1: 63.2 / 45.5 / 36.0; p_L = 0.25, p_C = 0.75: 64.0 / 57.8 / 35.8; default 0.5 / 0.5: 64.2 / 58.2 / 35.0; 0.75 / 0.25: 63.8 / 58.3 / 33.2; p_L = 1, p_C = 0 (no camera-only training): 60.8 / 55.9 / 3.0. So a modality that is never the only input collapses (camera-only 3.0 mAP), and the fused score moves little across the settings (60.8-64.2); whether dropout itself costs fused accuracy cannot be read, there is no run without it. Fusion: concatenation 51.9, average 52.3, CNW 52.5 (summary mAP over the three input cases). The page has no run without MD, so no with/without comparison.

**Transferable technique**: the dropout rate here is far above the 0.15-0.2 of plan 8.4 (0.5 of the samples lose one sensor) and the fused score stays at 63-64 mAP across the single-sensor mixes; for us the two single-sensor cases are not symmetric (camera-only must give lanes and boxes, radar-only only moving boxes and the stationary proxy), so p_C and p_R need separate values; see the contrary evidence in 2605.30983 (plain dropout cost 10.8 mAP of clean accuracy on BEVFusion-MIT).

**Cost and fit**: free at run time; training time unchanged.

**Doubts**: camera-LiDAR, never radar; no no-dropout baseline; single run per setting; the fusion comparison mixes the three input cases into one summary number.
