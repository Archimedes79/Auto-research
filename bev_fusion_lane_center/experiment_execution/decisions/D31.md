Question: bev_fusion: the detection scoring wedge (+-32.3 deg, 0 <= x < 60 m: `in_front` in `bev_fusion/evaluation/metrics.py`) reaches beyond the grid (\|y\| < 26 m) for x > 41 m, so GT boxes there can never be detected (review pass 2, C6). Limit it to the grid?
Options: (a) score GT and detections only inside the grid (the wedge and \|y\| < 26 m) / (b) leave: the same ceiling for every run
In plain words (BEV system chat, 2026-11-10, because the text above was not clear): the box score only asks for the cars and people inside a cone in front of the vehicle (+-32 degrees, up to 60 m). The network's map is only 52 m wide (+-26 m), and the cone is wider than that beyond 41 m, so some real boxes lie outside the map: the network cannot see them and the score counts them as missed (84 of 5,389 boxes, 1.6 %, 4.9 % of those beyond 40 m). Every run has the same handicap, so a comparison between runs is fair today; only the absolute recall and AP are a little too low. The question: leave out the boxes outside the map (a) or leave it (b)? It changes the numbers once, for all runs together.
Recommendation: (a), at the next re-evaluation of all runs (D29 (a) or (b) would be one) so the numbers change once: comparisons are not biased today (every run has the same ceiling), but absolute recall and AP are capped, the far bin most
Evidence: same frames and source as D30: 84 of 5,389 scored GT boxes (1.6 %) have their centre outside the grid (vehicles 63 of 3,635 = 1.7 %, pedestrians 21 of 1,581 = 1.3 %, two-wheelers 0 of 173); at x >= 40 m 84 of 1,715 (4.9 %)
