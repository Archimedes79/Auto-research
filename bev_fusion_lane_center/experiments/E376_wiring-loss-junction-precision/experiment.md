## 1. Card text
- **Statement:** the long-class loss shape, not only the long-class threshold, limits the champion's junction precision: either a separate (higher) none weight or an expected-F term lifts junction F1 by at least 0.03 on both fresh seeds at the champion's decode without hurting the topo score.
- **The anatomy of the champion's delivered long links (measured 2026-11-17 09:40, CPU, VAL 873, E373 fresh heads cache 0 / 1; scratch `temp/_session_scratch_d113/anatomy_long.py`, to be promoted into `evaluation/` with the E376 read-out):** link p >= 0.2 on the long class and both ends kept (p_none < 0.6): **12,509 / 12,356 delivered long links against 7,748 GT long links**; true links between the two assigned tokens 17.1 / 18.1 %, duplicates of a true link (an end is a duplicate token of the true end) 13.0 / 12.7 %, wrong pairings of two real nodes (both ends near GT nodes a, b, but a -> b is no GT long link) 33.9 / 35.8 %, links with an end near no GT node 36.0 / 33.4 % (part of it harmless: the GT has no nodes inside intersections, so a kept token on the connector path counts as 'false'; the junction F1 is a token-level count and overstates the problem, the topo F1 is the verdict); only 27.6 / 28.9 % of the GT long links are delivered as exact token-level links; the head's probability separates true (median p 0.50 / 0.52) from wrong pairings (0.32 / 0.33) and false ends (0.33 / 0.32) only partly. The signals the head already has do NOT separate them: the factor p_entry(src) * p_exit(dst) of the head's own type softmax has a median 0.011 / 0.006 for true links and 0.008 / 0.004 - 0.020 / 0.016 for wrong and false ones (p_exit is low even at true link ends), and B''s own long-link evidence sigmoid(uout) * sigmoid(uin) is saturated (median 0.98 for every category). **Reading:** the long wiring needs information (S2 past, S3 map) more than a new normalisation or prior; the loss variants below test only what a loss can do.
- **Arm lw:** `_source_nll` (training/grid/jtoken.py) multiplies the loss of sources with an empty G(i) by the none weight W (0.25 in the champion) in BOTH classes; lw gives the long class its own W_long = 1.0 (the E365 default), so empty-G long sources (most of them: an entry token rarely has a GT long successor among its candidates) push their none logit up four times harder than in the champion: more precision at the cost of recall, i.e. the operating point moves; E375 says the recall is 0.63 - 0.69, so some room exists. The type cross-entropy keeps 0.25.
- **Arm fl:** a differentiable expected-F term on the long class, per frame: over the valid sources i of the class (tokens with at least one long candidate), TP = sum_i m_i with m_i = the softmax mass of source i on its in-class GT successor group G(i) (0 when G(i) is empty), P = sum_i (1 - p^long_none(i)) (the expected number of sources that emit a link), Y = sum_i [G(i) non-empty]; F = 2 TP / (P + Y + 1e-6); the term is lambda (1 - F) with lambda = 1.0, averaged over the frames that have Y > 0, added to the champion loss. Source-level, not pair-level: the duplicates of a true successor all belong to G(i) (the multi-positive likelihood) and would inflate a pair-level TP. E2E differentiable (every quantity is a softmax mass), no threshold, no hard selection.
- **Why these two and not the Sinkhorn assignment (the lead's list):** the anatomy shows 13 % duplicate fan-out (what a two-sided normalisation removes) and 34 % wrong pairings between real nodes (what it does not); with `uout` / `uin` and the type factor non-separating, a typed Sinkhorn prior has no signal to work on; it stays a candidate behind the information cards (S2 / S3) and behind this card's read-out.
