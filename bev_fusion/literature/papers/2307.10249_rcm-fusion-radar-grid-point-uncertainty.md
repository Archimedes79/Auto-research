# 2307.10249 RCM-Fusion (radar-specific detail): radar-guided BEV queries, gating and adaptive grid points for radar position error

**What it does**: Radar points (x, y, z, RCS, vx, vy; six previous sweeps, nuScenes filtering and multi-sweep code modified by the authors) go through a PillarNet backbone (2D sparse conv) to a radar BEV map. (1) Radar Guided BEV Encoder: BEV queries are first updated by deformable attention over the radar BEV, then pulled by spatial cross-attention from camera features; a sigmoid Radar-Camera Gating fuses the two BEVs. (2) Radar Grid Point Refinement for instance proposals: because radar positions are noisy, T grid points are placed around each radar point, spaced along the tangential component of the proposal's predicted velocity (spacing scales with speed, clamped), Farthest Point Sampling keeps M of them (best T = 7, M = 64); a proposal-aware attention weights each radar point.

**Results that matter** (nuScenes val, trained on 1/7 of train; NDS / mAP / FPS): baseline 44.9 / 37.9 / 2.7; + radar-guided BEV queries 49.4 / 42.5 / 2.5; + gating 51.6 / 43.2 / 2.4; + grid points 52.3 / 43.7 / 2.3; + proposal attention 52.9 / 44.3 / 2.3. Grid-point ablation: none 52.4 / 43.8; fixed grid 52.5 / 44.0; adaptive grid 52.9 / 44.3 (so the uncertainty-aware spreading is worth about +0.5 NDS). Test, single frame: R101 58.7 NDS / 50.6 mAP; R50 53.5 / 45.2.

**Transferable technique**: radar-guided BEV queries and sigmoid gating give most of the gain (+6.7 NDS of the 8.0 total); explicit modelling of the radar position error (adaptive grid points) is a small extra. Gating is a cheap way to keep the camera path alive when radar is dead.

**Cost and fit**: heavy (2.3 FPS, 87.6 M parameters, trained on 1/7 of data in the ablation); only the gating and the guided query idea are portable to a small system.

**Doubts**: ablation on a 1/7 subset; text and table disagree by 0.1 on two numbers; no Doppler or RCS ablation.
