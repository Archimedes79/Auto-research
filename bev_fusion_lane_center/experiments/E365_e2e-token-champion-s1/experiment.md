## 1. Card text: the design, as the build reads it
- **Tokens (cache, frozen B', section 2a):** B' = `runs/e292_a_s<S>` (the E273 pyramid and node head with the soft Matrix-NMS layer: differentiable, no hard step) first; plain B (`runs/e273_p_s<S>`) second (a second cache, an ablation: does the head's own pruning replace the layer). The top-K cells by B's existence logit (K = 384 expected: the manifest fixes it, see 2a); per token: B's node token `tok` (64 d), pos (cell centre + offset, m), dirv (unit), e (after the layer) and e_raw, the 8 flag logits, s, uout, uin; padding tokens (sigmoid(e) <= 0.05) carry valid = False and are masked as keys and sources.
- **Embedding:** x0 = LN( Linear(64 -> 64)(tok) + MLP([Fourier(pos, 4 bands), dirv, e, e_raw, flags, s, uout, uin]) ), d = 64.
- **Soft pruning, said exactly:** the existence weight w_j enters every attention as the key bias log(w_j + 1e-3): w_j = sigmoid(e_j) of B' (a constant input) for the first 1000 steps and in layer 1; afterwards w_j = 1 - p_none(j) of the head's own type softmax, read by the SAME Linear after layer 1 and after the last layer (cross-entropy on both); the gradient reaches the head's own existence only, **none reaches B' (frozen, cached) and none goes through the hard top-K by B's existence** (a trained-through B is a later card). Tokens are not dropped inside the network. Output pruning: a node is kept when p_none < 0.5 (named threshold, on the output only). The loss curve of the first 1000 steps is reported.
- **Self-attention layers (3, 4 heads, FFN 128):** the logit of head h between token i (query) and j (key) = q_i . k_j / sqrt(16) + bias_h(g_ij) + log(w_j + 1e-3); bias = MLP(13 -> 32 -> H) of the 13 relative-geometry features of `jtok.pair_geometry` (turn cos / sin, chord / 20, the chord in the frames of both headings, the chord-direction cosines, e_i, e_j); pre-norm residual blocks.
- **The wiring = the attention weights of a last layer with two heads:** class c in {short (chord <= 8 m), long (chord > 8 m)}: z^c_ij = q^c_i . k^c_j / sqrt(d) + bias^c(g_ij) + log(w_j + 1e-3) + b^c_j (b = the destination evidence of class c read from x_j), restricted to the allowed gate of `jtok.pair_geometry` (the same gate as E357 - E362), plus ONE learned none slot per class (a key with its own logit q^c_i . k^c_none + bias); the per-source successor distribution of class c = softmax over {none} and the allowed keys. The none slot is the gate: it sees the whole candidate set. Two handle scales per pair from a small MLP of (x_i, x_j, g_ij), 0.5 x L1 on the long GT links (the connector geometry as E357).
- **Node types (softmax over 7, the lane chat's map):** 0 none / 1 lane point / 2 fork (flag split) / 3 merge / 4 junction entry (stop) / 5 junction exit (exit) / 6 boundary (start, end, win_in, win_out), with the priority split > merge > stop > exit > boundary > lane written into the cache manifest (the flags are multi-hot; the raw flags stay beside the label); the label of a token = the type of its assigned GT node, none when not assigned; cross-entropy weight 0.5. The type softmax serves the existence (p_none) and the report; the wiring does not read it.
- **Labels and loss (matching inside the loss is allowed, D55; the assignment is static, stored with the cache):** (a) the GT table is on the **2.0 m lattice** (B's own cells and node targets; the oracle stage used 2.5 m because it had no B); (b) the token-to-GT-node assignment (type label, existence) is greedy by DESCENDING existence of B' over the tokens: each token takes the nearest still unassigned GT node within 1.5 m with heading cosine >= 0.5 (ties to the lower token index): the choice among duplicates is a function of the input, so the head can learn it; (c) the targets of the wiring: the GT links are first **contracted over the GT nodes that no token covers** (no token within 1.5 m with cosine >= 0.5; as `jtok_eval.sub_table` does for removed nodes), then G(i) of a source token i that is assigned to the GT node a = **every token that lies within 1.5 m (cosine >= 0.5) of a GT successor of a, assigned or not** (the multi-positive likelihood allows exactly this), per class; (d) every token is a source: a token that is assigned to no GT node has G(i) empty in both classes, its target is the none slot. Likelihood per class c and source i: -log( sum_{j in G(i)} p^c(j|i) ) when G(i) is non-empty, -log p^c(none|i) when it is empty (normalised per frame over the sources of the class, as E359); + type CE (0.5, on both readings) + 0.5 x scale L1. One training stage, 12000 steps, bs 8, lr 1e-3 (5 % warm-up, cosine), AdamW, roll-back guard and 500-step checkpoint with resume as `trainer.fit`; the share of GT links lost to unassigned or uncovered ends is reported.
- **Decode of record (named before the run, on the output only):** a link i -> j of class c is kept when p^c(j|i) >= 0.3 and p^c(j|i) >= p^c(none|i) and both ends are kept nodes (p_none < 0.5) (a fork source keeps both branches); the argmax per source including the none slot is reported as the alternative decode (the argmax cap of E362 applies to it: one link per source). Delivered graph = the E357 section-free read-out (`qgraph_eval.readout`, every node section 0, chains cut at forks / merges) scored by the standard scorer (`qgraph_eval.score_frames`) on the 873 VAL frames, **inside the `jtok.lattice(2.0)` block (the scorer's `LaneRef` builds a node table; the headline graph numbers use the old graph GT and must not depend on it: the layer-1 check proves it)**. No rule step. **The read-out writer is new and takes no field of the GT table**: pos and dirv from the tokens, e = 1 - p_none, flags from B' / the head, section 0 (`jtok_eval.edge_prediction` writes flags, s and section from the GT table and must not be reused); the loader's token array is named `tokens_np`; a mutant test puts a GT flag or piece into the prediction and must fail.
- **Cost counted in every result:** parameters, GMACs per frame and ms of B' alone, of the S1 head alone, and of the whole path (G-cost); idle GPU, batch 1, 24-frame protocol, bf16 as E324 s, the load stated; K = 384 means 147 k pairs per frame, about 6.5 times E362's pairs: the pair tensors at bs 8 are chunked if the 20-step smoke run exceeds 11 GB.
- **Not claimed:** anything about S2 / S3, TEST (never touched), that B''s frozen nodes are the best token source (a trained-through B is a later card), the gradient to B. **Known limit, reported:** B' was trained on TRAIN, so its flags, e, uout and uin are cleaner on the TRAIN frames the head trains on than on VAL (the head may trust inputs that are weaker on VAL; no out-of-fold B' exists): the read-out of S1 on 873 TRAIN frames is reported next to VAL (the generalisation gap) with B''s node recall and precision on TRAIN and VAL; S1 uses no token-drop augmentation (the loader has the option), the degraded read-out (17 % of the tokens removed) is reported as the robustness number.
- **Referee:** fresh `ar-critic` (cards) 2026-11-16 on v1 (about 4.5 minutes): REVISE, 13 findings, taken in as listed in the header. A second pass on this v2 is not planned unless the cache or the gate changes.
