**What it does** [checked]: online vector-map builder with a streaming temporal design. BEV memory: the previous BEV feature is warped to the current frame with the pose transform between the two ego frames (Eq. 13), a GRU (after Neural Map Prior) fuses it with the current BEV feature (Eq. 14), LayerNorm on the fused output for stability. Query memory: propagated queries with a transformation loss that ties the transformed old prediction to the current one. Training: "Gradients on memory features do not propagate back to previous frames" (the one quote); every epoch each training sequence is split at a random point into 2 parts for diversity; inference runs on whole sequences; training starts with 4 epochs of single-frame input, after SOLOFusion, "to stabilise streaming training".

**Results that matter** [checked, Argoverse2 new split, 50 m, mAP]: single-frame relative predict 33.7; direct predict 41.7; + query propagation without the transformation loss 42.8; + transformation loss 43.7 (+0.9); + BEV fusion 46.1 (+2.4). Recipe: 8 x GTX 3090, batch 32, AdamW lr 5e-4, 24 epochs (nuScenes), 30 (AV2), R50. 13.2 FPS on nuScenes (R50, 480 x 800), 14.2 FPS on AV2.

**Transferable technique**: (1) detached memory + a short single-frame warm-up is the common recipe: StreamMapNet (4 epochs single-frame), CRT-Fusion code (6 epochs without history, then resume from the EMA weights, existing code note), BevAD 2603.15185 (4-epoch backbone stage), SOLOFusion (two-phase); (2) cut each sequence at a random point every epoch so that start-of-sequence states (empty memory) are seen in training: our memory has to be correct at frame 0 of a drive; (3) a GRU + LayerNorm gate on top of the ego-warped state is a stable fusion (our `temporal_fusion.py` uses conv3x3 + confidence; the GRU is the variant); (4) the transformation loss (old prediction moved by the pose equals the new one) is the instance-level twin of the raster consistency in MapTCL 2608.05209.

**Cost and fit**: BEV-level GRU on 100 x 50 m grids is cheap; training batches need ordered sequences (our scene-ordered loader replaces the mmdet sampler).

**Doubts**: no isolated run removes the BEV memory from the full model (the +2.4 is an incremental step); frames per training sample unspecified; map vectors, not dense layers or boxes; the single-frame warm-up is "inspired by SOLOFusion" with no ablation here.
