**What it does**: Joint 3D detection and motion forecasting from a time series of lidar sweeps in the range view. Past points are transformed by the ego motion into the frame of the next sweep, projected into its range view and merged, with the relative displacement between matched points as an extra feature. Three fusion orders: Early (warp all past sweeps into the most recent viewpoint, then one CNN), Late (process each sweep in its own viewpoint, then project the features into the latest view, as LaserFlow), Incremental (fuse sweep by sweep, passing the fused features only to the next sweep's viewpoint, so every viewpoint change is small).

**Results that matter** (checked, Table II): nuScenes detection AP at IoU 0.7 / forecasting L2 at 3 s: Early 57.9 / 135 cm, Late 58.8 / 127 cm, Incremental 59.9 / 120 cm (L2 at 0 s equal at 24 cm); at 1 s: 48 / 45 / 43 cm; on the authors' LSAD data AP 74.1 / 74.6 / 74.6 and L2 at 3 s 121 / 115 / 109 cm. The paper states that "the amount of information loss and gaps increase as either ego or actor speed increases" when sweeps are warped far. No runtime or memory comparison of the three orders.

**Transferable technique**: a recurrent radar state updated sweep by sweep with SMALL ego steps (one sweep, about 0.08 s for the nuScenes radars) beats one large alignment of a long history by +2.0 AP and about 10 percent lower forecast error; it supports a point store that is updated every sweep and rasterised once, and warns against warping a long-horizon raster in one go. It does not separate points from features: the Incremental winner passes FEATURES, so it is not proof that points beat a grid state.

**Cost and fit**: no cost figure; incremental fusion needs one network pass per sweep, which for a recurrent grid state is the same as VideoBEV-style recurrence.

**Doubts**: range-view lidar with a CNN, the 2D neighbourhood is the sensor lattice (our radar has none); the gain 2.0 AP is from one data set pair; "early" there already warps all sweeps to the latest viewpoint, so the comparison is about the order of fusion, not about points versus a raster.
