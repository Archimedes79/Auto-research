# 2302.07817 TPVFormer: three orthogonal feature planes (BEV + two height planes) for 3D occupancy

| | |
|---|---|
| source | https://arxiv.org/abs/2302.07817 (abstract page only), CVPR 2023 |
| fact status | checked (abstract); numbers below from other pages read in this scan (GaussianFormer HTML, OccFlowNet HTML) |
| groups | F4: 2 |
| code / licence | https://github.com/wzzheng/TPVFormer (memory, Apache-2.0 from memory) |
| verdict | context (the tri-plane lift is the middle way between BEV and a voxel volume; SelfOcc uses it) |

**What it does**: Adds two vertical planes to BEV; the feature of a 3D point is the sum of its projections onto the three planes; a transformer lifts image features into the planes by attention; trained with sparse lidar-point supervision it predicts occupancy for all voxels.

**Results that matter**: camera-only nuScenes lidar-segmentation comparable to lidar methods (abstract). In other tables: SC IoU 30.86 / SSC mIoU 17.10 on SurroundOcc labels (GaussianFormer Table 1), 27.83 mIoU on Occ3D (OccFlowNet table); latency 341 ms and 29 GB-class memory (copied from OctreeOcc, A100). SelfOcc TPV vs BEV: mIoU 9.30 vs 6.76, IoU 45.01 vs 44.33.

**Transferable technique**: memory-cheap 3D reasoning: planes cost O(HW + HZ + WZ) instead of O(HWZ); a lift MLP over (BEV feature, height plane features) is a small decoder.

**Cost and fit**: the transformer lift is heavy; the tri-plane decoder alone is cheap and gives +2.5 mIoU over BEV in SelfOcc's self-supervised setting. Two extra planes of 200x16 are negligible.

**Doubts**: no abstract numbers; latency figures from a different paper's table.
