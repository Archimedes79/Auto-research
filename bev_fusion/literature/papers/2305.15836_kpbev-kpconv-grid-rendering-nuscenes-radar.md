**What it does**: nuScenes radar, 5 aggregated sweeps, per point: x, y, ego-compensated radial velocity, RCS, time difference to the newest sweep (no elevation). Each point is first augmented with relative position to the anchor, relative position to the cell centroid, the centroid and the point count (F_in + 7) and a linear layer. KPConv (kernel points with linear influence, learnable weight matrix per kernel point, radius 0.6 m KPBEV / 1 m KPPillars, influence radius rho / 2.5) is evaluated ONLY at the centres of non-empty cells ("anchors"), so each anchor gets F_out = 64 features that are written one-to-one into a dense W x H x 64 map (grid +-60 m, cell 0.5 m). Multi-scale: the same rendering at scales s0 .. 8 s0 with adaptive radius, each map concatenated into the matching ResNet stage; FPN, class-group heads, oriented NMS. KPPillarsBEV = three KPConv point layers before the per-scale KPBEV modules. Rotation / translation invariance is not addressed.

**Results that matter** (nuScenes val, car class; 10 trainings of 50 epochs each; V100 SXM2, TensorFlow profiler; checked): PointPillars baseline AP4.0 38.31 / mAP 22.08 / 86.96 FPS / 89.7 MB; KPPillars 40.80 / 24.01 / 78.1 FPS; KPBEV single-scale 41.21 / 24.50 / 87.11 FPS (same speed as the baseline); KPPillarsBEV single-scale 41.84 / 24.95 / 74.9 FPS; multi-scale KPPillarsBEV 43.68 / 26.42 / 60.0 FPS / 111 MB; multi-scale PointPillars 38.70 / 22.44 / 76.3 FPS. Multi-scale helps every variant (largest for KPBEV).

**Transferable technique**: per-point state kept in a KPConv-style local conv and rendered to cells at their centres, with the offset to the cell centre as an input - a published form of "detection feature + decoder around it" (Mirko's idea 1 in radar_encoding.md) that is conv-only. Gain over the pillar baseline +2.9 AP4.0 at equal speed; the point-level part adds little cost. The rendering at several scales (0.5 .. 4 m cells) lets the large-scale maps see position error.

**Cost and fit**: 87 FPS on a V100 (11.5 ms for the whole detector) in the single-scale variant; KPConv needs radius search, which is irregular (custom neighbour search in the original).

**Doubts**: car class only, AP4.0 is a loose 4 m match threshold (position-uncertainty tolerant); mean over 10 runs but no spread printed; no ablation of Doppler / RCS / time features; no code; a different, earlier paper from the same group (KPConvPillars, 4.9 mAP on the nuScenes radar leaderboard) shows a bigger system can still score low on the full benchmark.
