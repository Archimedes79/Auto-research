**What it does**: Input is 5 LiDAR sweeps (4 past, 1 current) transformed into the current ego frame and voxelised into 13 x 256 x 256 binary occupancy (64 m x 64 m crop at 0.25 m, height bins as channels). A spatio-temporal pyramid network uses blocks of two 2D convs plus a pseudo-1D temporal conv (k x 1 x 1); the temporal length shrinks 5, 3, 1, 1 over the scales and the pooled temporal features reach the decoder through lateral connections. Per-cell heads: five-class classification, future displacement up to 1 s, and a per-cell static probability. Motion is zeroed for background, and the state estimate suppresses jitter on static foreground. Losses: cross-entropy, smooth L1 and three consistency terms (within instance, foreground in time, background in time with ego or ICP alignment).

**Results that matter** (nuScenes LiDAR, 500/100/250 scenes): mean L2 motion error static 0.0256 m, slow (<=5 m/s) 0.2565 m, fast (>5 m/s) 1.0744 m; without ego synchronisation the slow-speed error rises from 0.2565 to 0.4245. Class accuracy MCA 70.3 %, overall 96.1 %, bicycles only 20.6 %. 0.019 s per inference (about 53 Hz, stated in the paper); LSTM encoder-decoder 0.042 s.

**Transferable technique**: a dense static-probability map next to the class map, used to zero motion on static cells; the pseudo-1D temporal conv as a cheap temporal block on a short stack; background temporal-consistency loss across ego-aligned frames (a self-supervised signal that needs no labels: the static background must match after the warp).

**Cost and fit**: 19 ms on the authors' GPU (not named on the page); a 5-frame stack, not recurrent. Input is LiDAR occupancy; for camera + radar the input would be our BEV features.

**Doubts**: LiDAR only; 2020 baselines; bicycles/pedestrians weak; the static-probability head needs labels from boxes.
