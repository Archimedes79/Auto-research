# Frame changes - what changed in the trainer, data path, interfaces, evaluation and runner, and what it means for comparing runs

From 2026-11-02 to 2026-11-10 these files were frozen (D44: a bug fix only, a hash gate in `frozen.json`). Mirko lifted the freeze on 2026-11-10 (D73, his words: "Freeze nix, ich gebe alles frei, was änderungen im Wege steht"); the gate (`frozen.json`, `tests/test_frozen.py`, `FROZEN.md`) was removed in the clean-base round of the same day. What stays is this list: a change of the frame can move a number, so every such change is written down here with the evidence that nothing moved, or what moved. The baseline `t16.full_s0` trained from the frame of tag `bf/frame-2026-11-02`.

## How to compare runs across these changes
- A run is pinned by its snapshot commit (`runs/<name>/code/SNAPSHOT.txt`, the launcher's tag `bf/<id>`): the code that trained it is the code of that commit, with the trainer engine `autoresearch/trainkit` copied next to `train.py` (`tools/run_ar.sh`, `check_engine` refuses a mismatch).
- Trainer of 2026-11-10 (`be311601`): a new run has another data order, flip and dropout masks than the same seed before (`EpochLoader`: the pass order is a function of seed and epoch, the position is saved; the CUDA generators are in the checkpoint). Pair an arm with a control of the SAME trainer version. An old control (`t20.base_s0`, `t21.pair4_s0`, t22 stage B) against a new-trainer arm is an unpaired comparison: read it with the seed noise, or re-run the control. Bit-identical resume is proven on the CPU toy only; every resumed arm gets "resumed at S" in its ledger row.
- Evaluation: the evaluator hash (`evaluation/bev_adapter.py` NUMBER_PATHS) is part of a store's identity; a store started with other evaluator code is not resumed and an old card pairs with a new one only with `allow: provenance`.
- A card or ledger row that compares across the date of a line below names the version of both sides.

Add a line to the changelog for every change of the trainer, the data path, the interfaces, the evaluation or the runner that can move a number: date, files, what moves, how it was checked.
