# 2311.12058 FlashOcc: keep BEV 2D, lift to 3D by reshaping channels into height

**What it does**: The occupancy head stays 2D. BEV feature B x C x W x H is mapped by 2D convs to B x (C*·Z) x W x H and reshaped to logits B x C* x Z x W x H (C* classes, Z height bins; channel-to-height). No 3D convolutions, no 3D volume in memory.

**Results that matter** (Occ3D-nuScenes val mIoU): BEVDetOcc 42.0 -> FO(BEVDetOcc) 43.3; UniOcc 45.2 -> FO(UniOcc) 45.5 (UniOcc carries rendering supervision, so the plugin is compatible with it). Same-setting BEV vs 3D conv (Table 4): BEVDetOcc 36.1 vs 37.8, UniOcc 39.2 vs 39.0, FBOcc 37.2 vs 37.3 -> no loss from dropping 3D convs. Speed on RTX 3090 TensorRT FP16, no temporal module: 3D baseline 92.1 FPS / 31.6 mIoU, FlashOcc M0 210.6 FPS / 31.0, M1 152.7 FPS / 32.4. BEV encoder + occupancy head: 7.5 ms -> 3.1 ms, 398 MiB -> 124 MiB. Training 64 -> 32 GPU-hours. (Text gives M1 as 60.6 Hz, table 152.7 FPS: inconsistent in the paper.)

**Transferable technique**: a lifted decoder is just a conv head with Z·C* output channels; for an SDF the same reshape gives one signed distance per height bin (C* = 1), or an MLP over (feature, z) if a continuous z is needed. Cheap: ~3 ms head.

**Cost and fit**: excellent on a 3060; fully compatible with an added rendering loss. Limits: height resolution is fixed to Z bins; thin vertical structures rely on the channels.

**Doubts**: occupancy loss not specified in the page; independent critique (LightOcc) says height information is lost in the BEV collapse (seen in a search snippet, not read).
