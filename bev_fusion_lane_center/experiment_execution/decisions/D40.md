Decision: D40 (Mirko, in chat, answering the proposal of a result package per run with a clean-up rule: "ja. Und natürlich sollte man abgeleitete Daten löschen, sonst explodiert die Festplatte. Und auch bei gt sollte man nur die letzten Daten behalten. Sollte man ältere Stände benötigen -> geht man über git. Also ja, ein Ergebnis paket pro Lauf und aufräumregeln."): derived data may be deleted, and of the GT only the latest version is kept (an older one is regenerated from its `autogt/vN` tag); every run gets a result package
Consequence: scope as read by the review chat (Mirko may correct it): DERIVED data = what can be rebuilt from git + the raw-data manifest + a checkpoint: evaluation outputs (pickles, pictures, videos, per-scene folders) of runs outside the best three, caches, and the GT stores of versions older than the latest. NOT covered: the raw nuScenes data, checkpoints (the best three stay complete, the others are slimmed or archived as before, hard rule 5 stays for them), text records (run.json, config, logs, metrics.json, cards, `package.json`), everything of the best three, and anything that a running, stopped or held run needs for its resume (the GT store named in its `gt.json`). The tool is `autoresearch/tools/package.py` (`package <run>` writes `bev_fusion/results/<id>/package.json` (the result folder of the run, with `provenance.json`; `bundle/` beside them is a copy of the network and loss files and not in git), `clean` is a dry run that lists and sizes, `--apply` deletes and records what it deleted in the package). Hard rule 5 in METHOD.md / CLAUDE.md is reworded to this scope after the tool is tested
