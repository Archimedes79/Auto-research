# E53: Connector synthesis between split and merge key points: Bezier curves (SeqGrowGraph geometry) on SAM-Road-style nodes

Status: completed

**Question:** E44 can only cut key points into pieces that exist. The diagnosis of E44 found that for 55 % of the ground-truth splits and 42 % of the merges the branch piece itself is missing from the graph - there is nothing to attach the key point to - and even ground-truth key points reach only 0.694 / 0.752 split / merge F1 (TEST) with node insertion alone. SeqGrowGraph describes a lane graph as a growth of vertices joined by Bezier-curve centerlines. Can the cheapest explicit form of that idea - synthesising a missing branch as ONE cubic Bezier curve from a split key point to a merge key point ahead, confirmed by the dense head's own heat along the curve - recover the missing branches? (Pixel-based dense head and key points; the connector is a vector element added to the graph.)

## Setup
- Starting point: the DEFAULT graph of E44 (conservative cut r_s 16 m / r_b 8 m / cos 0.5 / d_c 1.5 m, then prune 6 m), the key points of E44 at tau_k 0.5 and the dense heat map of the final dense head (temporal variant A) as evidence. No learned parameter is added: only the heat threshold tau_h is tuned, on VAL.
- For every split key point S that lies on a piece (within 1.5 m) and has no branch yet, candidate merge key points M are taken from the key points that lie on a piece of the graph, 4-40 m ahead of S inside the heading cone of the feeder (cos >= 0.17), with compatible headings at S and M (cos >= -0.3) and not yet connected through the graph (no path of at most 1.6 |SM| + 6 m). The connector is the cubic Bezier curve P0 = S, P1 = S + |SM|/3 h_S, P2 = M - |SM|/3 h_M, P3 = M (h = heading of the feeder at S and of the receiving piece at M); it is accepted if the mean dense heat along the curve is >= tau_h; at most the two best candidates per S are kept.
- An accepted connector cuts the feeder at S and the receiving piece at M and is inserted as a new piece with two edges (feeder-part -> connector -> receiving part), sampled every 1 m. The evaluation is unchanged: split / merge locations within 3 m and 6 m of the ground truth, 1 m point F1, route score; the path column is the LaneGAP-style path F1 of E46.

## Findings
- Connectors recover most of the missing split branches. TEST at tau_h 0.5: split F1 (6 m) 0.552 -> 0.714 (precision 0.825 -> 0.845, recall 0.415 -> 0.619), merge F1 0.607 -> 0.637 (precision 0.875 -> 0.717, recall 0.464 -> 0.573); against the final system of the previous loop (0.342 / 0.380) this is a factor 2.1 / 1.7. VAL shows the same pattern (split 0.497 -> 0.689, merge 0.604 -> 0.648). The split F1 now exceeds the 0.694 that ground-truth key points reach with node insertion alone, because the connector creates the branch piece that node insertion cannot; the merge side stays below its bound (0.752) because the merge connectors bring false merges (precision 0.875 -> 0.717).
- The price is small and sits in the route score: TEST route F 0.733 -> 0.719 (-0.014; VAL -0.012), route precision 0.791 -> 0.764 - a false connector makes a shortcut between two real lanes - while the point F1 at 1 m is unchanged (0.876 -> 0.875; recall +0.007, precision -0.008), the share of ground-truth lanes found rises slightly (0.726 -> 0.737) and the direction accuracy drops by 0.007 (0.953 -> 0.946). The LaneGAP-style path F1 (E46) recovers part of what the node insertion costs: TEST 0.459 (default) -> 0.470 (tau_h 0.5) / 0.476 (0.6), still below the graph without key points (0.484); VAL 0.533 -> 0.536 / 0.544 (0.560 without key points).
- The heat threshold is a monotone trade-off (figure): below 0.3 the dense heat along a plausible curve is nearly always sufficient (VAL practically identical for 0.1 / 0.2 / 0.3), at 0.5 the route F recovers a little (0.781 against 0.778), 0.6 is an intermediate point (TEST split / merge 0.649 / 0.625 at route F 0.727) and at 0.7 almost every connector is rejected (VAL split / merge 0.504 / 0.603, i.e. the default again). The VAL selection score used for the cut sweep (split F1 + merge F1 + 2 route F + 2 point F1) is flat from 0.1 to 0.5 (4.70); 0.5 was taken as the strictest value of that plateau and 0.6 is reported as the cautious alternative. The switch between the 'default' (precision first) and the 'connector' (recall first) graph is therefore a per-application choice, not a free gain.
- With the map prior (exact pose; joint head) the connectors behave in the same way (table, rows 'MAP PRIOR'): TEST split / merge F1 (6 m) 0.556 / 0.615 (default) -> 0.717 / 0.643 at heat 0.5 and 0.665 / 0.635 at 0.6, route F 0.764 -> 0.750 / 0.757 (0.778 without key points), point F1 0.939 -> 0.937 / 0.939, path F1 0.530 -> 0.539 / 0.546 (0.565 without key points). The prior itself changes nothing in the node columns (E54: connectors with and without the prior differ by +0.003 / +0.006 split / merge F1, intervals include 0) but adds +0.061 point F1 and +0.031 route F.
- With a REGISTERED, noisy prior (pose noise sigma 1 m, registered by correlation + the learned fine stage of E48; system level) the node steps behave the same way (table, rows 'REGISTERED PRIOR'): TEST split / merge F1 (6 m) 0.351 / 0.380 -> 0.549 / 0.608 (default) -> 0.707 / 0.633 (connectors, heat 0.5), route F 0.765 -> 0.751 -> 0.737, point F1 0.913 -> 0.913 -> 0.911, path F1 0.513 -> 0.517 (default -> connectors); VAL 0.312 / 0.419 -> 0.500 / 0.604 -> 0.682 / 0.647 at route F 0.818 -> 0.811 -> 0.799. The node steps therefore also work on top of a prior that is not perfectly registered.
- In the examples the connectors do what they are meant to do at intersections: where the default graph misses several turn branches, the connectors between the incoming lane and the outgoing lanes lift the number of correct split / merge nodes of the sample from 2 to 8 and from 4 to 10 (rows 1-2). The failures are the false key points: on a mostly straight stretch without a lane change (sample 145) false key points close to the ego lane let the connectors add four false nodes to the two that the default graph already has (no correct node is gained), and at a busy intersection (sample 1547) four more correct nodes (2 -> 6) come with five additional false ones.

## Limits
- The connector inherits every key-point error: a false merge key point 10-30 m ahead of a true split key point creates a false lane change if the heat along the curve is high enough (the examples show such false nodes on straight stretches and at busy intersections). A learned edge decision (SAM-Road's topology decoder) would be the principled replacement of the heat threshold; the learned link heads of E42 / E45 did not beat rules, so this was not tried again.
- One cubic segment per connector (no intermediate pieces), at most two candidates per split, only split -> merge pairs; no end-to-end training. The threshold was tuned on VAL only; TEST was run for tau_h 0.5 and 0.6 only. Single seed; differences of about 0.01 in route F are within the scene-level uncertainty (E54).
