# D76

## Open

Id: D76
Question: May the directory `autogt/` be renamed `GtGenerator/` (the Python package and `python -m` name with it), now that the ground truth is one class `GtGenerator` behind one command line?
Options: (a) rename now, in one change with every living reference (code, tests, tools, living documents, `.gitignore`, `project.json` code lists); (b) later, when no lane or BEV job runs; (c) keep `autogt/`.
Recommendation: (a) when the box is quiet enough, with a temporary link `autogt` -> `GtGenerator` so that running processes and scratch scripts of other chats keep working until they are done. The data folder `data/autogt/`, the git tags `autogt/vN` and `autogt/lane-lN`, the hashed generator files (their bytes are the GT signatures) and the dated records stay as they are.
Evidence: 190 files outside the folder name it (`git grep -l -w autogt`); the hashed files carry the old name only in comments and one error message, so a rename does not change a signature (front 6a7aa7864a / v9, lane 2464b5755f and db288acca5 stay).

## Decided

Decided: 2026-11-10
Decision: D76 (Mirko, in chat on 2026-11-10, in the GT chat; after "Die Gt ist keine Gt Suite sondern eine GtGenerator Klasse in einem Verzeichnis GtGenerator mit allen benötigten Funktionen, Darüber liegt ein Command line interface, darunter die entsprechenden Teilfunktionen" I asked "Das Verzeichnis autogt/ jetzt in GtGenerator/ umbenennen?" with the answers "Später, abgestimmt" and "Jetzt umbenennen"; his answer: "Jetzt umbenennen"). My reading, which he can correct: the directory and the package are renamed in one change; what is history stays with its old name (tags, dated records, the data folder).
Consequence: done 2026-11-10 by the GT chat in one commit (rename, living references, `.gitignore`, `project.json` code lists, documents). Not renamed on purpose: `data/autogt/` (the stores; a data move is a decision of its own), the tags `autogt/vN` and `autogt/lane-lN` (new tags continue the series), the twelve hashed generator files and `checks.py` (their comments still say `autogt` until the next generator version: renaming a word there would change a signature), decisions, histories, results and ledgers. A link `autogt` -> `GtGenerator` at the repository root keeps running processes and old scratch scripts working; it is not in git and goes when nothing uses it.
UPDATE 2026-11-10 (GT chat, on the request of the BEV system lead: a stored run must still work, hard rule 5): the link `autogt` -> `GtGenerator` was replaced by a tracked alias package `autogt/__init__.py` at the repository root (`import autogt` is the package GtGenerator, `autogt.X` the same module object as `GtGenerator.X`, no copy; a test in `GtGenerator selftest` pins it). The pinned code snapshots of runs made before D76 (`runs/<name>/code/*.py`: `from autogt.nuscenes_adapter import pose_matrix`) import through it. Remove the folder and its three `.gitignore` lines when no stored run is needed.
UPDATE 2026-11-10 (D78, Mirko: "Jetzt entfernen"): the alias `autogt/__init__.py` was removed again; the pinned snapshots of runs made before D76 no longer import on their own (see D78).
