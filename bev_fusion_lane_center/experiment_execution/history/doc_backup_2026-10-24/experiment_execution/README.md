## Life of an experiment

1. **Gap check** (first wake-up of a loop): what the ledger and `experiments/` say was done, what the literature (`../literature/README.md`, open list) says is missing.
2. **Card** (`templates/experiment_card.md`): hypothesis, basis ids (earlier experiments, K ids), the one change, the gate / decision rule written *before* the run, the cost in GPU hours.
3. **Ledger row** `planned` (`python tools/experiment/ledger.py add E210.a --hyp "..." --basis E209`) and, for a new technique, a K id in `../literature/register.md`.
4. **Run** with `tools/experiment/run.py` (background, max 2-3 GPU jobs, < 11 GB). The launcher writes the run record and the `done` flag only on success; trainings checkpoint every 400-500 iterations.
5. **Read** the result with `evaluation/` (never a private metric), both route-head seeds, noise band 0.010; write result + decision into the ledger (`ledger.py note`).
6. **File it**: catalogue row (`tools/catalogue/e2e_catalogue.py` + `e2e_basis.py`, then `tools/catalogue/build_experiment_table.py`), experiment folder (`experiments/E<id>_<slug>/` with README, small results, images), state file entry.
7. **Report** along the way (`reports/`): architecture drawing, numbers table, result images (`tools/viz`, `tools/video`), conclusion; honest negatives stay.

## Wake-up routine of a loop (from PROGRAM.md)

Read the state files -> check jobs (`nvidia-smi`, ledger status) -> parse finished runs -> cut / continue by the written gate -> launch the next jobs -> write the next action into the state file and `HANDOVER.md` -> schedule the next wake-up (20-25 min, long fallback 1200 s+ if a monitor is armed). At STOP_AT: finish report, memory (facts only), state files.
