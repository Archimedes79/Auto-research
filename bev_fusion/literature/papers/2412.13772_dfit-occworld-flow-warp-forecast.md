**What it does** [checked]: 3D occupancy forecasting from past occupancy, images and ego poses, non-autoregressive (all future volumes at once) and ONE training stage (the earlier OccWorld needed a tokenizer stage and a transformer stage). A FlowDecoder predicts a flow from the encoded history BEV features in the current ego frame; the flow is moved into each future ego frame with the current-to-future rotation R and translation T; future dynamic features = grid_sample(history features, flow) (forward/backward and interpolation mode not stated); static voxels have zero flow and move by pose only; a few CNNs refine the warped features. Ego pose is encoded as relative 2D displacements. Image-assisted training: depth rendered from the predicted future volumes by volume rendering drives a multi-frame photometric reprojection loss (SSIM alpha 0.85 + L1, min over source frames, auto-masking); images are used in training only (masked attention lets the model run without them).

**Results that matter** [checked, nuScenes, averages over 1-3 s]: OccWorld 17.14 mIoU / 26.63 IoU; direct baseline 18.97 / 28.44; + flow decoder 20.67 / 29.89; + decoupled dynamic flow 20.89 / 30.97; render-based photometric consistency alone 21.96 / 31.88; best (with all parts) 23.05 / 32.92. Training time 25.1 h single-stage against 66.7 h for OccWorld (hardware not stated). Loss: CE + Lovasz-softmax for occupancy, L1 on pose, L2 on rendered depth, photometric term; the lambda weights, an explicit flow loss and any forward-backward flow consistency are NOT given.

**Transferable technique**: flow-warp beats direct generation by +1.7 mIoU / +1.5 IoU here (rows baseline vs flow decoder), the nearest published A/B for "splat the state with a learned velocity" against "decode the future from scratch" (our arm T2/B against FiLM-only). Static by pose, dynamic by flow is our 7.1 split. The photometric reprojection term is a label-free signal for the flow that we cannot use with frozen heads and no depth, but it shows the flow can be trained without a flow loss.

**Cost and fit**: 25 h single-stage on unspecified hardware; the decoder is attention-based (SALT blocks), not for a 3060.

**Doubts**: the history input is occupancy (plus images and poses), not camera-only features; no code; the ablation table is hard to read; the lambda weights are missing so the loss cannot be reproduced; planning metrics mixed in.
