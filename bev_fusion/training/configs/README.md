# configs - training configurations (`python training/train.py <config.json>`)

Cards: the `experiments/<folder>/` cards named in the rows below were deleted on 2026-11-04 (D56); they are in the git tag `archive/cards-before-delete-2026-11-04` (`experiments/README.md`). The t14 pair has no start gates or rule any more and needs a new card before it starts.

A config is the JSON of `train.TrainConfig` (unknown keys are an error); `model` holds `model.ModelConfig` fields, `loss` holds
`losses.LossConfig` fields (the head layout flags are taken from `loss`). One run = one config; an arm is the base config with
the listed fields changed (copy the file, change the name and the fields, never edit the base).

**Presets** (`presets/*.json`, overrides, not configs): `smoke` (20 steps, the end-to-end smoke of a new version), `small` (400 steps, evaluation every 100: a quick look), `onfly` (all caches off: preprocessing on the fly). `python -m trainsuite start training/configs/<base>.json --id <id> --preset small --set seed=3 ...` composes the run's config (written to `temp/compose/`, scratch), runs `startable.py` and prints the `run.py` command; `compose` only shows and writes the config. The full run is the base config as it is; data computed elsewhere is `--set feature_cache=<path>` (and `gt_cache`, `radar_cache`); one module with the rest frozen is `--set 'train_only=["fusion."]'` once `train.py` knows the key (see `freeze.py`). `fast` (D53: `model.share_mover`, `model.splat_fused`, `model.sync_free`, `loss.sync_free`: the launch- and sync-saving variants of `training/launch_saving.py`, same arithmetic; D54: also `pin_memory`, which is 40 % SLOWER without the sync-free forms and 6 % faster with them: records/speed_options_2026-11-03.md section 8), `timing` (70 steps, no evaluation, probe on, slim end: the timing runs of `trainsuite speed`).

**Split and manifest** (D48). A new config does not carry scene lists: it says `"split": "small"` / `"large"` / `"xl"` (the lists are `../../splits/<name>.json`, `../../splits/README.md`). `python -m trainsuite start` resolves the name through `training/splits.py` before it writes the composed config (project.json `trainsuite.resolve`), so the composed file, the `config.json` the trainer copies into `runs/<id>/` and the evaluation hold the exact lists; the trainer itself refuses an unresolved `split` key (a direct `python training/train.py` or `startable.py` call on a split config stops with "unknown key", it does not train on all scenes). Stored configs keep their inline lists and work unchanged; a config with `split` and inline lists is refused (only `null` switches `split` off: `--set split=null` for a base with a split and the preset `small_set`, which brings its own lists). `compose` alone does not resolve, only `start` does (a composed file with `split` stops in `train.read_config`). The preset `small` is a length (400 steps), the split `small` is data. A stored config moves to a split with `--set train_scenes=[] --set val_scenes=[] --set split=small`; the exact command is in `../../splits/README.md`.

The minimal experiment manifest is the config plus four things: `split` (the name, in the config), `gt` (the autogt version: `runs/<id>/gt.json` has `gt_signature` and `gt_version`, the split file names the version its caches were checked against), `code` (the commit of the run's snapshot: `runs/<id>/code/SNAPSHOT.txt`, the run's tag `bf/<id>`, `records/runs/<id>/run.json`) and `card` (hypothesis, prediction, rule: `run.json`, `experiments/<id>/experiment.md`). `python training/splits.py manifest runs/<id> [--card records/runs/<id>/run.json]` writes them together as `runs/<id>/manifest.json`: `{run, split: {name, train: {n, hash}, val: {n, hash}}, gt: {signature, version}, code: {commit, tag}, card}`; the split name is found by comparing the lists in `config.json` with the files in `splits/` ("inline" if none matches, "official" for no lists), so it also works for the stored runs (`t16_full_s0` is `large`). `start` does not write it: the commit exists only when `run.py` has made the snapshot and `gt.json` only when the trainer has built its data, so the file is made after the launch (a line after `record_gt` in the trainer would do it; the packaging step writes `split.json` next to it with `splits.write_split_json`).

The defaults of `model.ModelConfig` (`trunk_width` 0.5, `trunk_detail` 0, `trunk_pretrained` empty) are the third row of the table (the first round), not the first (what runs), and `BEVTrunk(light_up=...)` (the plan's T2) has no `ModelConfig` field, so a config cannot ask for it. A config copied from the last one inherits all of this: state the trunk in the `_about` key when a config means to change it, and when it does not, leave the three fields as they are.
