**What it does** [checked]: kernel function g(y_i) = sum_k h(y_i, x_k) W_k over K kernel points x_k with the linear correlation h = max(0, 1 - |y_i - x_k| / sigma) (sigma the influence distance), applied to all input points within a radius r (not k nearest, more robust to density changes). Rigid kernel points are placed by an energy minimisation at radius 1.5 sigma (K = 15, sigma 1.0, rho 5.0 in the paper). Deformable variant: the network predicts K offsets per location (learning rate x0.1), with a fitting and a repulsive regulariser (weight 0.1). Grid subsampling controls density, cell size doubling at each pooling.

**Results that matter** [checked]: ModelNet40 OA 92.9 rigid / 92.7 deformable; S3DIS Area-5 mIoU 65.4 / 67.1; ScanNet 68.6 / 68.4; Semantic3D reduced-8 74.6 / 73.1; Paris-Lille-3D 72.3 / 75.9; ScanNet ablation with 4 kernel points: deformable loses 1.5 % mIoU, rigid 3.5 %; about 14.3 M / 15.2 M parameters on ModelNet40. No driving or radar benchmark; no SemanticKITTI number was on the page read.

**Transferable technique**: for the radar density, a KPConv-like g with a few kernel points laid out in (dr, dphi) around the detection (a learnable, possibly deformable set of "lobes", each with a linear fall-off) is a low-parameter alternative to an MLP: the result is a mixture of triangular bumps with learned weights W_k (per output channel) and positions. It keeps g compactly supported by construction, which fixes the gate radius and makes cell-wise evaluation sparse. Deformable offsets predicted from the detection features (r_d, RCS, dt) would give a feature-dependent footprint.

**Cost and fit**: neighbourhood by radius search; K kernel evaluations per pair, cheap; the rest of KPConv (ResNet-style bottleneck blocks, strided pooling) is not needed.

**Doubts**: designed for dense lidar-like clouds; radar has 10 to 100 points per sensor, so kernel points of fixed layout may under-train; no evidence on radar.
