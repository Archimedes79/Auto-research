**What it does**: LiDAR pillars (0.25 m) are encoded (PFE), run through a FastFlow3D-like encoder and a Gated Multi-frame Fusion block. Motion comes from pillar association: correspondence probabilities are a softmax over the feature distance between pillars of t and t+1 (patch size 32), and the flow is the probability-weighted displacement. The training signal is contrastive: frame t+1 is made from the same sample by a known random rotation / shift / scale / jitter, so the true correspondence of every pillar is known; positives are soft (0.6 for the exact match, 0.1 for neighbours within a distance threshold).

**Results that matter** (nuScenes motion prediction, mean error, m; Table 3 as returned): static / <= 5 m/s / >= 5 m/s - Zero (no motion) 0.000 / 0.611 / 8.652; PillarMotion (SPML) self-supervised 0.162 / 0.697 / 3.550; ContrastMotion 0.083 / 0.452 / 3.527. Medians 0.000 / 0.096 / 1.323. The page does not mention MotionNet or the supervised numbers, so no supervised comparison is available here.

**Transferable technique**: a flow net can be trained on synthetic correspondence: augment one BEV (known rigid transform) and use the transform as the label. On our synthetic world this is free, and the correlation / soft-argmax association over feature distance is the RAFT-like cost volume reduced to a local window.

**Cost and fit**: the association is local (patch 32), so it is cheap; it assumes the augmentation motion resembles the real object motion.

**Doubts**: no code; no runtime in the main text; a global rigid augmentation teaches nothing about independently moving objects, which is exactly where the 'fast' bucket stays at 3.5 m error against 8.7 for zero motion.
