# 2401.03836 WidthFormer - height-compressed width features with a depth-bin reference encoding

| fact status | checked |

| verdict | context (speed reference; transformer decoder) |

**What it does**: Image features are max-pooled over the height axis into width features that serve as keys and values of one transformer decoder layer over BEV queries. Depth enters through a 3D positional encoding: each pixel is lifted to D depth bins, a light conv head predicts reference coefficients that aggregate the bin encodings (RefPE); a categorical height distribution per column pools the pixel encodings for the width features; a categorical depth loss is an auxiliary task.

**Results that matter** (nuScenes, 3D detection only, 256 x 704): view-transform latency 1.5 ms on an NVIDIA 3090 (CUDA) and 2.8 ms on Horizon Journey-5; the LSS baseline in its ablation is 4.5 ms. Comparison curves against IPM, LSS, MatrixVT, FastBEV and BEVFormer are in a figure only. No segmentation.

**Transferable technique**: a lift can be 1.5 ms with one attention layer if the camera geometry is injected as a positional encoding with depth bins; height compression is cheap but loses the vertical structure that our elevation channels keep.

**Cost and fit**: transformer, not a lookup-table gather; useful only as the speed reference for a "learned" lift.

**Doubts**: detection only; the depth is a positional encoding, not a distribution that multiplies a feature; code licence unknown.
