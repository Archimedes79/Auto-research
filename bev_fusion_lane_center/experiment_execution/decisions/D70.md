Decision: D70 (Mirko, in chat on 2026-11-10, in the BEV system chat, after I had explained cold and warm and named the open point that the Evaluation draft sets `cold` as the default of the runner while the runner carries the memory; his words, verbatim: "Wenn ein Netzwerk ein Memory hat, sollte es korrekt initialisiertu nd dann benutzt werden."). My reading, which he can correct: (1) the default memory mode of the runner, of the result set and of the evaluation is warm: at the start of every scene, and after a gap in a scene, the network starts from its own cold start (the empty state, the way `model.py` defines it for a chain without state), and from then on the state is carried from keyframe to keyframe; (2) cold (an empty memory at every frame) stays available as a named second run, for example for single frames drawn at random, and is never the default; (3) the memory mode is always written into the identity of a result set, so a warm and a cold number are never compared with each other; (4) a network without memory is not affected; (5) to check, not decided: that the chain carried over a whole scene is no longer than what the network saw in training (clip length against about 40 keyframes of a scene), `bev_suite memory` (warm against cold on the same frames) is the existing measurement.
Consequence: the open point "memory default" of `bev_fusion/records/jobs/running/README.md` is settled as warm; the Evaluation chat's draft (`Runner.run(..., memory="cold")`) changes its default to warm; no code changes today.
