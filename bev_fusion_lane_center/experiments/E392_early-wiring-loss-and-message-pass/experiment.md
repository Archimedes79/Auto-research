# E392 - iterative wiring inside the token head: after layer 1 (and 2) the wiring is read, the tokens exchange information with their likely partners along it, with an end-to-end loss on every read; perception only, no map

**Version 3.1 (2026-11-22 00:10, system clock), DRAFT, nothing run.** Versions 1, 2 and 3 went through a fresh `ar-critic` (cards): v1 REVISE (2 blocking + 8), v2 REVISE (minor), v3 REVISE (3 blocking + 5 should-fix; the text-only fixes are taken in here, section 5). **Version 3 changed the design** after the owner's clarification in the chat of the lane experiments session (2026-11-21, recorded here in paraphrase only; it is relayed by the chat, not recorded as a D<n>): wire iteratively and exchange the information between the possible partners; work with as much end-to-end loss as possible; learn nodes and their properties, the node weight end to end, top-K, self-attention, connection plus information exchange, self-attention, connection; the result is a lane graph on which a cross-attention to the map can be done afterwards; run the experiment and an end-to-end training. The map part is E391 (association, D135: the map reads logical data and leaves the perception untouched); this card is the perception part only. What of that chain exists already is not repeated: nodes with properties, the soft node weight (key weight 1 - p_none after the first 1000 steps, trained end to end in stage 2 / S4), top-K (hard, no gradient, named), the self-attention layers, the wiring softmax with a none slot. New is exactly one thing: **the wiring is read after layer 1 (and after layer 2) with a loss on each read, and the tokens exchange information along the read connections before the next layer** (a round). Top-K 384 and the map are different questions and not part of this card.

## 1. Card text
- **Statement:** In the champion token head, reading the wiring after layer 1 (arms x, r1) and after layers 1 and 2 (arm r2) and letting the tokens exchange information along the read connections before the next layer raises the VAL topo F1 at the D115 decode by at least the band 0.010 over the retrained champion head on both seeds, without lowering F1@1.0, lanes found or junction F1 beyond the guards; every rung (the loss on the early read, the second round) has to beat EVERY simpler arm by the band, not only the simpler arms that happen to be KEEP (section 1.3).
- **Mechanism:** Today the wiring is read once, after layer 3, and supervised once; before that the tokens exchange information through self-attention over all tokens with a relative-geometry bias, which knows nothing about who the likely partners are (no token sees its likely successor or predecessor before the final read). A round reads the wiring from the current features (the same function as the final read, shared weights, so a read has the meaning "who is my successor"), and passes to every token a weighted sum of the features of its likely successors and of its likely predecessors; the next layer then attends with that information. With the loss on each early read the connection structure is supervised from the first round on (deep supervision with one shared reading, as the head does for the types: one `types` linear for both positions); without it (arm x) the early read is only a learned weighting that the final loss shapes through the messages. All steps are soft: the message weights are the early read probabilities themselves (no argmax, no threshold, no new hard selection); R1 stays met up to the named items. ### 1.1 The change in detail (the design the coder is given, with `DESIGN.md`)
- **Option `--rounds R` (0, 1, 2; default 0 = the champion):** a round after layer 1 (R >= 1) and after layer 2 (R = 2). Order inside the head: layer 1 -> `types1, w1` read from this x (unchanged, BEFORE the round) -> round 1 -> layer 2 -> [round 2] -> layer 3 -> `types`, the final read as today; the key weight of the early reads and of layers 2 - 3 is `lw(w1)` after the switch step and `lw(w_in)` before it (w1 is read after layer 1 and is stale at round 2, as it already is for layer 3 today). In a round k, from the current features x:
  1. **early read:** the wiring is read with the SAME function as the final read (`lnw`, `wq`, `wk`, `wbias(g)`, `dest`, `none_k`, `none_b`; shared weights); `wbias(g)` is computed once and reused. Output `logp_k` (B, 2, K, K + 1), same shape and masks as `logp`;
  2. **exchange:** p_k (B, K, K) = the sum over the two classes of exp(`logp_k`[..., :K]) x gate, the early probability of the link i -> j. Forward message `mf_j = sum_i p_k[i, j] (W_v x_i)`, backward message `mb_i = sum_j p_k[i, j] (W_u x_j)`; **`x <- x + MLP([mf ; mb])` with an MLP 128 -> 64 -> 64 (GELU) whose LAST linear layer starts at zero** (no LayerNorm: the head starts exactly as the champion function, so the arms and c start alike and the residual scale is not perturbed at step 0); parameters of each round separate (about 20 700 each, +16 % of the head's 127 131 per round); p_k is not detached (the final loss reaches the early read through the messages);
  3. the next layer runs on the updated x.
- **Parameter order:** the new modules are constructed AFTER all existing ones, so every old parameter initialises exactly as in c for the same seed; with `--rounds 0` the state_dict keys and the forward are the champion's.
- **Option `--wire-weight W` (default 0):** the early loss `W x sum_k (nll_k_s + nll_k_l)` with `_source_nll` on `logp_k`, with the same none weight, rows and normalisation as the final likelihood; W = 0.5 (the weight the layer-1 type cross-entropy has), ONE value, not tuned. With W = 0 the early reads get no loss (arm x). Info keys `nll1_s`, `nll1_l`, `nll2_s`, `nll2_l`. The stage-2 trainer must carry it (section 2).
- **Option `--msg uniform` (the content null u):** the message weights replaced by uniform weights over the allowed pairs that keep each token's soft degree: `w_fwd[i, j] = gate[i, j] / sum_i' gate[i', j] x indeg_j`, `indeg_j = sum_i p_k[i, j]`, and `w_bwd[i, j] = gate[i, j] / sum_j' gate[i, j'] x outdeg_i`, `outdeg_i = sum_j p_k[i, j]`: the same parameters, row sums and pooling as the real exchange, but no information about WHICH neighbours the early read found likely.
- **Eval mode:** with `--rounds` >= 1 the early reads and the exchange run in eval mode too (the forward has no eval branch); with `--rounds 0` the forward, the loss and the parameters are the champion's bit for bit.
- **Not changed:** the allowed-pair gate, top-K, the four read-out thresholds, the type softmax, the scale branch, the data, the caches, the decode.

### 1.3 The verdict (by hand, written before any run; the JSON rule is NOT the verdict)
D_X(S) = topo F1(X_sS) - topo F1(c_sS) at D115 on VAL 873, per seed; the paired scene-bootstrap 95 % interval of D comes from the paired card. Arms are ordered by simplicity c < x < r1 < r2. Per arm the first that applies, in this order:
1. **INCONCLUSIVE:** a kill fires; a started run does not finish; the two seeds disagree beyond the band (one D >= +0.010, the other <= -0.010); on exactly one seed a guard fails while D >= +0.010. Add the diagnosis (a seed), no verdict.
2. **CUT-X:** D <= -0.010 on one seed and the other seed not >= +0.010; or a guard fails on both seeds.
3. **KEEP-X (quality):** D >= +0.010 on both seeds, the 95 % interval of D excludes 0 on both seeds, and the guards hold on both seeds: F1@1.0 not below c by more than 0.005, lanes found by more than 0.010, junction F1 by more than 0.015.
4. **TIE:** everything else.
- **The ladder (adoption):** an arm X is a candidate when it is KEEP-quality AND X - Y >= +0.010 on both seeds for EVERY simpler arm Y (x, r1 below it; KEEP, TIE or CUT alike: point differences of the same pairs). The adopted rung is the highest candidate whose cost check holds (next bullet) and whose null holds (the bullet after); if there is none, **c stands** (TIE). So a gain of r1 that x already gives (x +0.009, r1 +0.011) does not adopt r1.
- **Cost, measured before the null (arms x, r1, r2):** `jtoken_eval.py timing --run e392_<arm>_s0 --b-run runs/e292_a_s0` (24 cached VAL frames, batch 1, bf16, quiet GPU, `usable_for_gcost` true) for c TWICE (first and last) and the arms in the same session (the session spread of the whole path is about 1 ms): the cost holds when whole(X) <= mean(whole(c)) + 1.0 ms per round and the whole path <= 19.7 ms; otherwise **QUALITY-ONLY** (reported, not adopted, no null run). The 19.7 ms is the E365 G-cost bound (E324 s); the +1.0 ms per round (about 6 % of the path) is this card's own bar, chosen here, not taken from a source. A pre-check before the arms (a random-weight rounds head timed with `set_step(SWITCH)`) says in advance whether a round is likely to pass; the quality runs go on either way (ordered by the owner), the result says QUALITY-ONLY when the cost fails.
- **The content null (only for the highest candidate that passes cost):** u (with that arm's rounds and weight) on both seeds; the arm is adopted only if arm - u >= +0.010 on both seeds (which neighbours a token reads, not the extra block, carries the gain); if u fails, the gain is capacity: **c stands** (TIE; no lower rung is adopted by this card, its u was never run).
- **Scope:** an adoption replaces the stage-1 recipe only; nothing here touches TEST or the champion entry. The ladder, the null and the guards use point differences; only KEEP-quality uses the 95 % interval. All arms share c_s<S>: a lucky or unlucky c moves every arm against c in the same direction, the arm-to-arm steps cancel it.
- **The stage-2 diagnostic (end to end), by hand:** arm A = the adopted rung, else the arm with the highest mean D among those not CUT or INCONCLUSIVE (a diagnostic of a TIE head, never an adoption). Continuity before the read: the first logged head loss of the S4 run is within 20 % of the last logged stage-1 loss window (a gross check) and the tokens of its first five frames equal those in `runs/e372_s4_s<S>`'s log (same B', same data order). Per seed, read live at D115 on VAL 873: D4 = topo F1(S4 of A) - topo F1(`e372_s4_s<S>`), Dself = topo F1(S4 of A) - topo F1(A's own stage-1 head). **S4-GAINS** (E372's classes): D4 >= +0.010 on both seeds with the paired interval above 0 on both; **S4-HOLDS**: D4 >= -0.010 on both seeds, not GAINS; **S4-LOSES** otherwise, and also when seed 1 is not run. Seed 1 runs when D4(seed 0) >= -0.010 (the class is still open); when D4(seed 0) < -0.010 the class is LOSES and seed 1 is not run. The same guards, the kill and B''s node loss growth of E372 (largest 200-step mean not above 1.2 x the start). **Action:** the champion line, the module text of `DESIGN.md` and the architecture drawing change only for an ADOPTED arm with S4-GAINS; S4-HOLDS and S4-LOSES are reported only. ## 2. Detail plan (block experiment)
What would make it fail, in plain words: (i) layer 1 has seen only one attention layer, its wiring read may be too poor to supervise usefully, and the early loss then pulls layer 1 toward a task it cannot do (CUT or TIE; the weight 0.5 is one untuned value; arm x is the check); (ii) messages over bad early edges spread errors (an early edge with p near 0 sends no message, so false negatives are not amplified, false positives are); (iii) the shared reading may need different statistics at layer 1, 2 and 3 (the types share one reading without visible harm; a separate early reading would cost parameters, not tried); (iv) layers 2 - 3 may already compute what a round adds (attention is a soft edge matrix); the ladder is the probe; (v) the gain may sit inside the noise band, as most head-side changes of E367 - E388 did; (vi) the cost of a round may exceed the bar by construction.
