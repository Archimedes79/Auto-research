# data - derived data of bev_fusion (not in git)

Everything here is derived from the raw nuScenes data (`D:\Auto-research\NuScenes`, WSL views `~/data/nuscenes_full`,
`~/data/nuscenes`; `../../datasets/NuScenes/README.md`) and the pre-trained checkpoint (`../models/README.md`) by tracked
scripts, so it can be deleted and rebuilt (rule D11 of the lane project: a new derived artifact gets its row here in the same
step). `.npy` / `.npz` / `.pt` files are ignored by git globally. Folders: `cache/` (this file's table), `../runs/` (training runs).

| artifact | made by | inputs | status |
|---|---|---|---|
| `cache/cam_feats_<set>/<scene>.npy` + `.index.npz` - outputs of the frozen camera heads (118 depth-probability + 80 context channels at 16 x 44, float16, 0.28 MB per frame); the frames the dataset uses (`n_cam`, `cam_stride`) | `python training/feature_cache.py build <dataroot> <version> <root> [--split train\|val] [--device cuda]` (resumable per scene); the whole set by `temp/setup/build_full_cache.sh` | CAM_FRONT images, calibration, `models/pretrained/dualbev-r50-cbgs.pth` | scripted; mini: `cam_feats_mini` (first 6 samples); full: `cam_feats` built 2026-10-26 on the shared GPU at 11-16 frames/s: 58,101 frames, 16 GB, 510 scenes (train 428 scenes / 16,289 samples, val 82 scenes / 3,109 samples: the nuScenes parts downloaded so far), every sample finds its 3 frames |
| `cache/gt/<token>_<res>_<ss>_<signature>.npz` - GT of one sample = keyframes k - 1, k, k + 1 on the grid with the ego steps (`FrontRadarDataset(cache_dir=...)`, float16); the key contains the signature of the generator source `gt_bev.py`, so an edit of it means a new cache | written on first use by `training/nuscenes_dataset.py` (cold: 12 s per sample before the 2026-10-26 speed-up, about 1.5 s after); prefilled before training by `python training/gt_cache_build.py ...` / `temp/setup/build_full_gt_cache.sh` (4 workers, 0.5-0.6 s per sample with the keyframe memo) | nuScenes map expansion, annotations, poses | scripted (prefilled 2026-10-26: val 3,109 samples in 480 s, train 16,289 samples in 2,236 s wall) |
| `cache/radar/<token>_<cam sd token[:8]>_<window>_<doppler shift>_<signature>.npz` - the radar detections of one sample (all sweeps of the 0.5 s window moved to the camera time, as `FrontRadarDataset._radar` computes them; float32 columns, int64 sensor), exact; the key contains the md5 of `_radar`'s source | written on first use by `training/feature_cache.py` `CachedFrontRadarDataset(radar_cache=...)` (`TrainConfig.radar_cache`); prefilled by `python training/feature_cache.py radar <dataroot> <version> data/cache/radar --split train\|val --workers N` / `temp/train/fill_radar_cache.sh` | radar sweeps, poses, calibration | scripted 2026-10-26 (experiment t1: the radar sweep reads were 0.3-0.6 s of the 0.35-0.6 s per training sample; a cached entry reads in about 1 ms); self-test `python training/feature_cache.py radar-selftest` |
| `cache/img_front/<sd token[:2]>/<sd token>.jpg` - the CURRENT front-camera frame of every train / val keyframe of the t2 scene lists as the 256 x 704 RGB image after the dataset's resize + crop (`FrontRadarDataset._image_uint8`), JPEG quality 95 (mean error about 1.4 of 255); input of the lane branch (experiment t7) | `python training/lane_branch.py build-cache <config.json>` (one process; resumable; `temp/t7/build_cache.sh`), check `... check-cache <config.json>` | CAM_FRONT images | scripted 2026-10-30 |
| `../runs/<name>/` - checkpoints (trainable weights, optimizer, EMA, RNG; the frozen camera heads are not stored), `log.jsonl`, `config.json` | `python training/train.py <config.json>` | the two caches above or the raw data | scripted (re-train; GPU training agrees within the noise band, not bit-exactly) |

Size (the nuScenes parts downloaded so far, `n_cam = 3`, `cam_stride = 2`): feature cache 16 GB (58 k frames); GT cache 2.6 GB (19,398 samples, about 0.13 MB per sample).

Update 2026-10-28 (parts 7-10, 340 new scenes: 272 train, 68 val, front camera + radar only): the three caches above were extended
by `temp/data/prep_new_scenes.sh` (radar cache 13,051 samples, GT cache 32,449 entries, feature cache about 31 k frames of the train
split plus the val split, totals now: feature cache 26 GB, GT cache 4.4 GB, radar cache 1.6 GB on C:). Scenes `scenes_parts1_6.json` (428 train / 82 val = the scenes of the earlier runs and
of the study `t2_block_swaps`) are frozen in the t2 configs as `train_scenes` / `val_scenes`: `available_scenes()` takes every scene
whose first CAM_FRONT keyframe exists, so a config without these lists would silently train on 700 scenes. The older configs
(`t1_*`) have no list and now mean 700 / 150 scenes; patch them before re-evaluating an old run.

Note 2026-10-30: the feature-cache shards of the scenes of parts 7-10 (680 files, 10.9 GB) were moved from `cache/cam_feats/` to `D:\Auto-research\bev_fusion_cache_parts7_10\cam_feats\` because C: was full (`temp/study/move_new_feats.py`; `... back` restores them). Runs with the frozen 428 / 82 scene lists do not need them; a 700-scene run does.
