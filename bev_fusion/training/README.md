# training - the training system of the camera + radar BEV system

The training system: the trainer, the run configs and their checks, probes and timing. The model (preprocessing, network, losses) is in `../net/`
(`../net/README.md`); starting, stopping and watching trainings is the tooling in `../../autoresearch/` (`Training`, `trainkit`, `tools/run.py`).
Nothing in `../net/` imports this folder (`../tests/test_net_layering.py`). Plain PyTorch (env `gcar`: PyTorch 2.8, Python 3.12, no mmcv).
Every module has a self-test with known answers (`python training/<module>.py`).

| file | what it does | self-test |
|---|---|---|
| `architecture.json` / `.svg` / `.md` | the system in five layers (built 2026-11-01): precompute, input interface, network slots, output interface, post-processing; the spec (boxes, arrows, the code each box stands for), the picture, the layer and slot tables, the checks of the build and the file map with the end-to-end table (generated by `../../autoresearch/tools/archdraw.py`) |
| `ab_timing.py` | in-process A/B timing of the speed switches (`model.share_mover` / `splat_fused` / `sync_free`, `loss.sync_free`, `pin_memory`, `prefetch_factor`, `workers`, `cudnn_benchmark`, `tf32`): ONE process builds model, optimiser and EMA, then times blocks of real training steps per arm in the order A B \| B A \| ... (the drift of the machine cancels in the pairs, the startup is paid once, no checkpoints): about 7 minutes for two arms (4 rounds, a paired 95 % interval for the difference) instead of two 6-minute runs, with less drift; `--arm NAME[:@preset,key=value]`, `--check` prints the plan; start it under run.py `--no-card` and a machine lock, alone on the GPU | `python training/ab_timing.py <composed config> --arm plain --arm "fast:@fast"`, `tests/test_ab_timing.py` |
| `train_motion_block.py` | t12: trains ONLY the motion block on a frozen finished run (config + checkpoint, EMA weights): wraps `camera_bevs` (block inputs: current camera BEV, an older window frame ego-aligned by `splat_window`, radar raster, age) and replaces `TimeMover.motion` by the block's field; the base's frozen loss + the coarse levels' motion terms; evaluates base and block on the same `val_subset` (velocity EPE on moving / static / vehicle cells, at box centres vs the object head, layer-0 warp check with GT v, loss groups, block ms) -> metrics.json | dry run on `t10_dual_s0` (4 steps, 6-30 val samples) |
| `build_image_cache.py` | the command line of the image cache a config names (`net/prep/image_cache.py`): `build-cache`, `check-cache`, `build-cache-older`, `check-cache-older` | `tests/test_student_window.py` |
| `train.py` | the BEV side of the trainer (since D48 the loop, EMA, schedules, checkpoint / resume, clipping, AMP and the stop contract live in `../../autoresearch/trainkit/`, README there; `train()` builds model, loss and data and calls `trainkit.loop.fit`; the old names still import from here): trainer for the whole chain: the model's head layout from the `LossConfig`, targets from `sample_targets` (GT at -0.5 / 0 / +0.5 s = past AND future), AdamW (decay only on weights of dim >= 2) with warm-up from lr / 3 + cosine, gradient accumulation (effective batch = `batch_size` x `accum`), `radar_window` (s of radar sweeps per set, default 0.5; 0.09 = the newest sweep of each radar, t25; `make_datasets` also passes `model.radar_per_frame` to the dataset, `to_device` moves `batch["radar_seq"]`, `augment.flip_batch` mirrors it), grad clipping, EMA, optional bf16, non-finite guard (skips the whole step), task-balancing arms `balancing` = kendall / fixed / uwso, optional train-only cross-time consistency (`consistency`, own warm-up), optional gradient-conflict log (`grad_diag_every`), sequence training (`seq_len`, `seq_bptt`: clips of consecutive keyframes of one scene, the world memory carried with the ego step between them, detached or kept in the graph; validation reports the last keyframe warm and cold), atomic checkpoints with resume (the frozen camera heads are not stored), warm start of a new run from another run's checkpoint (`init_from` -> `warm_start`: its EMA weights and Kendall s, new branches and the `init_reset` prefixes keep their initialisation, optimiser and schedule fresh; only in a folder without a checkpoint; config keys starting with "_" are comments), JSONL log (rows carry the time `t`; the velocity terms `LOGGED_TERMS` next to the groups), stop request (a `CONTROL` file newer than the process start: checkpoint, `STOPPED` marker, exit code 75, never 0; written by `autoresearch/Training`), validation under the EMA weights, `eval_fn` hook for evaluation/metrics.py; config = `TrainConfig` JSON; `runs/<name>/gt.json` records the GT identity (`gt_signature`: grid, supersampling, GtGenerator source + flags; the code snapshot does not pin GtGenerator), a resume on other GT warns and keeps the earlier signature | GT at three times -> finite loss, balancing arms, consistency (hold = weight 0, gradient reaches the motion head), gradient cosines, clips (consecutive keyframes, the carried memory changes the prediction, an attached state reaches the earlier keyframe), accumulation, 4 steps with checkpoints, resume 4 -> 6, stop request (old file ignored, new one stops at the step with checkpoint + STOPPED + exit 75), validation restores the weights, schedule, gt.json written. Host-work cuts, default behaviour bit-identical (`../tests/test_speed_flags.py`, `../tests/test_host_overhead.py`): `run_clip` reads its logged terms back with one transfer per clip, `EMA.update` uses multi-tensor calls (float32 / float64 state); opt-in `pin_memory`, `prefetch_factor`, `cudnn_benchmark`, `tf32`; `profile_steps` n (capped at 8: 30 steps held 22 GB of host RAM) writes `profile.txt` into the run folder (GPU busy share, synchronisations per step, top operators). `amp = "fp16"` trains with a GradScaler (`make_scaler`, start scale `fp16_scale` 1024; `optimizer_step` unscales, clips and steps, an overflow skips the step and halves the scale; the scaler state is in the checkpoint's `extra`; `../tests/test_grad_scaler.py`); t26: `img_jitter` / `img_jitter_from` (photometric jitter of the camera student's image, off by default: `run_clip` draws it per clip from (seed, step, micro-batch) with `augment.draw_jitter` once `step / steps >= img_jitter_from`, the cached model applies it in training mode only; `../tests/test_student_window.py`) |
| `startable.py` | is a config startable? static checks without GPU, data or a training step (what `train.build` and `check_resume` refuse: unknown fields, model / loss layout, camera kind and its caches, `fusion_area_only` with `refine`, a changed config against an existing run; every named path exists, the run name is free, disk room; the GT: the GtGenerator that would be imported must have the signature files of the version the base run was trained on, `GtGenerator/versions.csv`; the uncommitted files of `training/` that the launcher's snapshot will carry, a problem with `--require-clean`), `--write-smoke DIR` writes the 20-step smoke twin of a config, and the `run.py` start lines are printed (a real run's card text is not made up; the smoke line is `--no-card`); the end-to-end proof stays a smoke run through the launcher (`smoke.d32`) | `python training/startable.py` (36 kinds of bad config incl. `keep_steps` by the engine's rule, resume, disk, relative paths, uncommitted files, GT identity against a tagged version and the real table, smoke twin without `keep_steps`; t26: the key-frame / older-frame image caches must have a finished-build `BUILT.json` that covers the config's scenes) |
| `freeze.py` | train one part and keep the rest fixed: `train_only` / `freeze` by module prefix (`apply(model, train_only, freeze)` before the optimiser is built, `trainable(model)` for it): a prefix naming no parameter is an error with the nearest names, a frozen module is forced into eval mode by a forward pre-hook (so `model.train()` cannot let a frozen BatchNorm move its statistics), `snapshot` / `unchanged` prove frozen weights and buffers bit-equal, `report`, `signature` (compare on resume). Wired into `train.py` (TrainConfig fields `train_only` / `freeze`, the optimiser from `trainable`); `StepProfiler` is the profile window of `profile_steps`; test `../tests/test_freeze_probe.py` |
| `probe.py` | see inside a step: `ModuleProbe.begin(step)` -> `grads()` / `finish()` give `grad.<module>` and `upd.<module>` (gradient norm, update-to-weight ratio; a module with no gradient reports 0), `StepTimer` gives `t_data` / `t_step`, `dump_incident` writes `incident_<step>.json` (step, kind, batch ids, losses; capped at 50, never raises). The keys are the ones `python -m Training status RUN` shows and `health` judges (dead module, blow-up, frozen-looking weights, data-bound steps); test `../tests/test_freeze_probe.py` |
| `debug.py` | debug tools without data or GPU: `overfit_one_batch` / `overfit_ok` (the loss must go towards 0 on one batch), `frozen_stayed` (frozen part bit-equal, trained part moved, on a copy), `anomaly()`, `replay_ids` (the batch of an incident from its sample ids); test `../tests/test_freeze_probe.py` |
| `gt_scenes.py` | the ground truth a config needs: `CONFIG names` (the sequences it trains and validates on), `check` (exit 0 when the GtGenerator store holds every keyframe of them for the current generator), `build` (generate what is missing: resumable, nice 15, a run of its own: a job with `"prepare": true`, `python -m Training run job.json`). GtGenerator does not read configs: this turns the config into `<config>.scenes.txt` and calls `python -m GtGenerator have|generate --scenes-file`; test `../tests/test_gt_prepare.py` |
| `scratch.py` | scratch hygiene for `../temp/` (C: was 100 % full with 18 GB of it, 2026-11-01): `tmpdir` (smoke runs and test outputs, removed on exit), `cached` (list caches: a bigger one serves a smaller n, an outdated one is deleted, sidecar `.meta`), `dump` (a finished dump is reused, never written twice), `guard` (refuses a write that leaves < 15 GB free or passes the 10 GB budget of `temp/`), `python training/scratch.py report`. A FINISHED run keeps complete checkpoints (`TrainConfig.keep`) so that it can be resumed later; `train.py` slims them only on request (`TrainConfig.slim_at_end`, default off since 2026-11-01: one checkpoint without optimiser state and RNG, about half the size; it evaluates and warm-starts but cannot resume training) | `python training/scratch.py --selftest` (16 checks on real files); `train.py` self-test 2b (slimming, loading, EMA equal) |
| `distill_student.py` | offline distillation of the student (t22 stage A1 frozen backbone / A2 all weights): key-frame JPEGs of a split (`data/cache/img_front`) against the cached teacher outputs (`cam_feats`, `cam_feats_bevfusion`), loss = depth KL + context (1 - cosine) + MSE on H16 and H8 (equal weights, every term logged); the trainkit `fit` (resume, CONTROL stop -> exit 75, `log.jsonl` with samples/s, data wait, GPU memory), validation by head and by flat-ground range band (near < 15 m, mid, far 30 - 60 m; H16 has one row in mid and one in far) under the EMA weights -> `runs/<name>/metrics.json` with the NULL baseline (per-cell mean depth distribution and context of the first `--null-frames` 512 training frames) as `null.*`, the depth skill `1 - kl / null.kl` per head and band, and the KL per output row and column; `--eval-only` re-scores the newest checkpoint of a run (EMA weights, any `--split`, `--device cpu --threads 2` or cuda) -> `eval_metrics.json`, `metrics.json` untouched; resource gate (free RAM < 3 GB or > 6 GB of the GPU in use: exit 3, `--force`), cuda asked for and missing = exit 3 (no silent CPU run), `--resume` guard (exit 2), `--eval-every`; `python training/distill_student.py --name A1_s0 --split small --freeze-backbone`; the loss and the checkpoint loader are in `student_encoder.py` | `../tests/test_student_encoder.py` (loss known answers, bands, null / skill / curves, fake-clock samples/s, a synthetic key-frame tree, CLI stop / resume / EMA / eval-only) |
| `legacy/` | modules off the whole chain (no import from `model.py` / `train.py` / `evaluation/`), kept runnable with their gates: `s1_camera.py` + `train_s1.py` (S1 camera-only pipeline, `../studies/early/s1_pipeline.py`), `camera_decoder.py` / `radar_decoder.py` (single-sensor decoders, `../studies/early/camera_only.py` / `radar_only.py`), `dualbev_front.py` (t4 SOA front, `../studies/recipes/t4/`), `light_encoder.py` (plan 2.7 light image encoder) - see `legacy/README.md` | each module's own self-test (`python training/legacy/<module>.py`) |

`configs/` holds the training configurations (`python training/train.py configs/<name>.json`, base `t1_base.json`, arms in its README; t21 (D51): `t21_pair.json` / `t21_pair4.json` (stride 4) / `t21_rec.json` / `t21_ctl.json` = `t20_base.json` warm-started from `runs/t20_base_s0` for 1500 steps at lr 1e-4 (ema 0.99; rec: batch 2, accum 3), differing in `model.cam_buffer` and `n_cam` only); the cache of the frozen camera heads is built by `python net/prep/build_feature_cache.py build ...` (`../data/README.md`, "Rebuild the caches for a split").
