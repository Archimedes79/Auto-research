**What it does**: Point clouds are unordered and change between steps, so features of consecutive frames cannot be stacked. The state of the cell is (coordinates P, per-point state S of n x d'). For every point of the current frame the cell finds neighbours in the previous frame (kNN or ball query), concatenates [own input feature, neighbour state, displacement (neighbour - own position)], applies a shared FC layer and max-pools; PointGRU / PointLSTM add gates, and an extra step re-weights and permutes the old state onto the new points.

**Results that matter** (checked, prediction of future point clouds, CD / EMD): Moving MNIST 1 digit (PointLSTM) 1.16 / 1.78, 2 digits 5.18 / 4.21 (ball query beats kNN: EMD 4.21 vs 5.13); Argoverse (PointRNN) 0.2789 / 0.8964; nuScenes (PointRNN) 0.0619 / 0.3750 (units not given on the page read). Cost: scales with the number of points, not the size of the space: on two-digit Moving MNIST about 49.6 GFLOPs for PointLSTM against about 345 GFLOPs for a voxel ConvLSTM.

**Transferable technique**: keep the radar history as POINTS with a state, not as a raster: each point carries its measurement vector plus a learned state, the old points are first moved by ego motion and by the radial Doppler shift (see 2508.12330), and the neighbour search then pairs old and new detections of the same reflector; the BEV raster is built once from the aligned points. This removes the repeated bilinear resampling of a grid state (blur at every step) because positions are only transformed, never interpolated. A ball query on 3,750 points is a 750 x 3,000 distance matrix, below 1 ms on the 3060 (estimate).

**Cost and fit**: the state and the update are small MLPs; the neighbour search dominates and is cheap at our sizes. Needs the ball radius tuned to speed x dt (about 1 to 3 m at 0.08 to 0.5 s and 20 m/s); that is a per-point radius that the Doppler can set.

**Doubts**: the task is future-point prediction on lidar/MNIST, not detection or mapping; no comparison with an ego-aligned raster state; the nuScenes units are unclear; the PyTorch port depends on PointNet++ ops (build effort on WSL).
