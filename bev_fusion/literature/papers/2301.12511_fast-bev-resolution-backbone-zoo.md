**What it does** [checked]: ResNet (R18 / R34 / R50 / R101) + a 3-layer FPN whose multi-scale outputs are F1/4, F1/8 and F1/16; the multi-scale variant projects all three into BEV grids of 200, 150 and 100 cells per side; the stride of the single-scale model is NOT stated on the page. Voxel grid 200 x 200 x 4 or 6 (250 x 250 x 6 for M4 / M5), BEV encoder 2-6 blocks of 192-256 channels, 4 frames in the zoo. The README offers two kinds of weights (Google Drive folders): trained detectors (`epoch_20.pth` per config) and 2D backbones "COCO-pretrained Cascade Mask R-CNN R18 / R34 / R50 fine-tuned on nuImages" (README via summariser; the paper text itself does not name the pre-training data).

**Results that matter** [checked, nuScenes val detection, mAP / NDS]:
- Image resolution (Table VI, R50, 2 frames, voxel 200 x 200 x 6): 256 x 448 0.280 / 0.419; 256 x 704 0.321 / 0.451; 464 x 800 0.342 / 0.466; 544 x 960 0.345 / 0.472; 704 x 1208 0.358 / 0.478; 832 x 1440 0.368 / 0.491; 928 x 1600 0.369 / 0.488 (saturates near 832 x 1440).
- Backbone (Table IX, 4 frames, 20 CBGS epochs): R18 0.293 / 0.437; R34 0.331 / 0.467; R50 0.335 / 0.473; R101 0.345 / 0.482 (the R18 to R34 step is the large one, R34 to R50 is +0.4 mAP).
- Multi-scale image features (Table V, R50, 2 frames, 256 x 704): baseline 0.321 / 0.451; image multi-scale (incl. the 1/4 map) 0.320 / 0.451; BEV multi-scale 0.316 / 0.446; both 0.324 / 0.455. With the long schedule (Table II): 0.334 / 0.473 single-scale against 0.343 / 0.485 multi-scale.
- Zoo (Table XIII / XIV; INT8 TensorRT FPS on Xavier / Orin / T4, six cameras, 4 frames): M0 R18 256 x 704 0.277 / 0.411, 19.7 / 44.8 / 97.1; M1 R18 320 x 880 0.295 / 0.421, 20.4 / 41.3 / 82.0; M2 R34 256 x 704 0.326 / 0.455, 15.1 / 43.3 / 82.0; M3 R34 256 x 704 (6 height cells, 256 ch) 0.331 / 0.467, 10.4 / 32.3 / 55.9; M4 R50 320 x 880 0.346 / 0.482, 6.3 / 20.9 / 34.5; M5 R50 512 x 1408 0.369 / 0.493, 4.3 / 16.6 / 23.5. Xavier 22 TOPS, Orin 170 TOPS, T4 130 TOPS; training 32 A100.

**Transferable technique**: (1) a sizing table: R18 to R34 at equal everything else is worth +3.8 mAP / +3.0 NDS (Table IX); in the zoo, M0 to M2 (R18 to R34 together with a larger BEV encoder, 2b-192c to 4b-224c) costs 15 percent of the T4 INT8 FPS (97.1 to 82.0); R34 to R50 is worth only +0.4 mAP / +0.6 NDS; resolution from 256 x 704 to 464 x 800 is worth +2.1 mAP / +1.5 NDS, beyond 832 x 1440 nothing. (2) The 1/4 map in the FPN gave no detection gain at the short schedule (0.320 vs 0.321 mAP); that is a statement about boxes of cars, it cannot be read as "stride 4 does not help thin lanes", and the page contains no stride ablation. (3) A nuImages-pretrained R18 / R34 backbone with FPN is downloadable (Google Drive, licence unstated), a driving-domain init for a small encoder; ImageNet-only init was not compared on the page.

**Cost and fit**: all numbers are six cameras x 4 frames on INT8 edge chips; one front camera, one frame is roughly 1/24 of the work, so only relative numbers carry over. Code is mmcv 1.4 / mmdet 2.14 and has no stated licence: read-only. The M0 / M2 weights are detectors with CenterHead, not map models.

**Doubts**: detection only; no map or lane metric; resolution sweep uses 2 frames and R50, the backbone sweep 4 frames, so the two tables are not one grid; the FPS figures are INT8 with TensorRT versions that differ between devices (CUDA 11.4 / TRT 8.4 on Xavier and Orin, CUDA 11.1 / TRT 7.2.1 on T4); licence of code and weights unclear.
