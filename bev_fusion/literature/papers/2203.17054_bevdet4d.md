# 2203.17054 BEVDet4D: align the previous BEV feature, concatenate, predict velocity as an offset

| | |
|---|---|
| source | https://arxiv.org/abs/2203.17054 and https://arxiv.org/html/2203.17054, arXiv 2022 (Huang, Huang) |
| fact status | checked (abstract page and html page read) |
| groups | A5: 2, F1: 1, axis F4 (temporal BEV, moving vs static) |
| code / licence | https://github.com/HuangJunJie2017/BEVDet, licence not checked (memory: Apache-2.0) |
| verdict | use (the cheapest temporal baseline: two frames, warp, concat) |

**What it does**: Keeps the BEV feature of the previous frame, warps it into the current ego frame with the ego transform (bilinear grid sampling, rotation plus translation), concatenates it with the current BEV feature and runs an extra BEV encoder (two residual units) before the head. Fusion after that extra encoder works best. For moving objects it does not model motion explicitly: the velocity target is turned into a positional offset between the two aligned features, which removes the time interval and the ego motion from what the network must learn. Training samples the time gap between the two frames (3T to 27T, T about 0.083 s), test uses about 15T.

**Results that matter** (nuScenes val, BEVDet-Tiny, 0.8 m grid): single frame 39.2 NDS / mAVE 0.909; concatenation without alignment 37.6 NDS / mAVE 1.544 (worse than no history); translation-only alignment mAVE 1.186; offset target 44.0 NDS / mAVE 0.479; rotation + translation alignment mAVE 0.376; time-interval augmentation 0.328. Cost: Tiny 52.6M to 53.6M parameters, 215.3 to 222.0 GFLOPs, 15.6 to 15.5 FPS; Base 1.9 FPS both. Aligning after the view transform (15.6 FPS) is twice as fast as aligning inside it (7.8 FPS). At 0.4 m grid GFLOPs rise to 440.8 and interpolation hurts less.

**Transferable technique**: (1) ego warp of the stored BEV by grid sampling is almost free (+1 M parameters, -0.1 FPS); (2) warp must include rotation, and an unaligned stack is worse than none; (3) velocity as the offset of an object between two aligned frames: the moving part is read from the difference of the warped and the current feature, the static part cancels. For a 0.5 m grid: finer grid means interpolation error of the warp matters less. Not registered as a K id.

**Cost and fit**: Memory of the temporal part is one extra BEV map (the previous one); no recurrent state. Needs ego pose only. Works with any BEV backbone.

**Doubts**: Only two frames; no explicit static/moving split (moving things are handled implicitly by the network via the feature difference); detection benchmark, no lane or map result; no memory figure on the page.
