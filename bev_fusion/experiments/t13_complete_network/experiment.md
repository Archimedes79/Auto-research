## 4 GT version and how it is pinned
- **Stage 1 trains and is evaluated on GT v5, signature `0.5_4_15efbde2d1`** (`autogt/versions.csv`: v5 = the generator of the t10 runs). The controls `t10_dual_s0` / `s1` were trained and scored on it; a bundle on any other version is not matched with them.
- **Why this has to be written down:** the live autogt is v8 (`c643a7539d`). v6 changed the velocity / flow targets (ego velocity at the ends of a sequence, instance / velocity / flow_sigma on the same sub-pixels) and v7 the occlusion (boxes hide by their height, softer `occluded`); both touch the targets of the heads this ladder changes (velocity, objects). A run started from the live tree would not find a stored GT under its own signature and would build the v8 trainval GT first (about 5 h; the GT chat is building it now), and its numbers would differ from the controls by the GT version as well as by the blocks.
- **How it is pinned (training):** a copy of autogt v5 in the run folder, as the stopped long run has it: `git archive` of the tag `autogt/v5` (path `bev_fusion/autogt`; the long run took the snapshot d14597e2e8, byte-identical in the five signature files) extracted to `runs/<run id>/autogt/`, next to the pinned `code/`; the walk-up of `nuscenes_dataset` / `losses` / `gt_bev` in the snapshot checks the run folder before any folder above it, so the trainer imports THAT copy whatever the live autogt becomes. The stored v5 GT stays where it is (`data/autogt/15efbde2d1`, 35000 keyframe files, and the trainer's cache `bev_fusion/data/cache/gt/*_0.5_4_15efbde2d1.npz`): never rebuilt, never removed (hard rule 5). Verified by the smoke test's second check (`autogt.__file__` inside the run).
- **Evaluation:** `runs/<id>/gt.json` must carry `0.5_4_15efbde2d1` and `bev_suite.py compare` refuses otherwise. The evaluation path imports the live `evaluation/`, `training/` and, through the repository root, the live autogt, so it has to run from the pinned copy (a `git archive` checkout of the same snapshot) or the arms have to be re-evaluated under the new version. Open: how `bev_suite.py` picks a run's GT (the Evaluation chat); the BEV system chat tells. Both controls are re-scored in step 0 with the same evaluator and pin.
- **The move to v8 is a separate step:** the controls retrained on v8 (`t10_dual` s0 / s1 again), or the GT difference declared; old numbers keep their label and are never mixed with new ones in one comparison.
