**What it does** [checked]: the image-view encoder, a view transform (LSS) and a BEV encoder; BEVDet-Tiny uses 704 x 256 (W x H) and BEVDet-Base 1600 x 640; the paper also tests 1056 x 384 and 1408 x 512. Source images are 1600 x 900. Augmentation: flip, random scale (centred on W_in/1600), rotation +-5.4 deg. Crop: "randomly in the horizon direction but fixed in the vertical direction"; the formula keeps the BOTTOM H_in rows of the scaled image, so the top (sky, horizon region above the cut) is removed; test time uses the same bottom-aligned window and a centred horizontal crop. The released config has `input_size (256, 704)`, `src_size (900, 1600)`, `resize (-0.06, 0.11)`, `crop_h (0.0, 0.0)`.

**Results that matter** [checked, nuScenes val mAP, detection over all ranges]: BEV cell 0.8 m: 704 x 256 31.2, 1056 x 384 33.3; BEV cell 0.4 m: 704 x 256 31.5, 1056 x 384 34.8, 1408 x 512 36.0. So +2.1 mAP for 1.5x the image size at the 0.8 m BEV; the BEV cell size alone moves only +0.3 mAP at 704 x 256 and +1.5 at 1056 x 384. The authors conclude that image resolution has a large effect on accuracy while the BEV resolution mainly trades accuracy against compute. No ablation of the crop, no per-range result.

**Transferable technique**: (1) cutting the top of the frame and keeping a bottom-aligned window is established practice in this family (every nuScenes BEV model derived from BEVDet inherits it); our 256 x 704 already does it. A horizon strip is therefore an extension of the same crop idea (keep the rows that matter, at a higher scale), not a new kind of operation; (2) image resolution, not BEV cell size, is the lever that moves mAP; (3) the numbers give an expected size of effect to compare with our own stride / strip test: about +2 mAP per 1.5x of image side, on aggregated detection.

**Cost and fit**: nothing to port, it documents a recipe; it justifies testing the strip against a plain 1.5x image (same pixel budget comparison).

**Doubts**: mAP is dominated by near objects (no per-range split in the nuScenes toolbox default), so far-range benefit is invisible in these numbers; the paper does not say the crop removes sky; the resolution table is for the Tiny model and an old LSS-type transform.
