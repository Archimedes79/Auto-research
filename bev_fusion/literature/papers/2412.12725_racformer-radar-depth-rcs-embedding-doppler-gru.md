# 2412.12725 RaCFormer: radar depth + RCS embedding for the lift, ConvGRU over radar BEV as Doppler/motion catcher

**What it does**: (a) Radar BEV: points are processed like lidar with PointPillars, z set to 0, max-pooled pillar features give a radar BEV map. (b) Depth head: each radar point is given a default height (z_r = 1 because elevation is unreliable), projected with the calibration, its vertical extent stretched over the full image height, giving a coarse radar depth map; discretised depths, RCS and pixel position are embedded and concatenated with the 16x downsampled image features before the depth head. (c) Implicit dynamic catcher (IDC): a ConvGRU runs over multi-frame radar BEV features, h_t = ConvGRU(x_t, h_{t-1}), output Conv2D(h_t + x_t); the paper does not list Doppler as a separate input channel. (d) Queries on concentric circles (polar) for initialisation. Queries sample both BEV and image view.

**Results that matter** (nuScenes val, mAP / NDS): depth/RCS embedding 43.6 / 51.7 (none) -> 44.3 / 52.9 (+ radar depth) / 44.1 / 52.5 (+ RCS) / 44.7 / 53.8 (both): RCS alone is worth +0.8 NDS, radar depth +1.2 NDS. IDC on moving objects: slow (0-5 m/s) mAP 18.8 -> 19.6, fast (>5 m/s) 43.4 -> 44.9. Real-time variant 64 x 64 grid at 1.6 m per voxel, 4 frames: 51.0 mAP / 58.8 NDS at 12 FPS on an RTX 3090. Full model: 64.9 mAP / 70.2 NDS (abstract).

**Transferable technique**: feed RCS and range as embeddings of the radar-projected depth map into the camera lift (small, per-attribute ablated gain); keep a recurrent state on the radar BEV so Doppler/motion cues accumulate. For a static lane target the recurrent radar BEV is more useful as temporal radar-occupancy memory than as Doppler.

**Cost and fit**: the radar pieces are small; the rest (query decoder with BEV + image sampling) is detection-specific and heavy.

**Doubts**: IDC gain is +0.8 to +1.5 mAP and only shown on moving objects; the abstract-level claim that Doppler is used is not matched by any Doppler input channel.
