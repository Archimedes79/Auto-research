## 1. Card text: the design, as the build reads it
- **Tokens (cache, frozen B, section 2a):** the top-K = 384 cells of B's node head by existence logit e, in descending order; per token: B's node token `tok` (64 d, after B's refinement), pos (cell centre + offset, metres), dirv (unit), e, the 8 flag logits, s, uout, uin. K is fixed after the coverage report of the lane chat (section 2a: the share of GT nodes that have a token inside 1.5 m for K = 256 / 384 / 512 on TRAIN and VAL; K is the smallest of the three with at least 0.97 of what K = 512 covers).
- **Embedding:** x0 = LN( Linear(64 -> 64)(tok) + MLP([Fourier(pos, 4 bands), dirv, e, flags, s, uout, uin]) ), d = 64.
- **Soft pruning:** the existence weight w_j enters every attention as the key bias log w_j (the gradient reaches the existence): w_j = sigmoid(e_j) of B in layer 1, and w_j = 1 - p_none(j) of the head's own type softmax (read after layer 1) in the layers 2, 3 and the wiring layer; tokens are NOT dropped inside the network. Output pruning: a node is kept when p_none < 0.5 (named threshold, on the output only).
- **Self-attention layers (3, 4 heads, FFN 128):** the logit of head h between token i (query) and j (key) = q_i . k_j / sqrt(16) + bias_h(r_ij) + log w_j, bias = MLP(6 -> 32 -> H) of the relative geometry r_ij = (dx, dy in the frame of i's heading, scaled by 20 m with a signed log, cos and sin of the heading difference, the distance); pre-norm residual blocks.
- **The wiring = the attention weights of a last layer with two heads:** class c in {short (chord <= 8 m), long (chord > 8 m)}: z^c_ij = q^c_i . k^c_j / sqrt(d) + bias^c(r_ij) + log w_j + b^c_j (b = the destination evidence of class c read from x_j), restricted to the allowed gate of `jtok.pair_geometry` (the same gate as E357 - E362), plus ONE learned none slot per class (a key whose logit is q^c_i . k^c_none + bias); the per-source successor distribution of class c = softmax over {none} and the allowed keys. There is NO separate gate sigmoid: the none slot is the gate (the E359 type head failed as a separate output). Two handle scales per pair from a small MLP of (x_i, x_j, r_ij), 0.5 x L1 on the matched long GT links (the connector geometry as E357).
- **Node types (softmax over 7):** none / lane point / fork (flag split) / merge / entry (start, win_in) / exit (end, stop, exit, win_out) / connector handle (a node incident to a junction link of the GT), read from x after the last layer; the label of a token = the type of its matched GT node, none when unmatched; cross-entropy weight 0.5. The type softmax serves existence (p_none) and the report; the wiring does not read it.
- **Loss (matching inside the loss is allowed, D55; the one-to-one assignment is static and stored with the cache):** type CE + for each class c and each source token i the exact multi-positive likelihood with the none slot, -log( sum_{j in G(i)} p^c(j|i) ) when G(i) is non-empty, -log p^c(none|i) when it is empty (also for unmatched tokens: they should wire to nothing), G(i) = the tokens matched to the GT successors of the GT node matched to i in class c (a GT link with an unmatched end is out of gate and counted); + 0.5 x scale L1. Normalisation as E359 (per frame mean over the sources of the class, then the mean over frames). One training stage, 12000 steps, bs 8, lr 1e-3 (5 % warm-up, cosine), AdamW, roll-back guard and 500-step checkpoint with resume as `trainer.fit`.
- **Decode of record (named, on the output only):** per source and class the argmax over {none} + keys; a link is kept when the argmax is a key (not none) and both ends are kept nodes (p_none < 0.5); ties to the lower token index. The delivered graph is the E357 section-free read-out (`qgraph_eval.readout`, every node section 0, chains cut at forks / merges), scored by the standard scorer (`qgraph_eval.score_frames`) on the 873 VAL frames. No rule step: no close-node step, no snap, no attachment, no distance rule. Secondary decodes (every key with s >= 0.3) are reported, never the verdict.
- **Cost counted in every result:** parameters, GMACs per frame (the head from the cache tokens; B's pyramid and node head are the same as E324 s's and are reported once), ms (idle GPU, batch 1, 24-frame protocol).
- **Not claimed:** anything about S2 / S3, TEST (never touched), that B's frozen nodes are the best token source (a trained-through B is a later card), that train-frame tokens are like VAL tokens (B was trained on TRAIN: its train-frame nodes are cleaner than its VAL nodes: the head trains on cleaner tokens than it sees; a node-drop augmentation is NOT used in S1 and the degraded read-out (17 % of the tokens removed, as E359) is reported as the robustness number).
- **Referee:** none yet.

## 2. Detail plan
### 2a. The predicted-node cache and its loader (the lane chat builds it to this spec; messaged to local_f87fc6cf 23:15)
One `.npz` per frame under `runs/e365_cache/b<S>_K<K>_<GT signature>_<version>/<split>/<token>.npz` (derived data, not in git; the split lists are those of the E357 cache: train 8414, val 873 rows of data/splits.json['val'] in that order; the version is bumped by hand when the table or matching code changes; a file is written whole and renamed), B = the frozen head `runs/e273_p_s<S>/model.pt` (S = 0, 1; NodeHead output as the delivered graph of B reads it, WITHOUT the E275 hard close-node step and WITHOUT the Matrix-NMS layer: raw existence logit), K = 384 (fixed after the coverage report below, the loader takes K from the cache name).
Fields per frame (float32 unless stated; K rows, descending by e; ties by the cell index):
- `cell` (K, 2) int16 (row, col of the 2 m cell), `pos` (K, 2) metres = cell centre + offset (B's `pos`), `dirv` (K, 2) unit (normalised `dir_raw`), `e` (K,) existence logit, `flags` (K, 8) logits in the order of `qtargets.FLAGS`, `s`, `uout`, `uin` (K,) logits, `tok` (K, 64) float16 = the node token of B after the refinement (`NodeHead` `tok` at the cell).
- the GT table of the frame on the 2.5 m lattice exactly as the E357 cache stores it (`lane_tok_data.frame_table`: pos, dirv, cell, flags, piece, sstart, src, dst, long, scale, conn; copy it from `runs/e357_cache/l2.5_9ad1d4ce30_t1/`, do not recompute) so that labels agree with E359 - E362.
- the static matching: `m` (K,) int32 = the GT node (row of the table) assigned to token k, or -1; `md` (K,) float32 the distance. Assignment = one-to-one greedy by increasing distance over the pairs with distance <= 1.5 m and heading cosine >= 0.5, each GT node gets at most one token, each token at most one GT node, ties to the lower token index; computed on position and direction only (B is frozen: the matching is static).
- stats (a JSON next to the cache, per split): GT nodes per frame (mean), the share of GT nodes that have a token inside 1.5 m for K = 256 / 384 / 512 (the coverage report that fixes K), the share of GT nodes matched, the share of tokens matched, mean number of tokens with e > 0, the share of GT links with both ends matched (the links the head can ever deliver: the out-of-gate share).
Loader `lane_ptok_data.py` (`loader("train" | "val", seed=S, bs=8, workers=4)`, collate): batch dict with `tok` (B, K, 64) float32, `pos`, `dirv` (B, K, 2), `e`, `s`, `uout`, `uin` (B, K), `flags` (B, K, 8), `m` (B, K), `ytype` (B, K) int64 in 0..6 (the type of the matched GT node by the mapping of section 1, 0 = none), `y` (B, K, K) uint8 = 1 where token i -> token j is a GT link whose both ends are matched, `ylong` (B, K, K) bool (chord > 8 m), `yscale` (B, K, K, 2) float32 (the fitted handle scales of the long links, NaN elsewhere), `gt_out` (B,) the count of GT links with an unmatched end, `token`, `row`, and the per-frame float64 `table` (pos / dirv of the tokens for the read-out). A `--drop` option (a seeded random 17 % of the tokens removed from the batch, the same seed rule as E357 `keep_nodes`) for the degraded read-out. A self-test and a test with mutants (a wrong match, a swapped link direction, a leak of a GT field into the input) go with it (`test_lane_ptok.py`).
