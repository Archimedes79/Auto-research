**What it does** [checked]: a layer h_{k,i} = sum_d sum_j g_{d,k}(y_i - x_j; theta) f_{d,j}, with the kernel g an MLP of the continuous relative offset z = y_i - x_j; the output locations y_i need not coincide with the input points x_j (so a dense BEV grid can be queried from sparse points). Locality by a window: K nearest neighbours or a fixed radius. Kernel depth / width not given. Efficiency: the weight tensor is factorised into a linear F x O matrix and an N x |S| x O MLP evaluation; batch-norm merged into the MLP FC layer gives about 3x speed-up; 8 layers, 32-d, 50 neighbours: 33 ms forward + 28 ms KD-tree, 61 ms end to end (GPU not read here).

**Results that matter** [checked]: Stanford indoor mIoU 58.27 vs PointNet 41.09; driving lidar segmentation pACC / mIoU: PCCN 94.56 / 46.35 at 9.34 MB vs 3D-FCN 74.66 MB 94.31 / 49.28, combined 95.45 / 58.06; lidar flow EPE 8.161 cm to 7.810 cm. In-house lidar data, not reproducible.

**Transferable technique**: this is the mathematical form of the radar density: for a detection j and a BEV cell i, w_ij = g(z_ij; theta) with z_ij built from the cell position expressed in the detection's sensor frame. In PCCN z is a Cartesian offset in R^D; our version would use polar offsets (r_i - r_j, phi_i - phi_j) from the sensor pose (a change of coordinates for the same MLP, so that range and azimuth noise are axis-aligned), plus conditioning on r_j, point features and dt as extra inputs (the paper conditions the kernel only on the offset). The "sum over detections of MLP output per cell" is also the cheap evaluation scheme (only cells within a gate around each detection are evaluated). Spec test for a port: a single detection and a g that is a fixed Gaussian in (dr, dphi) must reproduce the analytic Gaussian grid.

**Cost and fit**: small MLP per (cell, detection) pair; with nuScenes radar (up to ~100 detections per sensor, 5 sensors, gate of a few metres) a few 10^4 evaluations per frame, trivial.

**Doubts**: the paper has no radar; evaluation on proprietary lidar; the kernel is not given a physical prior, so the learned density can ignore the measurement physics unless the inputs are chosen in sensor coordinates.
