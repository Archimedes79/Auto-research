# The research system (design of 2026-10-25)

## Two systems, one interface

| | the product: the perception system | the improver: the research system around it |
|---|---|---|
| what it does | camera + radar features -> sparse lane graph -> time -> map / route -> planner input, fast | finds ideas, turns them into tested code, runs experiments, measures, decides, keeps the record |
| code | `training/` (data, models, losses, pipeline, train, trainer) | `tools/` (experiment, literature, catalogue, maintenance, viz), `evaluation/` (metrics, protocol, `evaluate.py`), `reports/build/` |
| its own records | checkpoints and caches in `runs/`, the WSL caches | `literature/`, `experiment_execution/` (plan, ledger, run records), `experiments/`, `reports/weekly/` |
| quality gate | spec tests, numpy reference, fast == reference graphs | selftests of launcher / ledger / decide, metric-response test, stored numbers reproduced |

The two meet at four interfaces only: a **config** (design name + `--set` settings), a **registry name** (`models/registry.json`: checkpoint + config + standard assembly settings), a **run id** (ledger row) and a **metric card** (`card.json`). The improver never edits the product during a run; it changes the product through reviewed commits of the core bundle, and every run names the commit it ran.

One pipeline from the paper to the decision. Every stage reads the artifacts of the stage before it and writes its own, so stages can be automated (or given to separate chats) without talking to each other. Code is checked before an experiment may use it.

```
 A literature (hierarchical)        B code funnel                 C experiments                D evaluation               E decision + report
 ---------------------------        -------------                 -------------                ------------               -------------------
 L0 source page / repo              K id + port card       --->   PLAN.md: tree of cards  ---> evaluate.py <name>   --->  decide.py -> ledger
 L1 paper note   (papers/)   --->   block (code) + spec test       run.py: ledger row,          (one entry point,          card.json -> experiment folder
 L2 deep / code extraction           in the core bundle            commit, snapshot, deps       registry name, cache,      report tables generated
 L3 axis summary (OVERVIEW)          config name in registry       train.py (trainer.fit,       metric card, bootstrap)    from card.json + ledger
 L4 backlog of hypotheses   ------------------------------------>  resume) -> checkpoint
```

## The artifacts and their ids

| artifact | id | lives in | made by | read by |
|---|---|---|---|---|
| paper note | paper id (`A01`, arXiv id) | `literature/papers/`, row in `papers.csv` | literature agent (L1) | L2, L3 |
| deep / code extraction | paper id | `literature/deep/`, `literature/code/` (with a port card: interface, licence, what to port) | literature agent (L2) | B |
| axis summary, gaps | axis `A1`-`A9` | `literature/OVERVIEW.md` (generated tables + short text) | `catalogue.py` + agent (L3) | L4 |
| technique | `K<n>` | `literature/register.md` | L2 / L4 | B, C |
| hypothesis backlog | `K` + one line | `literature/OVERVIEW.md` "open" section, ranked by expected gain / cost | L4 | PLAN |
| block (code) | module + function name | `training/` (models, losses, pipeline) | code agent (B) | configs |
| spec test of a block | test name | `evaluation/tests/` or the block's selftest | code agent (B) | the gate below |
| named model | registry name (`champion`, `fast`, `recall`) | `models/registry.json` (checkpoint, config, assembly settings) | C | D |
| experiment card | `E<id>` | `experiments/E<id>_<slug>/card.md`, node in `PLAN.md` | planner (C) | run, decide |
| run | `E<id>.<arm>` | `experiment_execution/runs/<id>/` (run.json with commit, log), ledger row | `run.py` | D, E |
| metric card | run id + split | `card.json` next to the checkpoint (`runs/`) | `evaluate.py` | decide, report |
| decision | in the ledger row | `LEDGER.csv` | `decide.py` | PLAN, HANDOVER |

## The funnel rules (what makes it systematic)

1. **Literature is read top-down and written bottom-up.** An agent that plans reads L3 / L4 only; it opens L1 / L2 only for the K ids it wants to use. Summaries (L3) are regenerated from the notes, never edited as free text (`catalogue.py`).
2. **No technique without a K id; no K id in an experiment without a block.** A block is code in `training/` with a spec test that passes: shapes, the gradient reaches every parameter, and either a numpy reference or the paper's own toy numbers. Port cards in `literature/code/` say what to take from a repository.
3. **An experiment is a config, not a script.** It names a design / blocks and settings (`--design D7 --set ...`, registry names), not a new training file. A new script is allowed only for a new kind of training, and then it uses `trainer.fit`.
4. **Every run goes through `run.py`.** It writes the ledger row, the commit of the code (git holds code only), the prediction and the rule, and waits for its dependencies (`--after`).
5. **Every number comes from `evaluate.py`.** It looks up a registry name, uses the standard settings of that name, caches the raw network outputs, and writes `card.json`. The metric library has response tests. The protocol (`evaluation/PROTOCOL.md`) fixes splits, seeds, the noise band and the TEST rule.
6. **Every decision is `decide.py`** against the rule written before the run. Report tables are generated from `card.json` and the ledger.

## The core bundle (well-checked code)

| part | where | checks that guard it |
|---|---|---|
| data | `training/data/` (`p16_data`, `sd_lib`, splits) | ground-truth alignment test, frame counts 8,414 / 873 / 833 |
| blocks / models | `training/models/` | spec tests (`evaluation/tests/test_p16_spec.py`), numpy reference `p16_ref.py` |
| losses | `training/losses/` | zero at the ground truth, gradient reaches every head |
| trainer | `training/trainer.py` | crash + resume = uninterrupted run (`trainer_selftest.py`) |
| inference | `training/pipeline/` | fast path == reference graphs (`p16_fast_check.py`, `p18_asm_check.py`) |
| evaluation | `evaluation/` (`evaluate.py`, `sparse_lanes/`, `lane_grid/`) | metric-response test, stored numbers reproduced |
| launcher, ledger, decisions | `tools/experiment/` | `selftest.py` |

`tools/maintenance/run_all_tests.sh` runs all of them. A change of the core bundle is reviewed by a fresh agent on its diff before other experiments use it.

## Code, state, records, data: what lives where

| kind | what | where | in git |
|---|---|---|---|
| **code** | the core bundle, launchers, report builders, configs (`models/registry.json`), the rules and READMEs that describe code | `training/`, `evaluation/` (code only), `tools/`, `reports/build/`, `CLAUDE.md`, `README.md` | **yes** (only this) |
| **state** | what is going on now: at most three files | `HANDOVER.md` (<= 3 KB), `experiment_execution/PLAN.md`, `experiment_execution/LEDGER.csv` | no |
| **records** | what happened, append-only | `experiment_execution/runs/`, `experiments/`, `literature/`, `reports/weekly/`, `experiment_execution/history/` | no (backed up as a folder) |
| **data** | big or regenerable | `data/`, `runs/` (checkpoints, card.json), the WSL caches, `temp/`, `_to_delete/` | never |
