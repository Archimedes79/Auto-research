**What it does**: camera BEV by LSS with an EfficientNet backbone, then a multi-scale U-Net-like prediction module made of 2D convolutions only (time and channels merged into one axis, five scales 200 x 200 down to 7 x 7) that predicts all future frames in parallel. Two branches without shared weights: segmentation (top-k cross-entropy, k = 25 %) and centripetal backward flow: for each foreground pixel at t a vector to the centre of its instance at t-1 (smooth L1). Instances are linked by warping the previous instance IDs along the flow, which is 14 ms (2 s horizon) against 82 ms for FIERY's association.

**Results that matter** (nuScenes, IoU / VPQ): short range 62.5 / 55.5, long range 39.3 / 33.8, FIERY reported 59.4 / 50.2 and 36.7 / 29.9 (the page lists the pairs in a table whose orientation was garbled by the summariser; the repo README gives 39.3 IoU / 33.8 VPQ for the long and 62.5 / 55.5 for the short checkpoint). Prediction module 39.3 M parameters against 8.4 M for FIERY; FLOPs 92.6 G against 206.8 G (2 s). Heads: segmentation + flow alone is as good as or better than adding centre and offset heads. Warping association with backward flow beats Hungarian matching with forward flow (VPQ 39.2 vs 38.3 short, 33.5 vs 31.9 long at 2 s). There is no no-flow ablation.

**Transferable technique**: flow defined as backward and centripetal is a target that is well defined on a pixel at time t pointing to the t-1 position, so a pull (grid_sample) with it needs no hole filling: matches our pull-based 'decoding at any dt' (plan 8.2). The supervised flow loss is a plain smooth L1 on foreground cells.

**Cost and fit**: the lift is LSS six-camera; the prediction module is too big for a 3060 at 0.5 m 120 x 104 only if kept at this width.

**Doubts**: it predicts future states from past, not the flow between two observed frames; flow only on foreground instances, so static and background motion is out of scope.
