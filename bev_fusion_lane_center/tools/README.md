# tools - the few reusable helpers

Python tools run through `tools/env/_py14.sh <script>` (conda env `gcar`; the script is found by name; `PYTHONPATH` covers all code folders). Code of the system is in `training/`, metrics in `evaluation/`, report builders in `reports/build/` - not here.

| tool | use |
|---|---|
| `env/_py14.sh`, `_pyr.sh`, `bflc_env.sh` | the launchers: run a script in `gcar` (`_pyr.sh` retries on CUDA 'unknown error'); `bflc_env.sh` sets the module search path (sourced by both). `export_env.sh` -> `environment_gcar.txt` / `.yml` (package list of 2026-10-24) |
| `env/setup/` | one-time scripts that rebuild the GaussianCaR environment and its rasteriser: `setup_gcar_env.sh`, `gcar_nvcc.sh`, `gcar_build_rast.sh`, `gcar_patch_rast.sh`. Not run day to day. The other setup scripts (WSL, DNS, CRN env, downloads) are in `../_to_delete/cleanup_2026-10-24b/tools/env/`. |
| (moved) | the general tools - launcher `run.py` (ledger row, commit + tag per run, `--after`, TEST guard), `ledger.py`, `schedule.py`, `decide.py`, `check_numbers.py`, `check_structure.py`, `clean_temp.py`, `selftest.py` - are in `../../autoresearch/tools/` (README there); they read this problem's paths from `../project.json` |
| `viz/render.py` | result images of lane graphs: `render_frame`, `render_compare` (several methods, same frame), `render_grid`, `frame_array`, `montage`; built on `viz_graph.py` (arrows, split triangles, merge diamonds, raster background). `viz/selftest.py` |
| `viz/qgraph_view.py` | pictures and videos of the E273 lane head on real VAL frames: the six cameras with the GT lane graph projected, 1 m centre pixels, 2 m road / intersection and 0.5 m dividers / boundary (GT grey underlay, correct dark, false positives light red, misses light blue), nodes by type with the Hermite links and the false / missed tints, ids (GT pieces in clean colours, delivered nodes in the expected colour of their map assignment so that an unsure assignment blends). `qgraph_view.py frame <token> --out DIR [--pred oracle|degraded]`, `scene <VAL scene> --out DIR --video`, `--selftest`; `pred_fn=qpredict.make_pred_fn(run)` for a trained run; CPU is enough |
| `prototype/` | the ready-to-use prototype (D28): `lane_prototype.py <registry name> [--scenes ...] [--frames N] [--video] [--fresh]` writes the delivered lane graph planner-ready (one JSON per scene, ego frame x forward / y left), summary.json / .md with the numbers of `evaluate.py` on those frames and the stored ms per frame; `make_results_video.py` (results video, moved from `temp/loop21/`); `test_lane_prototype.py`. README there (JSON fields) |
| `video/make_video.py` | result videos: `graphs_to_video`, `frames_to_video`, `side_by_side`; mp4 (OpenCV) or gif by file extension; no ffmpeg needed |
| `literature/catalogue.py` | literature catalogue: `render` (404 notes + register + `literature/papers.csv` -> `CATALOGUE.md`, the one paper reference with the code table at its end, and the generated blocks of `OVERVIEW.md`), `check` (ids, links, extraction files, verdict and reason codes, port cards), `all`, `selftest`. Plain python 3 (`wsl python3 tools/literature/catalogue.py all`), no GPU. Described in `../literature/OVERVIEW.md` section 5 |
| `literature/code_digest.py` | factual skeleton of a read-only repository checkout: licence files, version pins, file inventory with heavy-dependency flags (mmcv, spconv, custom CUDA), outline of classes / functions with line ranges and first docstring line, keyword index (loss, assign, merge, decode, metric ...); parses with `ast`, never imports or executes, reproduces no bodies, reads the commit from `.git/HEAD` without running git. `python3 tools/literature/code_digest.py <checkout> --paths <sub-paths> --out literature/code/<repo>.skeleton.md`; `selftest`. Process: `../literature/code/README.md` |
| `jarm.py` | one arm of a token-head experiment in one command (train with resume -> dumps -> TRAIN sweep -> `jtoken_eval.py choose-cell` -> scores at the pinned cell and D115, `--ref-run` when the tokens are the same), every step through `run.py` with the hypothesis / prediction / rule of the experiment card; `jarm.py table <ref> <runs..>` = pooled VAL numbers and differences to the first run; decides nothing. Replaces the per-experiment bash chains (E376 - E383) | `jarm.py selftest`; the run ids come from the card (`jarm.py ids <E-id> <arm> [--ref R]` lists them for the card's `run_ids`; an unlisted training id is refused), `--curve [BAND]` runs the data-order + loss-curve check of a speed-change arm after the training, one jarm per arm (lock) and a launch waits while another supervisor's run.py of the same id is alive (what the old keep_alive.sh did; it is in git history) |
| `simplify_stat.py` | what a simplification removed, from git: files and lines of named path groups at a BEFORE ref (an archive tag) and an AFTER ref -> a json the reporter reads (`values`), so the report's simplification table fills itself; counts what git tracks, not the working tree. Selftest: `simplify_stat.py selftest` |
| `draw_route_head.py` | E389 report: draws the architecture of the route-association head `grid/jroute.RouteHead` as an svg FROM the module (parameter counts and the route cap are read from the code; a renamed block fails the drawing; large type, few words) and `--table` prints the parameter table; `--selftest` checks the totals, the three data paths, the font size and that no colour is red. Needs torch (gcar python): `python tools/draw_route_head.py <out.svg>` |
| `route_frames_fig.py` | E389 / E389b report: the example frames of the route-association head in the style of the reports of 2026-11-18, chosen by a WRITTEN rule (typical fork frame = median gain, largest gain, largest loss, largest drop under the wrong map; candidates = frames with >= 30 covered nodes): front camera + table on top, the BEV panels side by side (head without the map z | with the map m | for the wrong-map case m with the wrong route); the SD route as its numbered PIECES (the map error applied piece by piece, same as the loader: `error_pieces`, checked against the loader's route), the delivered graph of the champion (nodes and E375-decode links) coloured by Mirko's rule (flagged and on the route = the colour of its route piece, flagged off the route = amber cross, missed = pale hollow, else grey; no red). Writes `e389_frame_<case>.png` and `e389_frames.json`. `--selftest` checks the rule, the colour rule on a hand-made frame with two pieces and the pieces of the error route. Run through `_py14.sh` (it changes the directory: absolute `--out`, with Git Bash `MSYS_NO_PATHCONV=1`; needs torch and WSL for the camera): `bash tools/env/_py14.sh route_frames_fig.py --seed 0 --out <abs dir>` |
| `maintenance/` | `run_all_tests.sh` (every self-test of the product, the evaluation and the general tools; about 25 minutes, parts use the GPU), `run_gates.sh` (the fast gates, adapted from the BEV system's: the tests that need no GPU and no stored network output, a few minutes; run before every commit of code), `CLEANUP_LIST.md` (open cleanup items with sizes and recommendations); `make_structure.py` writes `../temp/STRUCTURE.md` (folder tree with sizes, on demand) and regenerates `../models/REGISTRY_ALL.md`; `reproducible.py` (D11) answers: would things work if the working folder were deleted? (git policy, imports of untracked modules, rebuild manifest `../data/rebuild.json`, clone of HEAD + cheap checks; `selftest` included) |
