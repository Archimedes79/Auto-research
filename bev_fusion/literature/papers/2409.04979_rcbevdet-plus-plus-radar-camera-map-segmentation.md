**What it does**: Radar input: multi-sweep points with RCS and Doppler speed (RCS treated as a rough object-size prior). RadarBEVNet (from RCBEVDet): point branch + transformer branch (distance-modulated self-attention: a learnable Gaussian-like penalty on pairwise distance) linked by injection / extraction cross-attention, then an RCS-aware BEV encoder: each point's feature is scattered to its BEV pixel and neighbours within a radius proportional to (cx^2 + cy^2) * v_RCS, with a Gaussian-like weight (variance 1/3 of that); so RCS sets the footprint size (position uncertainty by proxy). RCBEVDet++ replaces the dense camera BEV by sparse camera object queries sampled against the radar BEV (deformable cross-attention for alignment, linear fusion layer) on top of SparseBEV. Segmentation: CVT-style decoder per task, sigmoid focal loss, classes vehicle / drivable / lane, loss weights 400 / 80 / 200.

**Results that matter** (nuScenes val): RadarBEVNet ablation (NDS / mAP): PointPillar baseline 54.3 / 42.6; + RCS-aware encoder 55.7 / 44.5; + transformer 55.8 / 44.8; + injection / extraction 56.4 / 45.6. Radar-only: 22.0 NDS / 10.8 mAP against 20.3 / 7.3 for PointPillars. Segmentation: 62.8 mIoU with ResNet-101 (vehicle 55.3, drivable 82.7, lane 50.5). Detection with ViT-L: 72.73 NDS / 67.34 mAP. RCBEVDet (v1 page, 21 to 28 FPS RTX 3090) was read in the first version; no speed is reported for ++.

**Transferable technique**: the RCS-scaled scatter footprint is the cheapest way to make the radar footprint depend on a measured quantity; it gave +1.4 NDS / +1.9 mAP (the largest single radar-encoder gain in the table; the transformer branch only +0.1 on its own). Lane IoU 50.5 is in the range of other camera-radar BEV methods.

**Cost and fit**: the scatter is a tiny op; the dual-stream backbone is optional (+0.7 NDS together). The sparse-query fusion part is detection-specific.

**Doubts**: no radar vs camera-only controlled segmentation comparison, no latency, segmentation resolution not given; Doppler is an input but never ablated; RCTrans (2412.12799) argues against using RCS.
