**What it does**: One memory map H_i = [warp(H_{i-1}, P_{i,i-1}); B_i] * V, a grid-sample warp of the previous memory by the ego transform, concatenated with the current BEV feature and passed through a conv V. Unrolled this is a sum over past frames weighted by V_cur * V_mem^(i-j), so older frames are down-weighted automatically. A temporal embedding E_i = e(dt_i) (two convs) is fused recurrently in the same way and feeds the velocity head, so missed frames and uneven gaps are visible to the net. No dedicated moving-object mechanism: motion is learned from the memory plus the time embedding.

**Results that matter** (ResNet-50, nuScenes val): history 0 / 1 / 4 / 8 / 16 / all gives mAP 0.323 / 0.340 / 0.359 / 0.375 / 0.379 / 0.379, NDS 0.382 / 0.450 / 0.471 / 0.483 / 0.489 / 0.492, mAVE 0.936 / 0.473 / 0.382 / 0.360 / 0.343 / 0.331. At 50 % missed frames velocity error grows by 54.7 %, the time embedding cuts that by 25.1 %. Headline: 55.4 mAP / 62.9 NDS (detection), 48.6 vehicle mIoU (segmentation), 54.8 AMOTA. Memory and latency: one stored feature at inference, claimed lower overhead than SOLOFusion as history grows (shown in a figure only, no numbers on the page).

**Transferable technique**: the recurrent update with a learned decay conv V and a delta-t embedding. This is a conv-gated EMA of the warped past; a direct candidate for our static hold / learned gate memory in a front-camera + radar BEV system, one extra BEV map of state and a few convs per frame.

**Cost and fit**: constant memory (one BEV map), cost independent of the history length. Needs ego pose and time stamps. No trainable depth required for the memory itself.

**Doubts**: moving objects are blurred into the memory unless the net learns to suppress them (no gate by motion); no latency numbers in the text; no lane or map evaluation.
