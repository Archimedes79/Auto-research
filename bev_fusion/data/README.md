# data - derived data of bev_fusion (not in git)

Everything here is derived from the raw nuScenes data (`D:\Auto-research\NuScenes`, WSL views `~/data/nuscenes_full`,
`~/data/nuscenes`; `../../data/NuScenes/README.md`) and the pre-trained checkpoint (`../models/README.md`) by tracked
scripts, so it can be deleted and rebuilt (rule D11 of the lane project: a new derived artifact gets its row here in the same
step). `.npy` / `.npz` / `.pt` files are ignored by git globally. Folders: `cache/` (this file's table), `../runs/` (training runs).

| artifact | made by | inputs | status |

**Rebuild the caches for a split** (`../splits/README.md`; from the bev_fusion folder in the gcar environment, `<root>` = `~/data/nuscenes_full`, every step resumable: what exists is kept, so only the missing scenes are built):
1. the scenes: `python training/splits.py names <split>` (one per line); the GT store of them: `python training/gt_scenes.py <composed config> check|build` (`trainsuite start --prepare` runs the build as a run of its own)
2. features, radar: `python training/feature_cache.py build|radar <root> v1.0-trainval data/cache/cam_feats|radar --split train|val` (whole official split), BEVFusion shards `python training/cache_bevfusion_features.py build --src data/cache/cam_feats`, front images `python training/lane_branch.py build-cache <composed config>`
3. GT cache: `python training/gt_cache_build.py <root> v1.0-trainval data/cache/gt --split train|val --scenes $(python training/splits.py names <split>)` (the names of the other part are skipped); `xl` also needs the feature shards of parts 7 - 10 (`cache/all/`, `../splits/xl.json`)
4. check: `python training/gt_scenes.py <composed config> check` says whether the GtGenerator store holds every keyframe of the split; `python training/startable.py <composed config>` that the cache folders and weights it names exist (not that they are complete)
