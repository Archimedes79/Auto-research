# Checkpoint slimming and scratch cleanup of 2026-11-01

Why: C: was 100 % full (4.1 GB free), bev_fusion/temp held 18 GB, bev_fusion/runs 11 GB of resume checkpoints. Mirko: "slim the checkpoints to the necessary ones, also delete unneeded data or cached information or outdated information". This record is the list of what was done (written by hand from the logs of the session, not generated by a tool).

## Checkpoints: 34 runs, 26.1 GB -> 6.7 GB (19.4 GB freed)
Rule: a run is slimmed only if it has the done flag and its last checkpoint is the configured end step (unfinished, stopped or old runs keep their resume checkpoints; none was found). Slim form = what the pinned code snapshot of an OLD run still loads: the Adam moments (2 x the parameters) are emptied, param_groups and RNG stay, slim = True. Weights, EMA, step and cfg were compared tensor by tensor with the original before the swap. Then bev_adapter.load_run (the evaluation's own load path, under the run's pinned code in runs/<name>/code) had to load the new file, else the full file was put back (no failure occurred). Only then the full copy and the older checkpoints were deleted. A slim checkpoint evaluates and warm-starts (init_from), it cannot resume training.

DEVIATION from the rules that the workspace CLAUDE.md gained later the same day (hard rule 5 "checkpoints are never deleted"; the best-three rule "every other checkpoint may be slimmed or archived, never deleted"): this cleanup was done on Mirko's chat instruction ("slim the checkpoints to the necessary ones", "delete unneeded data or cached information or outdated information") BEFORE the rule text reached the session, and it DELETED instead of archiving: the older resume checkpoint of each of the 31 two-checkpoint runs (about 13 GB, the step before the end, e.g. ckpt_00002500), the full-size final checkpoints (replaced by the slim form), the outdated caches and two GT signatures. The final weights of every run are kept; nothing was archived to D: first. bev_fusion has no keep3.json yet, so no designated best-three checkpoint was affected, but a network that is designated later will have a slim (not complete) checkpoint if it comes from a run listed here or from any new run made before the decision below.

DECISION (Mirko, later the same day, asked which of "complete default" and "slim default" he wants): "keep the full data to be able to resume later". `TrainConfig.slim_at_end` is OFF by default now: a finished run keeps its `keep` complete checkpoints (Adam moments and RNG included), slimming is an opt-in. The 34 runs of the table below stay slim: their Adam moments are gone and only a retraining brings them back (the full copies of t1_r0, t1_r3_combined, t1_r4_soa on D: remain). The paused run t10_dual_long_s0 was never touched: its ckpt_00005000 and ckpt_00005030 are complete (425 MB each), so it resumes exactly. Runs whose checkpoints live in D:/bev_fusion_ckpts (t2_*, t3_*) were slimmed in place. The D: copies of t1_r0, t1_r3_combined, t1_r4_soa (full size) were left as the backup of the slimmed C: files.
