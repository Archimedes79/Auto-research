**What it does**: Two streams. Long-term: lift image features to a BEV with per-pixel depth, align the BEV maps of the previous T steps with ego motion, concatenate them into a BEV cost volume at 1/16 resolution (16 frames in the main model). Short-term: a plane-sweep stereo volume against the previous frame at 1/4 resolution refines the per-pixel depth; "Gaussian-Spaced Top-k" keeps only k=7 depth hypotheses per pixel instead of all 112. The static-scene assumption behind the stereo matching is not discussed for moving objects on the page I read; only ego warp is applied.

**Results that matter** (nuScenes val): previous frames 0 / 1 / 16 / 41 give NDS 0.347 / 0.423 / 0.474 / 0.467 and mAVE 1.148 / 0.456 / 0.307 / 0.314, so it saturates at 16 frames. Module table: baseline 17.6 FPS 3.3 GB; short-term only 12.2 FPS 3.3 GB; long-term only 15.9 FPS 3.6 GB (NDS 0.479); both 11.4 FPS 3.6 GB (NDS 0.495). Sampling 7 depth hypotheses instead of 112 saves 8.5 GB to 3.3 GB and 2.9 FPS to 11.4 FPS.

**Transferable technique**: history stored at a lower resolution than the current frame (1/16 vs 1/4) buys most of the long-history gain for +0.3 GB; the cost grows with the number of stored frames (parallel fusion), which is why VideoBEV (2303.05970) goes recurrent. For us: a coarse long memory plus fine current frame for static content.

**Cost and fit**: Needs depth/stereo from a trainable image backbone, which our frozen cached features do not offer; only the BEV-history part ports. Memory grows linearly with the window.

**Doubts**: No moving-object handling beyond ego warp; the gain at 41 frames is below 16 frames; no map/lane evaluation.
