**What it does** [checked]: two balancing steps. Loss-scale balancing: train on sum_t log(l_t + eps), eps = 1e-8 (parameter free); Proposition 3.1 says log x = min_s e^s x - s - 1, so the log loss is exactly IMTL-L (a learned scale per task, the same form as Kendall's exp(-s) L + s). Gradient-magnitude balancing: per task g_t = grad_theta log(l_t + eps) at the shared parameters, exponential moving average g^_t <- beta g^_t + (1 - beta) g_t, then the update g~ = alpha * sum_t g^_t / (||g^_t|| + eps) with alpha = max_t ||g^_t||: every task gradient gets unit norm and the common length of the largest one.

**Results that matter** [checked, Delta_p = average relative change against single-task models, higher is better, mean +- std]: NYUv2 (3 tasks): equal weights -1.78 +- 0.45, GradNorm -1.24, PCGrad -1.57, CAGrad -0.27, Nash-MTL -1.01, DB-MTL +1.15 +- 0.16; Cityscapes: EW -2.05, PCGrad -2.36, CAGrad -0.87, Nash-MTL -1.11, DB-MTL +0.20 +- 0.40; QM9 (11 tasks, MAE based): EW -146.3, CAGrad -87.25, Nash-MTL -73.92, DB-MTL -58.10 (no multi-task method beats single-task there); Office-31 +1.05, Office-Home +0.17. The metric differs from Delta_m % of the FAMO / CAGrad tables, so the numbers cannot be put in one table with them.

**Transferable technique**: three facts for the loss design. (1) A log transform of each group loss makes the gradient scale-invariant (the gradient of log L is grad L / L) and is the optimum of Kendall's weighting, which is why Kendall, IMTL-L, FAMO and DB-MTL are one family; with our clamp s_g in [-3, 1] the equivalent weight 1 / L is limited to e^-1 .. e^3. (2) Shifting by a known lower bound or dividing by the initial loss (LDC-MTL does log(l / l_0) on QM9, 2502.08585) keeps the log defined and starts all groups at zero. (3) Gradient normalisation to a common length is the same idea as GradNorm's target, with a max-norm instead of a rate.

**Cost and fit** [checked]: the loss half is free. The gradient half needs the K gradients at the shared parameters every step; the paper says it is slower than loss-balancing methods and similar to gradient-balancing ones ("a common disadvantage"); no seconds in the text read. Works for K = 4; a feature-level version (gradient w.r.t. the shared BEV feature) is not in the paper.

**Doubts**: the single-task reference is the denominator of Delta_p, and the gains against equal weights are 1-3 points with 3 dense tasks; no detection or BEV task; the code is not released by the authors on the pages read (only through LibMTL).
