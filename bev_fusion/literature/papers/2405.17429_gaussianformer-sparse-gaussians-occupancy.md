# 2405.17429 GaussianFormer: sparse 3D semantic Gaussians instead of voxels

| | |

**What it does**: The scene is a set of N sparse Gaussians (mean, scale, rotation, semantic logits). Learnable queries pass through blocks of 3D sparse-conv self-encoding, image cross-attention and residual refinement; a CUDA Gaussian-to-voxel splatting aggregates only neighbouring Gaussians into the occupancy grid. Loss: cross-entropy + Lovasz-softmax on every block (deep supervision).

**Results that matter** (nuScenes, SurroundOcc labels, val): SC IoU 29.83 / SSC mIoU 19.10 with 144,000 Gaussians against SurroundOcc 31.49 / 20.30, TPVFormer 30.86 / 17.10. Latency on one RTX 4090, batch 1: 372 ms, 6.2 GB-class memory (printed "6229 M") against 302-502 ms for the voxel baselines; fewer Gaussians trade directly: 25,600 -> 227 ms / mIoU 16.00, 51,200 -> 259 ms / 16.41, 91,200 -> 293 ms / 18.31. Appendix: a photometric (image reconstruction) loss with 51,200 Gaussians gave mIoU 16.24 against 16.41 without, so no help.

**Transferable technique**: sparse Gaussian primitives as an alternative to a dense volume; negative evidence that a pixel-photometric rendering loss does not improve semantic occupancy.

**Cost and fit**: not faster than voxel methods at equal accuracy (latency 227-372 ms), only lighter in memory; unsuited as a 3060 fast path. Our own foundation already uses Gaussian splatting for BEV (GaussianCaR, SN01).

**Doubts**: memory unit printed as "M"; latency measured on a 4090 against baselines on A100 (copied from OctreeOcc), so not matched.
