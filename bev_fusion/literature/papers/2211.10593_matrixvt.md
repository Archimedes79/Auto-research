**What it does**: BEV feature = sparse Feature Transporting Matrix (FTM, shape (H_B W_B) x (N_c H_I W_I N_d)) times the lifted (feature x depth) tensor. The FTM depends only on intrinsics and extrinsics, so it is generated once; it can reproduce LSS pillar pooling exactly or encode other rules such as Gaussian sampling. Two reductions: Prime Extraction (a per-column "prime depth" attention weights the categorical depth, column-wise max pooling compresses the image height, FTM shrinks by H_I) and Ring and Ray decomposition (a Ring matrix N_d x H_B W_B for distance bins and a Ray matrix W_I x H_B W_B for direction, combined by Hadamard mask and a sum over the width axis; static parameters W_I N_d H_B W_B -> (W_I + N_d) H_B W_B, 30 to 50 times smaller).

**Along-ray distribution**: categorical, 112 uniform bins over 2 to 58 m (BEVDepth DepthNet), one per pixel then compressed per column. No explicit uncertainty beyond the categorical; no ground prior.

**Precompute versus runtime**: Ring and Ray matrices built once at startup (appendix); runtime is two dense matmuls and convolutions, no custom CUDA op (the point of the paper: deployable on any chip).

**Results that matter** (nuScenes val): map segmentation 200x200 BEV: drivable 83.5, lane 44.8, vehicle 46.2 (Table 2, 6 cameras). Detection R50 256x704: 33.6 mAP / 41.5 NDS. Memory: view-transform peak 734M -> 316M with Prime Extraction (ResNet-50); 2 to 15 times less than LS-BEVDepth; "2 to 8 times faster". Latency is plotted for CPU and CUDA only, no GPU model named and no absolute ms in the text. (The text gives 49.7 mAP for a setting where the table shows 39.6: internal inconsistency.)

**Flat-ground error**: none (3D depth bins), so no slope bias, but the quantisation is 0.5 m near vs uniform 0.5 m bins: 112 bins over 56 m.

**Transferable technique**: for one fixed front camera, W_I x N_d columns x BEV matrix is tiny; the ring/ray split could be rebuilt as a ring (range) x ray (azimuth) polar-to-Cartesian matrix applied to per-column depth weights; Gaussian sampling is allowed inside the FTM, which is how a Gaussian lift can run as a matmul.

**Doubts**: absolute ms missing; detection numbers weak vs BEVDepth; the 'conflicting' numbers; map IoU for 6 cameras only.
