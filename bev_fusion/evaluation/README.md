# evaluation - evaluating the BEV system (qualitative + quantitative suite, metrics)

Every number and every picture of a training run comes from here. The machinery is the problem-independent **evaluation suite** `../../autoresearch/evalsuite/` (use: its `README.md`, bigger projects: its `EXTENSIONS.md`); this folder is the BEV *adapter* (the three boxes Source / Subject / Task for a run `runs/<name>`) and the metric library. Run from the `bev_fusion` folder with the `gcar` environment: `wsl ~/miniconda3/envs/gcar/bin/python evaluation/bev_suite.py RUN ...`.

## The one command

`python evaluation/evaluate.py RUN [options]` (from the `bev_fusion` folder, RUN = `runs/<name>`; without an option it prints this list) is the front door. It computes nothing: it runs the `bev_suite.py` commands the options stand for, each as its own process, so every output is where `bev_suite.py` puts it. What it adds is `RUN/eval/door.json`: every call with its options and the commands run (exit code, seconds), calls appended.

| option | the `bev_suite.py` command(s) |
|---|---|
| `--quant [--n 1000] [--curves] [--fusion] [--velocity]` | `eval --n N` (the three flags are bev_suite's global options): `eval/metrics.json`, `card.json`, `table.txt` |
| `--qual N` or `--qual scene-0061/12,scene-0003/5` | `qual random N --seed S`, or the named frames drawn in one process (the model is loaded once) |
| `--videos N` or `--videos scene-0003,scene-0012` | `qual videos N --seed S`, or `qual videos --scenes ...` |
| `--time` | `timing --n 30` + `time` (ms per module, ms per frame; idle GPU only: `timing` runs first and refuses a busy one) |
| `--all` | the evaluation chain of the t16 bring-up: `timing --n 30`, the numbers (`--curves --fusion --velocity eval --n 1000 --prior 500 --images 8`), `generalisation` (train against val), `modules --frames 4`, `qual videos 3 --seed 1`, showcase videos (`--out RUN/eval/showcase qual videos 6 --view overview --seed 21`), and the report page last (`report --no-pictures` with the train and val tables of generalisation, so that it shows the videos; the chain made it inside generalisation, before them). Only the numbers are fatal; a failed step is listed and the chain goes on; generalisation gets a second try (its half-made store moves to `suite/failed_stores/`, nothing is deleted) |

Also `--seed S` (default 1) and bev_suite's `--device cuda|cpu --workers N --split val|train --ckpt-dir DIR --out DIR` (the TEST split is not offered). `--quant` alone is a plain `eval`: `../tests/test_evaluate_door.py --real` shows that its metrics.json, card and table equal those of `bev_suite.py RUN eval --n N` on `runs/t16_full_s0`. `--out DIR` is the suite folder; `timing_modules.json` goes into it too. Refused before any step (exit 2, with the reason): `--n` below 1, a named scene or frame that is not in the val list (`bev_suite.py RUN list` is read for it, about a minute), no checkpoint, and outputs that exist already and would be rewritten in place: `eval/card.json` (`--quant`, `--all`), `eval/timing_modules.json` and `eval/latency.json` (`--time`; `--all`: the timing file). A delivered run is not overwritten by accident; `--replace` does it on purpose, or evaluate a copy of the run folder. Exit code: 0 when every step passed, else the exit code of the first step that failed (1 if it gave none); a failed step of `--all` other than the numbers does not stop the chain, but the call ends non-zero, with one summary line of what failed. The commands below are what the door calls; they stay usable by hand.

## Use

**Quick start (the decision path, four commands):** `bev_suite.py RUN --curves --fusion eval --n 1000 --time` (every number of a run incl. PR / ROC and the fusion-area scoring), `bev_suite.py RUN generalisation` (train against val), `bev_suite.py compare RUN_A RUN_B --curves --fusion` (paired bootstrap, refused on another GT), `bev_suite.py RUN report --vs CONTROL` (the one page). Before you trust a number: `bev_response.py --selftest` and `bev_gtcheck.py --selftest` (the evaluation against known damage, CPU, no model).

```
python evaluation/bev_suite.py runs/t1_r4_soa list                                   # the val scenes ("videos") and their frames
python evaluation/bev_suite.py runs/t1_r4_soa qual frame scene-0061/12 --view overview debug     # one frame; overview = camera with the GT, GT, prediction, three error maps
python evaluation/bev_suite.py runs/t1_r4_soa qual debug scene-0061/12              # + the stages of the chain (taps), statistics, plausibility flags, raw taps .npz
python evaluation/bev_suite.py runs/t1_r4_soa qual random 6 --seed 1                # 6 frames: a random video first, then a random frame in it
python evaluation/bev_suite.py runs/t1_r4_soa qual videos 2 --seed 1                # 2 random scenes as H.264 videos (dashboard view, memory carried along)
python evaluation/bev_suite.py runs/t1_r4_soa report --vs runs/t8_ctl_s0                # ONE PAGE for a person without code: runs/t1_r4_soa/report/index.html (state, prediction / rule, curves, numbers next to the control, 6 random frames + a video, review fields; made first when missing)
python evaluation/bev_suite.py runs/t1_r4_soa generalisation [--n 600]                  # train-vs-val: the same evaluation on both splits (stored val numbers reused), the gap table on the report page; TEST is never touched
python evaluation/bev_suite.py runs/t1_r4_soa --curves eval --n 1000                    # also PR / ROC / calibration per layer and velocity regression (evaluation/bev_curves.py: ap, roc_auc, f1_max, ece, brier; epe, rmse, r2 of the velocity field)
python evaluation/bev_suite.py runs/t1_r4_soa --fusion eval --n 1000                    # also the fusion-area scoring `detf` / `detfp` and the coverage split `cov` of the complete GT set (D37 / D38, evaluation/bev_fusion_area.py); the old `det` numbers keep their label
python evaluation/bev_suite.py runs/t1_r4_soa --velocity eval --n 1000                  # also the velocity field per cell set (static, per class, moving) and at the GT box centres: field / object head / zero (evaluation/bev_velocity.py, metric `vel`); `compare --velocity`
python evaluation/bev_fusion_area.py --coverage [--n 300]                              # no model: how the complete GT set splits into care / partial / don't care and camera / camera + radar / radar only / neither (needs `bev_annotation_pts.py build` once for the radar classes)
python evaluation/bev_gtcheck.py [--n 24] [--versions SIG_A SIG_B] [--list] [--selftest]  # GT against GT on real cached GT, no model: the GT as the prediction reaches every ceiling, degraded copies fall as they must, the GT frames agree with their poses, two GT versions compared layer by layer
python evaluation/bev_suite.py runs/t1_r4_soa quant run --n-scenes 20               # numbers over many videos, stored per frame (state carry)
python evaluation/bev_suite.py runs/t1_r4_soa quant outliers eval_n1000             # where the numbers come from: scenes / frames / flags, each with the command that draws it
python evaluation/bev_suite.py runs/t1_r4_soa quant report eval_n1000               # html report with the worst frames drawn
python evaluation/bev_suite.py runs/t1_r4_soa eval --n 1000 [--warm] [--prior 500] [--images 8] [--time]     # the evaluation of a run (see below)
python evaluation/bev_suite.py runs/t1_r4_soa time                                  # ms per frame, idle GPU only -> eval/latency.json
python evaluation/bev_errors.py runs/t1_r4_soa --n 1000 [--check] [--class vehicle]    # every false positive and missed box of an evaluated run as a table (kind, frame, token, position, the command that redraws it) -> eval/errors_n1000.csv; no GPU, nothing re-run
python evaluation/bev_suite.py runs/t16_small_s0 modules [--frames 3]               # module probe on CPU (bev_modules.py): output statistics, dead channels, the response when the camera / all radar detections / only the Doppler are removed, the velocity field on static and moving cells, a warm second frame, one PNG per frame -> eval/modules/
python evaluation/bev_suite.py runs/t16_small_s0 timing [--n 30]                    # ms per module at batch 1 + forward / backward of a training micro-batch (bev_timing.py), idle GPU only (refused otherwise) -> eval/timing_modules.json
python evaluation/bev_suite.py runs/t1_r4_soa memory --clips 600                    # does the carried memory help? warm vs cold -> eval/memory.json + txt
python evaluation/bev_suite.py compare runs/a runs/b [--tag _warm] [--n 1000] [--force]   # paired scene bootstrap b - a; refused when the GT signatures differ (manifest / metrics.json, runs/<name>/gt.json; warned when unknown); legacy records scene_records<tag>_n<N>.pkl only on the same frames
python evaluation/bev_suite.py front runs/ref runs/b [LABEL=FILE.pkl ...] --n 1000 [--x-max 50] [--out FILE.md]   # front-sector AP / mAP2 table, difference to the first system with the paired bootstrap
```
Global options: `--device cuda|cpu --workers N --split val|train --ckpt-dir DIR --control shuffle_radar|zero_radar|shuffle_cam|zero_cam --out DIR --state carry|reset|warmup`. Outputs default to `RUN/eval/suite/{qualitative,quant}`. Views of a frame: `overview` (the simple one: grey right, RED false, BLUE missed, cream not evaluated), `outputs` (detailed), `stages` = `debug` (the chain stage by stage), `dashboard` (video frame), `taps` (every tap generically).

`eval` replaces the former `evaluate_run.py`: it runs the suite over the val frames (`--n N` spread over all scenes, cold = every frame from an empty memory; `--warm` the memory carried along whole scenes) and writes the same files as before - `eval/metrics<tag>.json` (flat, same key names; since 2026-10-31 also `"better"`: the direction of every number but the counts, from each metric's `direction()` in `bev_task.py`), `card<tag>.json` (the same finite numbers with their directions as a metric card of the autoresearch contract, with split, frames, the run's code commit and seed and the GT signature as protocol: the file an `experiment.json` arm names for `autoresearch/tools/decide.py`), `table<tag>.txt`, `scene_records<tag>.pkl` (for the study tools), `latency.json` - plus the per-frame store `eval/suite/quant/eval<tag>_n<N>/` that everything else (outliers, report, trace, compare) reads. Its numbers equal those of `evaluate_run.py` on the same frames (golden test below). Since review pass 2 (2026-10-31):
- **Copies per n:** metrics, card and table are also written as `eval/by_n/<name><tag>_n<N>.<ext>`, so an early check with another `--n` does not replace the 1000-frame numbers.
- **Provenance (2026-11-01):** the card also carries a `provenance` block (`autoresearch/tools/provenance.py`, design `autoresearch/reproducibility.md`): GT version and signature, the hash of the evaluator's source files (`evaluation/` and `autoresearch/evalsuite/`) with the files that differ from HEAD, the frame hash, the hash of the raw-data manifest (`manifest.json` in the NuScenes data folder), the model (run, checkpoint hash and step, config hash, training GT), the settings (n, warm, device, store) and the environment of the interpreter. The evaluator and checkpoint hashes are taken at the START of the evaluation and again at the end; a difference is marked (`changed_during_run`, evaluator `dirty` unknown) and `decide.py` does not use the card for a verdict. A collector that fails prints `WARNING: provenance not collected` and leaves `{"error": ...}`; the evaluation is not lost. Commit the evaluator files before an evaluation that feeds a verdict: every file that differs from HEAD marks the card dirty.
- **GT refusal:** a stored run of another recorded GT is refused. One made before the signature was recorded is resumed only with `--force-resume` and labelled `mixed:unrecorded+<current>`; the prior baseline's store is checked too.
- **Legacy pickle:** `scene_records` is written only when the process saw every stored frame.
- **Camera controls:** `--control shuffle_cam|zero_cam` replace every camera input (`bev_adapter.perturb_camera`: both feature caches, the image, the t7 lane image).

## Prototype outputs
`python evaluation/bev_prototype.py RUN [--scenes scene-0003 5 ...] [--frames N] [--out DIR] [--video] [--device cuda|cpu]` (scenes by val name or index in `bev_suite.py RUN list`, default the first; first N frames of each, default all; out default `RUN/prototype/`). Each scene runs from an empty memory at its first frame, the memory carried frame to frame (as `eval --warm`). Files:
- `objects.json`: `run`, `checkpoint`, `frame` and `forecast` (the conventions below, as text), `scenes: {scene: [frame, ...]}`; a frame: `index` (in the scene), `token` (nuScenes sample token), `timestamp_us`, `box_source` (`det` = the object head's decoded boxes, `detr` = refined, for models with a refiner), `objects` (dt 0), `forecast_0.5s` (+0.5 s, null when not decoded). A box: `class` (vehicle, two_wheeler, pedestrian), `score` (0-1; boxes from score 0.05, at most 100 per frame and dt), `centre` [x, y] m, `size` [length, width] m and `yaw` rad (boxes; null for circles), `radius` m (pedestrians are circles; null for boxes), `velocity` [vx, vy] m/s. Frame: the ego (vehicle) frame of the frame's own time, x forward, y left, yaw counter-clockwise from x; velocity = the object's world velocity in the ego axes (the autogt definition). The +0.5 s boxes are at the next keyframe (t + 0.40 ... 0.60 s) in the ego frame of that time, decoded as in the evaluation with that keyframe's true gap and ego motion from the GT (a deployed system has to supply its own).
- `maps_<scene>.npz`: one array per layer `<layer>` of shape (frames, nx, ny), float32 probabilities (sigmoid of the semantic head) at dt 0; `layers` (names), `index`, `token` (per frame), `grid` (a JSON string: `res`, `x_min`, `x_max`, `y_min`, `y_max`, `nx`, `ny`, `axes`): `map[f, ix, iy]` is the cell centred at x = x_min + (ix + 0.5) res forward, y = y_min + (iy + 0.5) res left (as drawn: x up, +y left).
- `summary.json` / `summary.md`: run, checkpoint, step, device, code snapshot, scenes with frames and the mean `predict` ms of this pass (wall time on this device and load, not the latency protocol); `gt_signature` now / training (`gt.json`) / stored card and whether they agree; `headline`: the `evaluation/board.py` COLUMNS read from `eval/card.json` (its split, frames, date, GT, and the memory mode from `eval/metrics.json`) - copied, never recomputed; `ms_per_frame` from `eval/latency.json` or "not measured".
- `qualitative/videos/<scene>_dashboard.mp4` (with `--video`): the suite's `qual videos` dashboard over the same frames (it runs the scene a second time, memory carried).

## How the numbers are traced
Every metric stores additive counts per frame (maps: the SegMeter counts; boxes: the true-positive flag of every detection and the GT counts), so any set of frames reduces to the same numbers the direct meters give: all frames, one scene, all but one scene (`quant outliers`: the scenes that drag a headline number most), a bootstrap resample (`compare`). A frame's own scores (drivable IoU, vehicle IoU, recall at 2 m, false alarms, loss) are in its picture's header and in `frames.csv`; `quant trace RUN scene/index` redraws it exactly as the run saw it.
