# 2301.12511 Fast-BEV - depth-free lookup-table lift for on-vehicle chips

| verdict | use (the speed floor for any lift: a static LUT, no depth) |

**What it does**: "Fast-Ray" projects every image feature along its camera ray into a dense voxel grid with a UNIFORM depth distribution (no depth network, no attention). The pixel-to-voxel index map is precomputed once as a look-up table because camera parameters are fixed, so the lift at run time is a gather. All cameras write into one shared voxel ("multi-view to one-voxel"); in overlaps the first view wins. Voxel grids 200x200x4 / 200x200x6, then the height axis is folded into channels and a 2D BEV encoder follows. Depth uncertainty is represented as "none / uniform along the ray" (maximum uncertainty); ambiguity is left to the BEV encoder.

**Results that matter**: nuScenes val detection, R50 256x704: mAP 0.334 / NDS 0.473. On an RTX 2080 Ti, R50 4-frame, TensorRT FP32: 19.0 ms (52.6 FPS) vs BEVDepth 41.3 FPS and BEVDet4D 30.2 FPS. View transform alone: 0.006 ms on CUDA (7.0 ms on CPU). INT8: Orin M0 44.8 FPS, T4 M0 97.1 FPS, Xavier M0 19.7 FPS, TI TDA4VM (8 TOPS) 13.9 FPS.

**Transferable technique**: for a single fixed front camera the LUT is a constant gather: precompute for each BEV cell (0.5 m) the image pixel(s) it sees at a set of heights, so lift cost is ~0. It is the zero-uncertainty-model baseline against which a Gaussian lift must show its gain. Combining: use the LUT for the geometry and add a per-pixel depth mean/variance only as a weight.

**Cost and fit**: smallest cost of all candidates; trivially fits a 3060. Six-camera, detection (not lane) paper; the metrics are boxes, no map IoU.

**Fixed-geometry record**: precompute = LUT of voxel index per pixel (built once at startup, camera rig fixed); runtime = a gather, 0.006 ms on CUDA at 256x704 (7.0 ms on CPU; M2BEV 1.2 ms CUDA); along-ray distribution = uniform (each ray fills all its voxels with the same feature); flat-ground error: none by construction (3D voxels), but the uniform fill puts a ground feature also at every height and depth along the ray.

**Doubts**: uniform depth puts features on the whole ray (smear), which hurts thin structures at range; no map/lane results; "first view wins" is a hack only needed for multi-camera.
