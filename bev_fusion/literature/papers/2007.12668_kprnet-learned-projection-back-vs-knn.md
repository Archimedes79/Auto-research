**What it does** [checked]: A 2D CNN on a range image (scan unfolded in capture order, 64 rows) gives per-pixel features; the features are projected back to the 3D points and a KPConv layer over the point neighbourhood replaces the non-learned KNN / CRF voting that RangeNet++-type methods use to label points. Radius and neighbour count are not given.

**Results that matter** [checked, SemanticKITTI val mIoU]: KNN post-processing at 145 x 2049 input 57.7; KNN at 289 x 4097 input 61.7; KPConv layer replacing KNN at 289 x 4097 input 64.1 (+2.4); test 63.1 (SalsaNext 59.5). Latency not reported; training on 8 V100.

**Transferable technique**: a learned continuous-offset kernel (the parametric-continuous-convolution / KPConv family) for the last hop from a regular grid to irregular positions beats a fixed vote by 2.4 mIoU. Our direction is grid to grid (polar image to Cartesian cell), where the offset between the cell centre and the polar sample is known and small: a bilinear read plus a second small conv in the Cartesian domain is the grid-to-grid version, with the sub-cell offset as extra input channels if needed. The result argues against a nearest-neighbour read-back, not for KPConv at our scale.

**Cost and fit**: KPConv needs neighbour search (CUDA or torch_cluster); not worth it for a regular 0.5 m grid.

**Doubts**: lidar semantic labels, not radar; no timing; one run.
