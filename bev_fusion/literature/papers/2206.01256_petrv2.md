**What it does**: Extends PETR with temporal 3D position embeddings aligned across frames and a feature-guided position encoder. Multi-task is done with task-specific queries initialised in different spaces (detection queries as 3D anchor points, segmentation queries as patches on a BEV grid, lane queries as anchor lanes), all reading the same image tokens. Tasks: 3D detection, BEV segmentation, 3D lane detection (OpenLane).

**Results that matter**: the page claims state of the art on all three tasks and gives no numbers.

**Transferable technique**: one shared token memory with separate query sets per task instead of one dense BEV for everyone. Not directly usable on a dense 0.5 m grid, but shows that lane and box tasks can share a trunk without a shared head.

**Cost and fit**: multi-camera, transformer decoder, heavy; our front-camera + radar system with dense heads fits BEVerse or CVT better.

**Doubts**: no task-interference numbers here; query design is tied to a perspective-token encoder.
