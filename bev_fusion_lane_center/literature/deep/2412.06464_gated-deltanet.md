## 1. Problem and claim
Language modelling with a fixed-size recurrent state instead of a growing key-value cache. Linear attention keeps a matrix state that only accumulates; Mamba2 adds a scalar forget gate (fast erasing, but it also erases what should be kept); DeltaNet adds the delta rule (a write replaces the value stored under the same key, targeted but with no way to wipe the state). The paper combines both in one update (the gated delta rule), gives a chunkwise parallel training algorithm for it, and builds a Llama-like model (Gated DeltaNet) plus two hybrids with sliding-window attention.

The claim that matters: gate and delta rule are complementary (the abstract says gating erases fast, the delta rule edits targeted), and the combination beats Mamba2 and DeltaNet on language modelling, in-context recall and long context at 1.3B parameters / 100B tokens. The gain over Mamba2 on the average zero-shot accuracy is small (section 3). Nothing is shown outside text.

## 2. Method as built

### 2.1 Notation and update rules (digest; equation numbers: only Eq. 10 was returned with a number)
State per head S_t in R^{d_v x d_k}; q_t, k_t in R^{d_k}; v_t in R^{d_v}; output o_t = S_t q_t. (The order d_v x d_k is the paper's; the FLA reference stores [K, V], i.e. the transpose.)

| name | recurrence | note |
|---|---|---|
| linear attention | S_t = S_{t-1} + v_t k_t^T | only accumulates |
| Mamba2 | S_t = alpha_t S_{t-1} + v_t k_t^T, alpha_t in (0,1) scalar per head and token | data-dependent decay; cumulative decay gamma_j = prod alpha_i, chunk mask Gamma_ij = gamma_i / gamma_j |
| DeltaNet | S_t = S_{t-1} (I - beta_t k_t k_t^T) + beta_t v_t k_t^T, beta_t in (0,1) (the paper remarks (0,2) is possible) | S_{t-1} k_t is the value currently stored under k_t; the step moves it towards v_t by beta_t |
| **gated delta rule (Eq. 10)** | **S_t = S_{t-1} ( alpha_t (I - beta_t k_t k_t^T) ) + beta_t v_t k_t^T** | alpha_t -> 0 wipes the state, alpha_t -> 1 gives the plain delta rule |

Equivalent step form (my derivation, checked against the FLA reference order in 2.4): S <- alpha S; r = S k; S <- S + beta (v - r) k^T; o = S q. Expanding gives alpha S - alpha beta S k k^T + beta v k^T, which is Eq. 10. The paper reads alpha as an adaptive weight decay on the one-step SGD update of the regression loss ||S k - v||^2 (Table 1 lists the objectives of LA, Mamba2, Longhorn, DeltaNet and Gated DeltaNet; no benchmark numbers in it).

Consequence (my derivation): with d_k = 1 and k = 1 the rule is h <- alpha (1 - beta) h + beta v, a convex-style gated update. Our current learned gate is this degenerate case; the delta rule adds something only when the key has several dimensions and different contents are addressed by different keys.

### 2.2 Block: projections, normalisation, output (digest; Section 3.4, Figure 1)
- q, k: linear projection -> short causal convolution -> SiLU -> **L2 normalisation** (for stability); v: linear -> short convolution -> SiLU (no L2).
- alpha and beta: linear projection only (per head, scalar per token). The paper says alpha follows the Mamba2 parameterisation and omits it; from memory (not seen on the page) Mamba2/FLA use alpha = exp(-exp(A_log) * softplus(x W + dt_bias)) and beta = sigmoid(x W). Treat as unverified.
- Output: normalisation and an output gate (linear + SiLU) before the output projection. Macro structure: Llama-style, token mixer then SwiGLU MLP; the mixer replaces self-attention.
- Hybrids: H1 = Gated DeltaNet layers interleaved with sliding-window attention (window 2K); H2 = Mamba2, Gated DeltaNet, sliding-window attention stacked in that order.
- State size per head: d_v x d_k values. Head count, d_k, d_v of the 1.3B model: not stated in the text read. Ablation B.2 (400M) picks head dimension 128 as the trade-off (64: PPL 28.31, 256: PPL 27.13, accuracy 47.38; digest). With d_k = d_v = 128 that would be 16,384 values per head (my arithmetic, assumption d_v = d_k).

### 2.3 Chunkwise parallel form (training; digest, Section 3.3 and Appendix A)
- The sequence is cut into chunks of length C; state is carried across chunks; inside a chunk everything is matrix multiplication (tensor-core friendly). Chunk size: not stated.
- WY representation / UT transform for the delta part: T = [I + strictLower(diag(beta) K K^T)]^{-1} diag(beta) in R^{C x C}; W = T K; U = T V; chunk update S_next = S + (U - W S^T)^T K; output O = Q S^T + (Q K^T masked causal) (U - W S^T).
- Gated version: the same with decay-aware quantities: U~ = [I + strictLower(diag(beta) (Gamma (.) K K^T))]^{-1} diag(beta) V; Q and W decayed to the chunk start, K and the old state decayed to the chunk end; S_next = decayed S + (U~ - W_back S^T)^T K_forward; the causal mask carries the ratios gamma_i / gamma_j. Appendix A proves the closed form by induction.
- The only inverse is a lower-triangular C x C system per chunk and head; the paper says the gating adds marginal overhead to DeltaNet's algorithm.

### 2.4 Single-step recurrent form (what we need at batch 1, one frame at a time; digest of the FLA reference)
The FLA `naive_recurrent_gated_delta_rule` is plain PyTorch with a Python loop over time. Inputs: q, k [B, T, H, K]; v [B, T, H, V]; beta, g [B, T, H]; optional initial state [B, H, K, V]; output o [B, T, H, V] and final state [B, H, K, V]. It casts to float32, does **not** normalise q or k (the block does that before), scales q by 1/sqrt(K), and takes g as a log-space decay (state times exp(g)). Per step: decay the state; read it with the key and subtract from the value; scale by beta; add the rank-1 update; read the output with the scaled query from the updated state. For one frame the recurrent form needs no chunking at all: it is a handful of batched small matrix-vector products. The chunk form is only a speed device for long training sequences.

### 2.5 Losses, training recipe (digest, Section 4)
Language-model cross-entropy only (nothing else stated). 1.3B parameters (400M for some tables), 100B tokens of FineWeb-Edu, Llama-2 tokenizer (32,000), AdamW, peak lr 4e-4, weight decay 0.1, gradient clipping 1.0, cosine schedule with 1B warm-up tokens, batch 0.5M tokens, sequence length 4K. Reference training script in the repository: a 0.4B hybrid on 15B tokens, about 4 hours on 4 nodes (README, digest).

### 2.6 Inference
Constant memory per token via the recurrent form; evaluation is zero-shot (lm-evaluation-harness), retrieval tasks use cloze-style prompts truncated to 2K (digest, Appendix B.1).

### 2.7 Custom kernel versus plain PyTorch
- Training path: chunked algorithm, written as fused GPU kernels in the FLA library (Triton, per the FLA page: `fla/ops/gated_delta_rule`, `chunk_gdn`; licence MIT). The NVlabs repository carries its own copy plus the FLA version (`lit_gpt/gated_delta_rule_ops/fla_version/`). The paper text itself names no kernel language and no chunk size; its only repository citation is FLA (appendix).
- Reference/test path: `naive_recurrent_gated_delta_rule` is plain PyTorch, no kernel.
- For us: nothing needs a kernel (state tiny, T of a few frames, batch 1). Not seen: whether FLA also ships a fused-recurrent decode kernel (memory: yes; not needed).

## 5. Transfer to our pipeline

### 5.1 Where our memory is now (checked, local files)
- Vertex level: `training/models/p16_time.py` `prior_from_prev`: the previous frame's own nodes (top P = 64 by validity, no gradient through the previous frame), warped by the ego motion, become extra seed candidates (validity x 0.9) and their validity is fused with the current one by log-odds where a current node coincides with a previous node (a = 0.9, b = 1.0); pose noise and a share of frames without a prior in training. One-step memory, state = position, heading, validity, hidden features.
- Raster level: `training/train/p17_gate.py` class `Stabilizer`: memory y_{t-1} (42 channels = 39 features + 3 map channels) warped by `grid_sample`, per-pixel gates from a small conv net initialised to the training-free hold (decay 0.95); y_t = g m + (1 - g) x_t; 3-frame unroll, memory detached before the first frame. That is exactly a gated update with scalar d_k = 1.

### 5.3 Cost (my arithmetic, assumed sizes; not measured)
Per head and vertex, one recurrent step costs 3 d_k d_v multiply-adds (read S k, rank-1 write, read S q). With H = 4, d_k = d_v = 16, input dimension D = 64: state 4 x 16 x 16 = 1,024 floats per vertex (4 KB fp32); for 300 vertices 307,200 floats, about 1.2 MB. Recurrence 3,072 MAC per vertex; q, k, v projections 3 x 64 x 16 x 4 = 12,288 MAC; alpha and beta heads 2 x 64 x 4 = 512 MAC; about 15.9 k MAC per vertex, 4.8 MMAC for 300 vertices. For comparison, one 3 x 3 convolution with 64 -> 64 channels on the 200 x 200 raster is about 1.5 GMAC (from the RB01 file's arithmetic). So FLOPs are negligible; the cost is kernel launches, roughly 15 to 25 small PyTorch ops per step in eager mode. Estimate for the 25 ms budget: under about 1 ms, to be measured on the idle GPU at batch 1 (the card sets the limit; guess, not a result). Fixed-size padding of the vertex set (for example N = 64 or 128 slots with a mask) avoids shape changes between frames.

### 5.4 Design sketch: per-vertex gated delta memory with ego-motion warping, birth and death
- **State:** S_i in R^{H x d_v x d_k} per slot i of a padded vertex set, plus a mask. Positions and headings of the slots are warped each step by the existing ego-motion code (p16 `warp_prior`). The state itself needs no warp if q, k, v are built from ego-invariant inputs: features in the local lane frame (lateral offset, heading relative to the vertex tangent), not in the ego frame. Anything ego-frame (absolute heading, position) is rotated before it enters k / v, as the direction channels in `warp_mem` are rotated by `rel`.
- **Association (no matching):** current vertex j reads the warped states of previous vertices with a Gaussian distance kernel w_ij (position and heading), S_bar_j = sum_i w_ij S_i / (sum_i w_ij + eps); the mass m_j = sum_i w_ij is the birth signal (small m -> the state is effectively zero, a fresh vertex). This is a soft pooling, not an argmax; it replaces the hard coincidence test and is the one new piece to build and verify. A simpler first version keeps the existing coincidence rule and index-aligns the states.
- **Key, value, query:** from the current-frame feature f_j of vertex j (the builder's hidden vector, validity logit, local-frame direction): k_j = L2norm(W_k f_j), q_j = L2norm(W_q f_j), v_j = W_v f_j with the target slots of v defined by what must be remembered (validity logit, lane-geometry feature, lane-type feature). The key's job is to address content types inside one vertex's state (validity vs. geometry vs. type), not to address positions: position is carried by the vertex itself. Different keys are what the plain gate lacks; if all keys end up equal the rule collapses to the gate (check by measuring the effective rank of the keys).
- **Gates:** alpha_j from f_j and from scalar mismatch (current validity against memory read-out S k) and from "frame has failed" cues (the failure series: cameras off, dark); beta_j from f_j. Initialise alpha near the existing hold decay 0.95 and beta so that the first epoch reproduces the current fusion (the same trick as the Stabilizer zero-initialised output).
- **Read-out:** o_j = S_bar_j q_j (then merge into the validity logit and the feature of vertex j through a zero-initialised residual).
- **Birth and death:** birth = new slot with S = 0 (state starts empty; the first write has beta weight only); death = mask off when validity falls below a threshold or the vertex leaves the range; its state is dropped (no gradient needed through a deleted slot). Slots are reused by the top-P selection already in `prior_from_prev`.
- **Training:** unroll 3-5 frames, memory detached before the first one (as p17_gate), clean 30 % / failure 70 % mix as in E134, loss = the builder loss of the last frame. The chunked form is never needed.
- **Prediction (number, to go on a card):** Q on the failure half: change within -0.005 to +0.010 against the current learned gate; probability that the gain exceeds the band 0.010 with the paired bootstrap interval excluding 0: about 0.15 (my judgement). Clean half: tie. Probability that a GRU of the same state size matches the gated delta variant inside the band: about 0.8.
- **Decision rule:** arms, equal data / steps / seeds (2): C0 current fusion (log-odds + learned raster gate); C1 same slot machinery with a scalar gated update (d_k = 1, the degenerate delta rule); C2 GRUCell with hidden size H x d_v on the same inputs and association; V gated delta, d_k in {8, 16}. `decide.py --variant V --control C2 --band 0.010 --cost-variant ms --cost-control ms` on the VAL failure series (clean and failure halves reported separately, seen and held-out failure types separately, as E209). KEEP only if V beats both C1 and C2 by more than the band with the interval excluding 0 and adds < 1 ms; TIE -> the cheaper (C1 or C2); INCONCLUSIVE -> add a seed. The main interpretation test is V against C1: it isolates the delta-rule key.

### 5.5 Minimal spec test of a port (layer 0; toy case with a known answer)
Port card interface (re-implement, no repository code): `gated_delta_step(S [N,H,dv,dk], k [N,H,dk] (L2-normalised), v [N,H,dv], q [N,H,dk], alpha [N,H], beta [N,H]) -> (o [N,H,dv], S_new [N,H,dv,dk])`: S <- alpha S; r = S k; S <- S + beta (v - r) k^T; o = S q. Tests (all numpy / torch reference, tolerance 1e-6):
1. Equal to the closed form of Eq. 10, S alpha (I - beta k k^T) + beta v k^T, on random inputs.
2. Orthonormal keys (d_k = 2, k1 = e1, k2 = e2), alpha = 1, beta = 1: write v1 at k1, v2 at k2; reading q = e1 returns v1 and q = e2 returns v2; a third write v3 at e1 makes the read of e1 return v3 while e2 still returns v2 (targeted overwrite; the gate-only update would add v3 to v1 instead).
3. alpha = 0: S_new = beta v k^T, whatever the old state (erasure); alpha = 1, beta = 0: state unchanged (hold).
4. d_k = 1, k = 1: h_new = alpha (1 - beta) h + beta v (reduces to the gate form).
5. Padded slots (mask 0): output and state unchanged / zero; permutation of the slots permutes the outputs (set invariance).
6. Batch-1 timing on the idle GPU with N = 300, H = 4, d_k = d_v = 16 (the ms goes on the card). The paper's own numbers (language models at 1.3B) cannot be reproduced and are no test.
Licence of what we write: ours; the paper's equations are used as facts.

### 5.6 What transfers
- The update rule and the two-gate idea (forget gate alpha separate from write strength beta): a clean parametrisation of "hold, replace, erase".
- Prediction-error writing: the memory is corrected by v - S k, not by the raw value; useful if vertex content contradicts the memory (a lane that moved).
- L2-normalised keys and queries for stability; initialisation near hold.
- The online-learning reading (alpha as weight decay): a way to explain the gate in the report.

### 5.7 What does not transfer, and honesty about a GRU
- Long-context benefits (retrieval over 8K tokens, S-NIAH, length extrapolation, LongBench) are irrelevant: our horizon is 2 Hz and a few frames, and each vertex gets one write per frame.
- Matrix state pays off when many different key-value pairs are stored in one state and read back later. A vertex state sees at most T (a few) writes; its matrix has rank at most T. A GRU or LSTM cell of the same number of state floats can represent the same information and is the better-understood tool at this scale; the paper has no recurrent-network control, so nothing in it argues against a small GRU. My judgement: a GRU is likely as good (probability about 0.8), and the plain scalar gate we already have (E134 `Stabilizer`, E199) is a degenerate delta rule, so the question is only whether multi-dimensional keys help.
- Short convolution over tokens, token embeddings, sliding-window attention hybrids, SwiGLU stack, the 4K training length, chunked WY kernels: no counterpart.
- The paper's tasks have exact copy structure; ours has noisy geometry with ego-motion error (about 0.15 m and 0.5 degrees pose noise in training); nothing in the paper handles a state that must be moved in space.
- A raster (per-cell) delta memory is not sensible: 200 x 200 cells x d_k x d_v floats (for 8 x 8: 2.56 M floats) with no content to address; the conv-gate `Stabilizer` already does the per-cell job.
- Value is therefore mostly as a documented, parameter-light alternative with erase-on-contradiction; low priority next to the open gaps (coverage at range, connectivity).

## 8. Novelty and relevance for our problem
The novelty is the combination of two known recurrences (scalar decay from Mamba2, delta-rule overwrite from DeltaNet) in one update, with a chunkwise training algorithm that keeps the cost close to DeltaNet; the evidence is language modelling and needle retrieval, with a small margin over Mamba2 in the main table. For us the idea is a clean "hold, replace, erase" memory per vertex with prediction-error writing, of which our learned gate is the scalar special case. The long-context and kernel parts do not apply (2 Hz, few frames, batch 1), and a small GRU of equal state size is a serious competitor, so this belongs behind a cheap equal-budget test (section 5.4), not ahead of the coverage and connectivity gaps.
