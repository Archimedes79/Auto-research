# Literature check (extra 15): differentiable, iterative point generation for online maps / lane graphs, and hand-over to a planner

Date of check: 2026-10-23. Method: web search and web fetch only (arXiv abstract/HTML pages, proceedings pages, and, where the paper text did not settle a question, the official GitHub source read through the fetch tool; nothing downloaded or installed). Entries I could not verify on a paper page were left out. Where a statement is my own reading of what the text implies (not a sentence of the paper), it is marked "(inference)". Where a statement comes from the official code and not from the paper, it is marked "(code)". Some fetched pages were summarised by the fetch tool's small model; the points that matter most for the design are marked with the section or file so they can be re-checked in two minutes.

Target design in mind: camera+radar BEV, trace (initial centre-line points/paths) then iterative refinement, one differentiable chain into a lane graph with navigation attribute that a planner consumes.

## 1. MapTR, MapTRv2, and whether a successor exists

**1.1 MapTR** - B. Liao, S. Chen, X. Wang, T. Cheng, Q. Zhang, W. Liu, C. Huang. *MapTR: Structured Modeling and Learning for Online Vectorized HD Map Construction*. ICLR 2023 (Spotlight). arXiv:2208.14437. https://arxiv.org/abs/2208.14437
- Each map element is a point set with a group of equivalent orderings (permutations); hierarchical query embedding (instance query + point query, summed: q_ij = q_i^ins + q_j^pt; defaults 50 instances x 20 points) and hierarchical bipartite matching (instance level Hungarian, then best permutation at point level). The decoder has L stacked layers that "iteratively refine the predicted map elements" (MapTRv2 paper text, Fig. 4 and Fig. 8). Losses: focal classification, point-to-point Manhattan (L1-type) distance, edge-direction loss (negative cosine of edge vectors). Chamfer distance is used only for evaluation thresholds (0.5/1.0/1.5 m), not for training. At inference the 50 outputs carry scores and "the top-scoring predictions can be directly utilized without other post-processing"; no NMS is described.
- Point refinement in the official decoder (code, `projects/mmdet3d_plugin/maptr/modules/decoder.py`, main): per layer `new_reference_points = sigmoid(reg_branch(output)[..., :2] + inverse_sigmoid(reference_points))`, then `reference_points = new_reference_points.detach()`. So positions are regressed differentiably (residual in logit space) and supervised at every layer, but the gradient between layers is cut.
- Relevance for trace-then-refine: the standard recipe is "residual offset per layer + per-layer loss + stop-gradient on the previous positions"; if the refinement stages of the new net should learn from each other's errors, copy DINO's look-forward-twice (5.2) instead of a plain detach.

**1.2 MapTRv2** - B. Liao, S. Chen, Y. Zhang, B. Jiang, Q. Zhang, W. Liu, C. Huang, X. Wang. *MapTRv2: An End-to-End Framework for Online Vectorized HD Map Construction*. IJCV 2024. arXiv:2308.05736. https://arxiv.org/abs/2308.05736 (arXiv notes substantial text overlap with 2208.14437; official README confirms IJCV 2024 acceptance.)
- Adds, for training only: auxiliary one-to-many matching (T = 300 extra instance queries, each ground-truth element repeated K = 6 times, sharing point queries and decoder layers with the one-to-one branch) and auxiliary dense supervision (depth cross-entropy from LiDAR-rendered depth, BEV segmentation, perspective-view segmentation; weights 3 / 1 / 2). Inference stays one-to-one with score-ranked outputs.
- Relevance: the one-to-many branch is a way to give each ground-truth centre-line several positive traces during training without changing the NMS-free inference; useful for a trace stage that proposes many candidate paths per lane.

**1.3 "MapTRv3" - does it exist?** No evidence of one. (a) An arXiv full-text search for "MapTRv3" returns "no results"; a title search for "MapTR" returns only 2208.14437. (b) The official hustvl/MapTR README (read 2026-10-23) lists MapTR, MapTRv2 and "MapTRv2*" (MapTRv2 with a centre-line class using the LaneGAP path-wise modelling, not a separate paper) as the newest; related works named there are VAD, VADv2 ("built on MapTRv2", arXiv:2402.13243, README statement), VMA (map annotation) and LaneGAP. (c) Web search for "MapTRv3" finds nothing. The same group's later driving work (DiffusionDrive, CVPR 2025) is not a MapTR version.

## 2. Query-based / streaming / temporal and topology methods

**2.1 StreamMapNet** - T. Yuan, Y. Liu, Y. Wang, Y. Wang, H. Zhao. *StreamMapNet: Streaming Mapping Network for Vectorized Online HD Map Construction*. arXiv:2308.12570 (arXiv page lists no venue; I did not verify one). https://arxiv.org/abs/2308.12570
- Multi-point attention uses the previous layer's predicted points as reference points; each layer regresses absolute coordinates P_{i+1} = sigmoid(Reg(Q_i)). The top-k confident queries of the previous frame are warped with the ego-motion matrix (points and query features), BEV features are warped and fused with a GRU. Loss: SmoothL1 polyline loss minimised over the permutation group, focal classification, and an auxiliary SmoothL1 loss aligning propagated queries with transformed points. Hard steps: bipartite matching, top-k query selection for propagation. No inference NMS described.
- Relevance: gives the temporal-carry-over template (warp points + features by ego motion, top-k carry) for a streaming trace stage.

**2.2 SQD-MapNet** - S. Wang, F. Jia, Y. Liu, Y. Zhao, Z. Chen, T. Wang, C. Zhang, X. Zhang, F. Zhao. *Stream Query Denoising for Vectorized HD Map Construction*. ECCV 2024. arXiv:2401.09112. https://arxiv.org/abs/2401.09112 ; ECVA page https://www.ecva.net/papers/eccv_2024/papers_ECCV/html/2879_ECCV_2024_paper.php
- Noisy copies of the previous frame's ground truth (noise on each curve's bounding box: shift/scale, so points keep their relative layout) become denoising queries trained to reconstruct the current frame's ground truth. Training only; no inference cost. Hard step: adaptive temporal matching of previous to current ground truth by bidirectional Chamfer distance with a threshold delta = alpha(w+h)/2 (alpha = 0.1 best), noise decay tied to that threshold.
- Relevance: a cheap way to teach the refinement stage to repair displaced/outdated traces, using perturbed ground truth as training input.

**2.3 MapTracker** - J. Chen, Y. Wu, J. Tan, H. Ma, Y. Furukawa. *MapTracker: Tracking with Strided Memory Fusion for Consistent Vector HD Mapping*. ECCV 2024 (Oral). arXiv:2403.15951. https://arxiv.org/abs/2403.15951
- Treats mapping as tracking: memory of BEV raster features and of vector features per road element, with strided fusion of past memories; tracked elements carry over frame to frame. (Point-refinement internals not checked beyond the abstract.)
- Relevance: argument for keeping both a raster and a vector memory in a streaming trace/refine loop.

**2.4 MapQR** - Z. Liu, X. Zhang, G. Liu, J. Zhao, N. Xu. *Leveraging Enhanced Queries of Point Sets for Vectorized Map Construction*. ECCV 2024. arXiv:2402.17430. https://arxiv.org/abs/2402.17430
- Scatter-and-gather query: 100 instance queries each scattered into 20 point-level queries with their own reference point, cross-attention to BEV, then gathered by an MLP over the concatenated outputs. Training uses one-to-one loss (classification, point-to-point, direction), one-to-many loss, dense BEV/PV segmentation loss; hierarchical bipartite matching with Manhattan distance. The paper text I read does not describe per-layer reference-point refinement or detach; no NMS/threshold at inference is described.
- Relevance: separating content (per instance) from position (per point) is a clean interface between an instance-level "trace" token and point-level refinement.

**2.5 LaneSegNet** - T. Li, P. Jia, B. Wang, L. Chen, K. Jiang, J. Yan, H. Li. *LaneSegNet: Map Learning with Lane Segment Perception for Autonomous Driving*. ICLR 2024. arXiv:2312.16108. https://arxiv.org/abs/2312.16108 ; https://proceedings.iclr.cc/paper_files/paper/2024/hash/06d86daa7001b7ea755ac4c80dc93497-Abstract-Conference.html
- Lane segment = centre-line plus left/right boundary, each an ordered set of 10 3D points (left = centre + offset, right = centre - offset), plus type and mask. Six-layer Deformable-DETR-style decoder with "lane attention" (heads attend to regions along the lane; 4 reference points per segment; reference points refined per layer from the previous prediction), 200 queries. Topology: predecessor and successor MLPs (separate weights) on every query pair, then an MLP on the concatenation and a sigmoid, giving a soft weighted adjacency matrix. One-to-one assignment (Hungarian or Sinkhorn), losses: L1 geometry, mask CE + dice, focal for class and topology. No inference NMS/threshold stated; thresholds appear in evaluation only.
- Relevance: the closest published "centre-line queries -> soft adjacency matrix" design; adjacency stays continuous until evaluation.

**2.6 TopoNet** - T. Li, L. Chen, H. Wang, Y. Li, J. Yang, X. Geng, S. Jiang, Y. Wang, H. Xu, C. Xu, J. Yan, P. Luo, H. Li. *Graph-based Topology Reasoning for Driving Scenes*. arXiv:2304.05277 (arXiv page lists no venue). https://arxiv.org/abs/2304.05277
- Deformable-DETR-style centre-line decoder with 200 queries, 11 ordered 3D points and a confidence per query; scene graph neural network on lane (and traffic-element) queries; pairwise sigmoid heads give lane-lane and lane-traffic-element topology. As read from the paper text (via fetch), reference points stay fixed across decoder layers and no iterative box refinement is described (not checked in the code). Topology edges are counted at confidence > 0.5 for the metric, and the paper lists merging/pruning post-processing as a limitation.
- Relevance: shows the failure mode of independent per-lane detection (endpoint inconsistency) that a trace-then-refine chain with shared endpoints is meant to avoid.

**2.7 TopoLogic** - Y. Fu, W. Liao, X. Liu, H. Xu, Y. Ma, F. Dai, Y. Zhang. *TopoLogic: An Interpretable Pipeline for Lane Topology Reasoning on Driving Scenes*. NeurIPS 2024. arXiv:2405.14747. https://arxiv.org/abs/2405.14747 ; https://proceedings.neurips.cc/paper_files/paper/2024/file/7116cda41d75d580bae15d9e484a8466-Paper-Conference.pdf
- Scores a lane pair by combining a geometric distance (between lane endpoints) with similarity of lane queries in semantic space; the abstract states the geometric part can be added to already trained models without retraining and reduces sensitivity to endpoint shifts.
- Relevance: a differentiable, endpoint-distance based edge score is a direct candidate for "which trace continues which" without a hard matching step.

**2.8 TopoStreamer** - Y. Yang, Y. Luo, B. He, H. Lin, S. Fu, C. Zheng, Z. Cao, E. Li, C. Yan, S. Cui, Z. Li. *TopoStreamer: Temporal Lane Segment Topology Reasoning in Autonomous Driving*. arXiv:2507.00709 (v5, Nov 2025; no venue listed). https://arxiv.org/abs/2507.00709
- Streaming attribute constraints (centre-line/boundary coordinates and classes consistent over frames), dynamic lane-boundary positional encoding (query positional information kept current), and lane-segment denoising.
- Relevance: "update the positional encoding of a query from its current prediction" is the same idea as re-encoding refined points into the next refinement step.

**2.9 LaneGAP** - B. Liao, S. Chen, B. Jiang, T. Cheng, Q. Zhang, W. Liu, C. Huang, X. Wang. *Lane Graph as Path: Continuity-preserving Path-wise Modeling for Online Lane Graph Construction*. ECCV 2024. arXiv:2303.08815. https://arxiv.org/abs/2303.08815
- Whole paths (not pieces) are the learned unit: ordered polyline (default 30 points) or Bezier, MapTR-style decoder (6 deformable layers, Hungarian matching, focal + L1 + auxiliary BEV segmentation). The lane graph is recovered by Path2Graph, a non-learned post-process: discretise each path at 0.15 m, add vertices/edges, merge overlapping vertices closer than 0.15 m. Beats TopoNet by 1.6 mIoU on OpenLane-V2 (abstract).
- Relevance: the path-as-unit representation is the closest published analogue of "trace"; its Path2Graph step is exactly the kind of hard geometric step the new design wants to replace by a learned/soft merge.

**2.10 Coherent Online Road Topology Estimation (SD-map prior)** - K. S. Pham, C. Witte, J. Behley, J. Betz, C. Stachniss. IROS 2025. arXiv:2507.01397. https://arxiv.org/abs/2507.01397
- Lane segments + topology + road boundaries online, with hybrid lane-segment encodings that include a standard-definition map prior, denoising techniques to stabilise training, and past frames for temporal consistency.
- Relevance: another instance of denoising-query training for lane queries; the SD prior is optional for the present camera+radar setting.

**2.11 SMART** - J. Ye, D. Paz, H. Zhang, Y. Guo, X. Huang, H. I. Christensen, Y. Wang, L. Ren. *SMART: Advancing Scalable Map Priors for Driving Topology Reasoning*. ICRA 2025. arXiv:2502.04329. https://arxiv.org/abs/2502.04329
- Learns lane-topology priors from SD and satellite maps supervised by large-scale geo-referenced HD maps; plugs into online topology methods (up to +28% on OpenLane-V2, abstract).
- Relevance: low for point refinement (it is a prior, not a refiner); relevant only if an SD/navigation prior is later fed to the trace stage.

## 3. Diffusion / denoising / autoregressive generation of maps

**3.1 VectorMapNet** - Y. Liu, T. Yuan, Y. Wang, Y. Wang, H. Zhao. *VectorMapNet: End-to-end Vectorized HD Map Learning*. ICML 2023 (PMLR 202:22352-22369). arXiv:2206.08920. https://proceedings.mlr.press/v202/liu23ax.html
- Two stages: an element detector (queries -> keypoints and labels) and an autoregressive polyline generator over flattened coordinate tokens on a 200 x 100 grid (0.3 m cells), ended by an EOS token. Differentiable: token logits and the transformers. Hard: coordinate quantisation, categorical token choice, EOS termination, Hungarian matching in training; teacher forcing on ground-truth keypoints in training.
- Relevance: the cautionary baseline - discretised autoregression gives quantisation error and a non-differentiable token choice; the later query-based methods (MapTR) beat it, which is evidence against token-based point generation for a fully differentiable chain.

**3.2 SeqGrowGraph** - M. Xie et al. (Amap, Alibaba / Xi'an Jiaotong University). *SeqGrowGraph: Learning Lane Topology as a Chain of Graph Expansions*. ICCV 2025. arXiv:2507.04822. https://arxiv.org/abs/2507.04822 ; https://openaccess.thecvf.com/content/ICCV2025/html/Xie_SeqGrowGraph_Learning_Lane_Topology_as_a_Chain_of_Graph_Expansions_ICCV_2025_paper.html
- The lane graph is grown one vertex at a time (adjacency n x n -> (n+1) x (n+1)), centre-lines as quadratic Bezier curves, DFS ordering of the ground-truth graph, one transformer decoding tokens autoregressively. Tokens: node positions binned at 0.5 m (ids 0-200), node indices, Bezier control points, special tokens; cross-entropy with teacher forcing (point tokens weighted 2x). Gradients flow through the decoder and BEV encoder, but not through coordinates (quantised) or the discrete connectivity tokens; Bezier geometry is supervised only via quantised control-point tokens. DFS ordering and node merging are preprocessing, not learned. (From the paper's HTML; inference strategy argmax vs sampling not specified there.)
- Relevance: handles loops and bidirectional lanes, which a fixed-query set struggles with; but every geometric quantity is a class label, so it cannot be refined by a continuous loss.

**3.3 MapDiffusion** - T. Monninger, Z. Zhang, Z. Mo, M. Z. Anwar, S. Staab, S. Ding. *MapDiffusion: Generative Diffusion for Vectorized Online HD Map Construction and Uncertainty Estimation in Autonomous Driving*. IROS 2025. arXiv:2507.21423. https://arxiv.org/abs/2507.21423
- Diffusion directly on vectorized polylines, starting from Gaussian-noise queries; DETR-style decoder with timestep embedding and deformable cross-attention to a latent BEV grid; class scores are kept out of the diffusion and predicted in a final step; trained to regress the clean polyline at all timesteps (T = 1000, cosine schedule), inference with 5 DDIM steps (eta = 0.5). Hard steps (paper HTML): outputs with score below tau = 0.5 are dropped and re-randomised between steps; ten samples are drawn, rasterised (score-weighted, Gaussian-smoothed), averaged and thresholded to obtain the refined map and a per-pixel variance as uncertainty. The paper does not state whether gradients flow through the inference chain; training is the usual per-timestep regression.
- Relevance: shows a published way to refine points iteratively from noise and to get uncertainty, at the price of a threshold-and-average step; for a planner the per-sample spread could be passed as a feature instead of being thresholded (inference).

**3.4 LaneDiffusion** - Z. Wang, W. Zhang, W. Zhang, X. Tan, H. Liu, Y. Wang, G. Li. *LaneDiffusion: Improving Centerline Graph Learning via Prior Injected BEV Feature Generation*. ICCV 2025 (arXiv posting Nov 2025). arXiv:2511.06272. https://arxiv.org/abs/2511.06272
- Diffusion in BEV feature space generates lane-centre-line priors (Lane Prior Injection Module + Lane Prior Diffusion Module), then vectorised centre-lines and topology are decoded from the generated features; plug-in for BEV-based architectures; +1.8% to +6.8% on point-level and segment-level metrics (abstract). I did not check the decoder's matching/threshold steps.
- Relevance: the diffusion acts on dense features, so the whole chain stays differentiable; vectorisation remains a separate DETR-style stage.

**3.5 DiffMap** - P. Jia, T. Wen et al. *DiffMap: Enhancing Map Segmentation with Map Prior Using Diffusion Model*. arXiv:2405.02008 (no venue verified). https://arxiv.org/abs/2405.02008
- Latent diffusion over map-segmentation masks as a structural prior plugged behind HDMapNet/SuperFusion to fix structural errors (largest gains for dividers and crossings).
- Relevance: raster-space refinement only; no point positions.

**3.6 TopoGPT** - J. Fu, Z. Huang, H. Li, N. Wang, S. Liu. *Generative Lane Topology Reasoning via Autoregressive Model with Geometry Prior*. ECCV 2026. arXiv:2606.31814. https://arxiv.org/abs/2606.31814
- Serialises lane graphs into discrete tokens and pretrains a transformer by next-token prediction on a 3.3M-scene map dataset; a perception adapter aligns multi-view BEV features with the prior. Reports +6.4 lane-level and +11.6 point-level over prior methods on OpenLane-V2 (abstract).
- Relevance: a learned geometry prior over lane graphs; discrete tokens, so same hard-step caveat as 3.2.

**3.7 MapDreamer** - J. Brandes, P. Crocoll, W. Burgard. *MapDreamer: Aerial Imagery Conditioned Latent Diffusion for Lane-Level Map Generation*. ECCV 2026. arXiv:2607.01370. https://arxiv.org/abs/2607.01370
- VAE latent of centre-lines and connections, transformer latent diffusion conditioned on aerial features through cross-attention at each denoising step; a "lane cardinality module" and learned "ghost" lane latents handle a varying number of lanes. Offline map generation from aerial imagery, not online perception.
- Relevance: the cardinality module plus ghost latents is a published way to cope with a variable number of lanes without a score threshold in the generator.

**Denoising queries (training-time) in map methods:** SQD-MapNet (2.2), TopoStreamer (2.8), Coherent Online Road Topology (2.10); in object detection DINO (5.2). MapTRv2 itself uses no denoising queries (its extra training device is the one-to-many branch, 1.2).

## 4. How end-to-end stacks feed map queries to the planner

**4.1 UniAD** - Y. Hu, J. Yang, L. Chen, K. Li, C. Sima, X. Zhu, S. Chai, S. Du, T. Lin, W. Wang, L. Lu, X. Jia, Q. Liu, J. Dai, Y. Qiao, H. Li. *Planning-oriented Autonomous Driving*. CVPR 2023 (arXiv listing: "award candidate"). arXiv:2212.10156. https://arxiv.org/abs/2212.10156
- MapFormer's last-layer queries go to MotionFormer, which cross-attends to them (agent-map interaction, Sec. 2.2). The planner does not attend to map queries itself: its ego query comes from MotionFormer ("the ego-vehicle query from MotionFormer already expresses its multimodal intentions"), is combined with a command embedding and attends to BEV features (Sec. 2.4), so map information reaches the planner indirectly. No score filter, threshold or NMS on map queries is specified (thresholds 0.4/0.35 in the appendix belong to detection/track queries). Training: stage 1 tracking + mapping, stage 2 end-to-end for 20 epochs with all modules (Sec. 2.5); the paper does not discuss detaching. A collision-avoidance step at inference optimises over candidate trajectories against predicted occupancy; it is a hard post-processing step and not trained through (Table 10 ablation "Occ. Optim.").
- Relevance: map tokens as the whole last-layer query set via cross-attention, with the planner loss reaching them through the ego query (inference from the stage-2 setting).

**4.2 VAD** - B. Jiang, S. Chen, Q. Xu, B. Liao, J. Chen, H. Zhou, Q. Zhang, W. Liu, C. Huang, X. Wang. *VAD: Vectorized Scene Representation for Efficient Autonomous Driving*. ICCV 2023. arXiv:2303.12077. https://arxiv.org/abs/2303.12077
- The ego query cross-attends to the map queries (and agent queries) in a transformer decoder; the output feeds an MLP planning head - no thresholding on that path. Separately, vectorised planning constraints (ego-agent collision, ego-boundary overstepping, ego-lane direction) act on map vectors selected by score threshold epsilon_m = 0.5 and nearest-element selection (closest boundary within 1.0 m, closest lane divider within 2.0 m); these are hard selections inside the constraint losses. The paper calls VAD "fully differentiable and trained in an end-to-end manner"; it does not explicitly discuss the planning gradient into map queries, but the ego-to-map cross-attention is on the gradient path (inference).
- Relevance: the soft path (cross-attention, no filter) and the hard path (thresholded, nearest-selected constraints) coexist; a replacement for the hard path would be a soft distance field or a score-weighted distance.

**4.3 GenAD** - W. Zheng, R. Song, X. Guo, C. Zhang, L. Chen. *GenAD: Generative End-to-End Autonomous Driving*. ECCV 2024. arXiv:2402.11502. https://arxiv.org/abs/2402.11502
- Learnable map queries refined by cross-attention over BEV tokens, each decoded into 20 BEV points per map element; map tokens enter the planner by cross-attention into the instance tokens (I <- CA(I, M, M)) after ego-agent self-attention. No thresholding, NMS or top-k on map tokens is described; bipartite matching is used only for the auxiliary map and detection targets. Total loss = prior + planning + map + detection ("end-to-end"); the paper does not explicitly discuss planning gradients into M.
- Relevance: the plainest "all map tokens, cross-attention, one summed loss" interface.

**4.4 SparseDrive** - W. Sun, X. Lin, Y. Shi, C. Zhang, H. Wu, S. Zheng. *SparseDrive: End-to-End Autonomous Driving via Sparse Scene Representation*. ICRA 2025 (stated in the official README, "17 March, 2025: accepted by ICRA 2025"; the arXiv page lists no venue). arXiv:2405.19620. https://arxiv.org/abs/2405.19620
- Paper: the ego instance is concatenated with detection instances and interacts via agent-temporal cross-attention, agent-agent self-attention and agent-map cross-attention; ego initialised from front-camera feature; stage 2 trains perception and planner jointly with no weights frozen. The paper does not mention top-k or stop-gradient. Official code (`projects/mmdet3d_plugin/models/motion/motion_planning_head.py`, code): top-k by max class sigmoid score before planning (num_det = 50, num_map = 10 by default), no threshold; map top-k features are the keys of the map cross-attention; motion anchors are detached (`prediction.detach()`), instance features and anchors are not detached in that file, so a planning loss can reach detection/map features through the attention (one file read; other helpers not checked). Planning output: command filter then collision-aware rescoring that sets the score of colliding trajectories to 0 (hard).
- A successor *SparseDriveV2: Scoring is All You Need for End-to-End Autonomous Driving* (arXiv:2603.29163, 2026) exists; I did not analyse its map-token handling.
- Relevance: top-k by confidence is the hard step that standard stacks use; the gradient still reaches the selected tokens' features, not the selection.

**4.5 DiffusionDrive** - B. Liao, S. Chen, H. Yin, B. Jiang, C. Wang, S. Yan, X. Zhang, X. Li, Y. Zhang, Q. Zhang, X. Wang. *DiffusionDrive: Truncated Diffusion Model for End-to-End Autonomous Driving*. CVPR 2025 (Highlight). arXiv:2411.15139. https://arxiv.org/abs/2411.15139
- Truncated diffusion from K-means anchor trajectories (20 on NAVSIM, 18 on nuScenes), 2 DDIM steps; cascade decoder with deformable spatial cross-attention to BEV/PV features and cross-attention to agent/map queries from the perception module (on NAVSIM only agents, no vectorised map). On nuScenes it is built on SparseDrive and initialised from perception-only stage-1 weights, then trained 10 epochs on planning; the text does not say whether perception is frozen. Hard steps: nearest anchor to the ground truth is the positive in training; highest-score trajectory is output at inference; no NMS ("without post-processing").
- Relevance: the planner side can be a diffusion/anchor decoder that cross-attends to the full map-query set; the open point is gradient flow into map queries.

**4.6 DriveTransformer** - X. Jia, J. You, Z. Zhang, J. Yan. *DriveTransformer: Unified Transformer for Scalable End-to-End Autonomous Driving*. ICLR 2025. arXiv:2503.07656. https://arxiv.org/abs/2503.07656
- Task parallelism: agent, map and planning queries interact directly in every block (task self-attention), sensor cross-attention, temporal cross-attention. From the paper's HTML: map queries are 100 learnable queries spread over the range; map positional encoding is re-encoded after each block from the predicted positions and classes; all ego/agent/map queries are concatenated in task self-attention with no top-k, threshold or NMS; the only hard selections are top-K = 50 confidence filtering before queries enter the temporal queue and winner-take-all mode selection. Single-stage training; stop-gradient is not mentioned, so the planning gradient reaches map queries through attention (inference).
- Relevance: the closest published example of the target interface: planner query and map queries in one attention, positions re-encoded between blocks, no NMS.

**4.7 UncAD** - P. Yang, Y. Zheng, Q. Zhang, K. Zhu, Z. Xing, Q. Lin, Y.-F. Liu, Z. Su, D. Zhao. *UncAD: Towards Safe End-to-end Autonomous Driving via Online Map Uncertainty*. ICRA 2025. arXiv:2504.12826. https://arxiv.org/abs/2504.12826
- Estimates online-map uncertainty and uses it to guide motion prediction and planning and in an "uncertainty-collision-aware" trajectory selection; +1.9% parameters, collision rate down by up to 26% (abstract). Mechanism of fusion not read beyond the abstract.
- Relevance: supports passing per-point/per-lane uncertainty to the planner instead of thresholded geometry.

## 5. Generic differentiable-geometry building blocks

**5.1 Soft-argmax / integral regression**
- X. Sun, B. Xiao, F. Wei, S. Liang, Y. Wei. *Integral Human Pose Regression*. ECCV 2018. arXiv:1711.08229. https://arxiv.org/abs/1711.08229 - an integral (expectation) operation over heat maps replaces the non-differentiable argmax and removes quantisation error. Relevance: a BEV heat-map/peak step becomes the expectation of coordinates under the softmax of the map, so refinement positions get gradient and sub-cell resolution.
- A. Nibali, Z. He, S. Morgan, L. Prendergast. *Numerical Coordinate Regression with Convolutional Neural Networks* (DSNT). arXiv:1801.07372 (no venue verified). https://arxiv.org/abs/1801.07372 - parameter-free differentiable spatial-to-numerical transform that works at low heat-map resolution. Relevance: usable per point at coarse BEV resolution.

**5.2 Iterative query/box refinement and query selection in DETR-type detectors**
- X. Zhu, W. Su, L. Lu, B. Li, X. Wang, J. Dai. *Deformable DETR*. ICLR 2021 (Oral). arXiv:2010.04159. https://arxiv.org/abs/2010.04159 (details from the ar5iv text, Sec. 4.2 and Appendix A.4). Iterative bounding box refinement: each layer predicts offsets added in inverse-sigmoid space to the previous box; "the gradients only back propagate through" the offsets (stop-gradient on the earlier box); the previous box's centre becomes the next reference point; heads do not share parameters. Two-stage variant: the first stage predicts a box per encoder pixel, "top scoring bounding boxes are picked as region proposals", "no NMS is applied" before the second stage, and the proposals are the initial boxes and positional embeddings of the decoder queries. Relevance: top-k with no NMS is the accepted, published way to pick traces; the selected positions then train through the decoder, while the selection itself is hard (inference).
- H. Zhang, F. Li, S. Liu, L. Zhang, H. Su, J. Zhu, L. M. Ni, H.-Y. Shum. *DINO: DETR with Improved DeNoising Anchor Boxes for End-to-End Object Detection*. ICLR 2023. arXiv:2203.03605. https://arxiv.org/abs/2203.03605 (details from the ar5iv text, Sec. 3.4-3.5). Look forward twice: Deformable DETR's refinement "blocks gradient back propagation to stabilize training", so a layer gets no signal from how the next layer corrects its box; DINO adds the next layer's offset to the undetached box so "the parameters of layer-i are influenced by losses of both layer-i and layer-(i+1)". Mixed query selection: only the anchor boxes (positional queries) are initialised from the top-K encoder features, content queries stay learnable. Contrastive denoising training for the decoder. Relevance: the direct fix for the MapTR-style detach if refinement stages should be trained jointly.
- N. Carion, F. Massa, G. Synnaeve, N. Usunier, A. Kirillov, S. Zagoruyko. *End-to-End Object Detection with Transformers* (DETR). ECCV 2020. arXiv:2005.12872. https://arxiv.org/abs/2005.12872 - set prediction with a bipartite-matching loss, removes NMS and anchor generation. Relevance: the origin of the "no NMS" interface that all query-based map methods inherit; matching remains a hard (but training-only) step.
- H. Hu, J. Gu, Z. Zhang, J. Dai, Y. Wei. *Relation Networks for Object Detection*. CVPR 2018. arXiv:1711.11575. https://arxiv.org/abs/1711.11575 - an object-relation module (appearance + geometry) replaces hand-designed duplicate removal; the authors call the result the first fully end-to-end detector. Relevance: a learned duplicate-suppression layer, an alternative to NMS if the trace stage outputs overlapping paths.

**5.3 Iterative offset refinement with per-iteration supervision**
- S. Peng, W. Jiang, H. Pi, X. Li, H. Bao, X. Zhou. *Deep Snake for Real-Time Instance Segmentation*. CVPR 2020 (Oral). arXiv:2001.01629. https://arxiv.org/abs/2001.01629 - an initial contour (octagon from extreme points) is iteratively deformed by per-vertex offsets predicted with circular convolution (3 iterations at inference by default, 128 points, smooth L1 on vertex positions). Relevance: vertex-offset refinement on an ordered closed/open point sequence with 1-D convolution along the sequence is a point-wise alternative to deformable attention for polylines.
- Z. Teed, J. Deng. *RAFT: Recurrent All-Pairs Field Transforms for Optical Flow*. ECCV 2020 (Best Paper). arXiv:2003.12039. https://arxiv.org/abs/2003.12039 (loss details from the ar5iv text). A recurrent unit updates the estimate iteratively; the loss covers every iterate with exponentially increasing weights (gamma = 0.8); the gradient is propagated through the update Delta f only and zeroed through the previous estimate f_k. Relevance: same two ingredients as MapTR (per-iteration loss, stop-gradient on previous estimate) in a recurrent, weight-shared form.

**5.4 Discrete choice made differentiable**
- E. Jang, S. Gu, B. Poole. *Categorical Reparameterization with Gumbel-Softmax*. ICLR 2017. arXiv:1611.01144. https://arxiv.org/abs/1611.01144 - differentiable sample from an annealable relaxation of a categorical. C. J. Maddison, A. Mnih, Y. W. Teh. *The Concrete Distribution*. arXiv:1611.00712 (venue not verified here). https://arxiv.org/abs/1611.00712 - same idea, independently. Relevance: for a sampled "next waypoint / which branch" decision with annealed temperature.
- Y. Bengio, N. Leonard, A. Courville. *Estimating or Propagating Gradients Through Stochastic Neurons for Conditional Computation*. arXiv:1308.3432 (preprint). https://arxiv.org/abs/1308.3432 - includes the straight-through estimator (copy the gradient across a stochastic or hard unit). Relevance: hard top-k/argmax in the forward pass, identity gradient in the backward pass, with the usual bias.
- G. Mena, D. Belanger, S. Linderman, J. Snoek. *Learning Latent Permutations with Gumbel-Sinkhorn Networks*. ICLR 2018. arXiv:1802.08665. https://arxiv.org/abs/1802.08665 - the Sinkhorn operator as a continuous relaxation of discrete matchings, combined with Gumbel-Softmax. Relevance: a soft assignment of predicted traces to ground-truth lanes (and of lane endpoints to successors) that keeps the loss differentiable.
- Y. Xie, H. Dai, M. Chen, B. Dai, T. Zhao, H. Zha, W. Wei, T. Pfister. *Differentiable Top-k with Optimal Transport* (SOFT top-k). NeurIPS 2020. arXiv:2002.06504. https://arxiv.org/abs/2002.06504 - top-k as an entropic optimal-transport solution with gradients from its optimality conditions. Relevance: replaces the top-k query selection by a smooth operator (the cost of the operator on 100-300 queries was not checked).
- Score gating (multiplying a selected token by its confidence so that gradient reaches the score) is not covered by any of the papers above as a named technique; I make no claim about it beyond noting that Deformable DETR/DINO select by score and do not describe such gating (inference).

**5.5 Set losses without a matching step, and differentiable rasterisation**
- H. Fan, H. Su, L. Guibas. *A Point Set Generation Network for 3D Object Reconstruction from a Single Image*. CVPR 2017. arXiv:1612.00603. https://arxiv.org/abs/1612.00603 (loss text from ar5iv). Proposes Chamfer distance and Earth Mover's distance as point-set losses; Chamfer is "continuous and piecewise smooth" in the point locations; EMD needs a bijection and is approximated. Relevance: Chamfer needs no instance or ordering assignment, so it can supervise unordered traces; a point-to-polyline variant (distance to the nearest segment) is the same construction with segments (inference).
- G. Zhang, J. Lin, S. Wu, Y. Song, Z. Luo, Y. Xue, S. Lu, Z. Wang. *Online Map Vectorization for Autonomous Driving: A Rasterization Perspective* (MapVR). NeurIPS 2023. arXiv:2306.10502. https://arxiv.org/abs/2306.10502 (details from ar5iv). Differentiable rasterisation of vectorised outputs: lines as a soft mask exp(-d/tau) with d the distance to the nearest polyline segment, polygons as sigmoid of signed distance / tau; dice loss between rendered prediction and ground-truth masks plus direction regularisation; training only, no inference cost; Hungarian matching is kept (the dice rendering cost is part of the matching cost). Relevance: a ready recipe to give a gradient to centre-line points from a raster ground truth and to measure lane-graph agreement without correspondence.
- S. Liu, T. Li, W. Chen, H. Li. *Soft Rasterizer: A Differentiable Renderer for Image-based 3D Reasoning*. ICCV 2019. arXiv:1904.01786. https://arxiv.org/abs/1904.01786 - replaces hard rasterisation by a probabilistic aggregation of all triangles' contributions per pixel, so gradients reach occluded and distant vertices. Relevance: the same softening principle that MapVR applies to polylines.

## Conclusion (5 lines)

1. No "MapTRv3" exists (arXiv full-text search empty, official README ends at MapTRv2 and the centre-line variant MapTRv2*); the reference recipe for differentiable iterative points is MapTR/Deformable-DETR: per-layer residual offsets, loss on every layer, stop-gradient between layers; DINO's look-forward-twice and RAFT's sequence loss are the documented variations on how gradient crosses iterations.
2. Every published lane/map method keeps some hard step: Hungarian matching and permutation argmin in training, top-score selection (no NMS) at inference, and for graphs a non-learned merge (LaneGAP Path2Graph, TopoNet pruning) or a thresholded edge (0.5); autoregressive and token methods (VectorMapNet, SeqGrowGraph, TopoGPT) are the least differentiable because coordinates are quantised.
3. The driving stacks (VAD, GenAD, DriveTransformer, and via MotionFormer UniAD) pass the whole map-query set through cross-attention/self-attention without NMS or threshold, so a planner loss can reach map tokens by construction; thresholds and nearest-element selection survive only in VAD's constraint losses, SparseDrive's top-k (50/10) and collision rescoring, and UniAD's occupancy optimisation. No paper in this set reports an ablation on detaching the map head from the planner loss.
4. Building blocks that fit a trace-then-refine chain: integral/soft-argmax coordinates (Sun 2018, DSNT), top-k with no NMS and refinement from the selected positions (Deformable DETR two-stage), look-forward-twice, Chamfer/point-to-polyline and MapVR-style soft rasterisation as correspondence-free losses, Sinkhorn/Gumbel relaxations for assignments, SOFT top-k for the selection itself, Relation-Network-style learned duplicate removal.
5. Suggested interface (inference from the above, not a published result): pass all refined traces plus per-trace confidence and per-point uncertainty as tokens into one attention with the planner query (DriveTransformer/GenAD style), use soft endpoint-distance edges (TopoLogic) instead of merge thresholds, and keep matching only as a training-time device.
