**What it does** [checked]: Branch 1 is a PointPillars-style pillar encoder. Branch 2 gives every radar point a density rho(p) = sum over the neighbours within bandwidth R in (x, y, z, Doppler) of a Gaussian kernel (written with a lost minus sign in the HTML); standardised per scan (rho - mu) / sqrt(sigma^2 + eps), so isolated clutter gets low values; two bandwidths (VoD 1.5 m and 2 m, TJ4DRadSet 0.6 m and 1 m), voxelised (0.16 x 0.16 x 0.24 m), 3D sparse convolutions, one pseudo-image per bandwidth, concatenated with the pillar pseudo-image. The method section does not model angular uncertainty explicitly; the claim that KDE absorbs it is only argued through noise suppression.

**Results that matter** [checked]: VoD val, 5 scans, entire area, AP 3D mAP / BEV mAP: pillar only 48.04 / 55.20, KDE only 26.97 / 31.60, both 50.97 / 56.77; driving corridor mAP 3D 68.08 / 48.45 / 69.72, BEV 69.29 / 52.09 / 72.05. TJ4DRadSet test, 1 scan, mAP 3D / BEV: pillar only 29.97 / 36.51, KDE only 12.27 / 16.43, both 32.99 / 40.98. Inference about 33 ms (VoD) and 43 ms (TJ4D, 23.1 FPS), GPU for timing not stated (training on a V100).

**Transferable technique**: a density channel next to the hard-binned features is worth +2.93 (VoD entire area) and +3.02 (TJ4D) mAP 3D, whereas density alone is much worse (it loses attributes): soft footprints help as an addition to the hard-binned attribute image, not as a replacement. The standardised density is cheap (neighbour search within R). For option B this is "count channel smoothed in polar bins", i.e. the soft rasterisation channel next to the hard attribute channels.

**Cost and fit**: neighbour search and 3D sparse conv are not trivially plain PyTorch; the idea (one extra smoothed-density channel, two bandwidths) is.

**Doubts**: no code; VoD / TJ4D 4D radar with elevation, not nuScenes 2D radar; kernel is isotropic in metres (not range-azimuth); no run-to-run spread.
