# 1908.09492 CBGS: class-balanced grouping and sampling for nuScenes detection

**What it does** [checked]: (1) sampling: count for each class the training samples that contain at least one instance (sum 128,106 over 28,130 samples because samples hold several classes), then draw 10 % of 128,106 = 12,810 samples per class, so rare classes are repeated; the epoch grows from 28,130 to about 128,100 samples (4.5x). (2) grouping: 10 classes in 6 detection heads of similar shapes: (car), (truck, construction vehicle), (bus, trailer), (barrier), (motorcycle, bicycle), (pedestrian, traffic cone). Optimiser AdamW with a one-cycle policy, max lr 0.04, batch 5, 20 epochs on 2080Ti GPUs (unclear whether the 20 epochs count the expanded set).

**Results that matter** [checked, nuScenes val, mAP / NDS, sparse-conv LiDAR detector]: none 35.68 / 45.17; + GT-AUG 37.69 / 53.66; + sampling 42.64 / 56.66 (+4.95 mAP, +3.0 NDS); + multi-head grouping 44.86 / 58.13 (+2.2 mAP); the remaining rows add encoder and head changes up to 51.44 / 62.56. Per-class gain only for the final model against PointPillars (bicycle 1.60 to 22.3, motorcycle 20.0 to 51.5), not isolated per component.

**Transferable technique**: our object head has 3 class groups (vehicle, two-wheeler, pedestrian); a two-wheeler appears in few frames. Class-balanced sampling is a change of the sampler only: repeat frames that contain a rare group. Cost: epoch length x (up to 4.5 in CBGS, much less with 3 groups); on a 3060 this competes with the training budget, so use it as a weight or a partial oversampling arm, not the CBGS default. The BEVDet configs train with CBGS (RECIPES note; DualBEV configs name it too); CR3DT trains without.

**Cost and fit**: free at run time; the epoch becomes longer in proportion.

**Doubts**: LiDAR sparse-conv detector, 2019; the +4.95 mAP is the step with GT-augmentation already on; no per-class isolation; the dense semantic head (areas, lines) is not affected by it.
