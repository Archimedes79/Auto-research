**What it does**: Pre-training of a sparse-conv lidar backbone (MinkUNet, SPVCNN, SECOND, PV-RCNN) by occupancy estimation. The backbone gives a latent vector per support point (voxel features read back at the points). A decoder, a 4-layer MLP with 128 hidden units and a sigmoid, takes [latent of the support point, local offset of the query from that point] and outputs the occupancy of the query; it is applied inside a ball of radius r around each support point (a vertical cylinder for BEV backbones). Queries are made without labels from the lidar ray from the sensor centre c to the point p with u = direction: front (p - 10 cm u) empty, behind (p + 10 cm u) full, and random "sight" points on [c, p] empty. Loss: binary cross-entropy (optionally an intensity term with weight 1).

**Results that matter** (checked): nuScenes mIoU with MinkUNet at 0.1 / 1 / 10 / 50 / 100 percent of the labels: 21.6 / 35.0 / 57.3 / 69.0 / 71.2 without -> 26.2 / 37.4 / 59.0 / 69.8 / 71.8 with ALSO; SPVCNN at 100 percent 70.7 -> 71.3. Detection (pre-trained on nuScenes, fine-tuned on KITTI, moderate R40 mAP): SECOND 65.35 -> 68.07, PV-RCNN 70.57 -> 72.53; ONCE 51.89 -> 52.68. Pre-training on one 16 GB V100, 200 epochs at batch 16 on nuScenes. The gain shrinks with more labels (+0.6 mIoU at 100 percent).

**Transferable technique**: a continuous-offset query decoder on top of a grid / point feature is the published, working form of "a decoder g(f_j, x + l, y + m)"; with the offset input it can output ANY per-query quantity, so for radar the targets can be the attributes of the detection nearest to the query (Doppler phase, RCS, codes) plus an occupancy / distance value. It needs no matching and no set loss: queries are taken at the true detections and at random points around them. The ray-based labels also exist for radar: the ray sensor -> detection is known, but only strong reflectors are reported, so "empty in front" is much weaker than for lidar and the "full behind" label must not be used.

**Cost and fit**: decoder MLP of 128 units on a few thousand queries per frame; training only, no inference cost.

**Doubts**: the benefit is a pre-training gain that fades with labels; no ablation against a reconstruction-free auxiliary task at equal compute; the detection numbers come from cross-dataset transfer (nuScenes -> KITTI), not nuScenes detection; the code licence is not named on the page.
