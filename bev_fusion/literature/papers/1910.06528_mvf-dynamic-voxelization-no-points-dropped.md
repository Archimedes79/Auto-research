**What it does**: Hard voxelization (HV, VoxelNet / PointPillars) fills a fixed buffer of K voxels x T points: a voxel with more than T points is randomly sub-sampled, a sample with more than K voxels loses voxels, and empty slots are zero-padded. Dynamic voxelization (DV) assigns every point to its voxel by index and keeps the full point-to-voxel and voxel-to-point maps: no cap, no padding, no random drop, so the voxel feature is deterministic. The per-voxel feature is a pooled point-MLP output; because the map is kept, the pooled feature can be handed back to each of its points (a lossless "devoxelise") and fused with a second view at the point level.

**Results that matter** (checked, the paper's own ablation, same detector, only the voxelization changed): Waymo vehicle 3D AP (IoU 0.7) HV+SV 56.62 -> DV+SV 59.29, BEV AP 75.57 -> 77.18; pedestrian 3D AP (IoU 0.5) 59.25 -> 60.83; KITTI car 3D AP easy / moderate / hard 85.9 / 74.7 / 70.5 -> 88.77 / 77.86 / 73.53. Latency per frame vehicle 41.1 -> 41.1 ms, pedestrian 36.1 -> 34.7 ms (GPU not named in the text read). The paper states that VoxelNet and PointPillars reserve 100 or more points per voxel; its own HV baseline uses T = 50, K = 48,000 (about 4x the voxels and 2x the buffer of PointPillars). The total fraction of points dropped is NOT reported.

**Transferable technique**: for the radar raster: never cap or average per cell without a record. Implement the cell code as a sort by flat cell index plus the rank of each detection inside its cell (a cumulative count after `argsort`), giving a canonical slot index; K slots x D features per cell hold every detection of the cell as long as the cell has at most K of them, and the count channel says when it does not. Pooled cell features (mean / max / count) can be added on top, and the cell-to-detection map lets a decoder read each detection's own feature back. Our `radar_bev.rasterize` (index_add_ mean) is the "mean of a cell" special case: injective only for one detection per cell.

**Cost and fit**: scatter / sort with variable lengths, no padding; for about 750 to 3,750 radar detections a sort plus segment ops is far below 1 ms on the 3060 (estimate, not measured). Plain PyTorch.

**Doubts**: lidar with 100k points, not 125-detection radar; the AP gain is mixed with other differences (HV+SV uses T = 50, K = 48,000); no number for how many points HV really dropped; the gain of DV may be mostly the removal of random-sampling noise at far range, where it is least relevant for a radar with few collisions.
