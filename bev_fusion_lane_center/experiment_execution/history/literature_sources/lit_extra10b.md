### 3.15 Deep learning as a catalogue of building blocks, and how a block is tuned to a function (added for loop 10; classic references from memory, recent ones checked by search on 2026-10-18: StreamMapNet (WACV 2024), MambaMap (arXiv 2507.20224), the topology-aware perception survey (arXiv 2509.23641) and the map survey (arXiv 2509.12632))

An end-to-end lane-graph network is a composition of a few block types. Each block does one kind of operation on a **grid** (a feature map) or on a **list** (tokens: seeds, vertices, edges, map polylines, queries); a function is built by choosing what the elements of the lists are, which positions and masks they carry, and which list pulls from which. The catalogue is short; the last two columns say whether the block is differentiable and where it was used in this project (E-numbers of the report).

| # | block | what it computes | tuned to a function by | diff. | used here |

| 1 | convolution, residual / U-Net / FPN pyramids (ResNet, U-Net, FPN, ConvNeXt) | local feature extraction on a grid, multi-scale | kernel, dilation, stride, pyramid levels, receptive field | yes | dense head (E27, E37), stem pyramid (E94), SD raster branch (E103) |
| 2 | deformable convolution / deformable attention (DCN, Deformable DETR) | sampling at learned offsets around a reference point | reference points, number of samples, scales | yes | replaced by explicit fan and cross-section sampling (E94: 27 + 7 points) |

**How a block is tuned to a function (patterns used in this project).** (i) *Choose what the list elements are:* seeds and trace steps (extraction), vertices (graph tokens), edges of 6 m (assignment, E83), SD polylines or SD raster cells (map). (ii) *Choose who pulls from whom:* head tokens pull from the BEV maps through an explicit fan of reference points (E94, a hand-designed deformable cross-attention with 27 + 7 points); vertex tokens pull from the SD-map tokens by full cross-attention (E104) instead of sampling the raster at the vertex (E103c). (iii) *Fuse the raw input with the pulled data:* the cross-attention layer of E104 adds a learned gate times the vertex's own input to the attention result, so that a vertex can ignore the map where the map is wrong (the abstention behaviour of E87 as a gate; the effect of the gate alone was not isolated). (iv) *Inject geometry as a bias, not as a rule:* distance, direction and relation biases in the attention (E83), the heading frame and the covered crop (E94) instead of hand-built rules. (v) *Make a rule a block:* the template ICP becomes a correlation volume with a soft-argmax (E103e), the assignment rules become a transformer (E83), the tracer becomes a step network (E94); the price in every case was measured (sections 7.18 and 7.21).

Takeaway: a lane-graph-to-planner network is the composition conv (grid) -> peak picking and iterative sampling blocks (grid to list) -> self- and cross-attention, pointers and relation-biased graph attention (list to list) -> recurrent or state-space memory with ego-motion warp (time) -> a planner head that pulls the lane tokens by cross-attention; each block has a differentiable form, and the only non-differentiable elements are discrete decisions (argmax events, matching in the loss), which imitation and relaxations handle.
