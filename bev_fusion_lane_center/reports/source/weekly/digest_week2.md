## 0. Setup recap (10 lines)

1. Task: from camera + radar (nuScenes) output a lane-centre-line graph around the car (polylines with successor links, few vertices), attach a navigation attribute per lane (on the route or not, from a simulated SD map), hand it to a planner; later (from loop 15) every module on the path should be differentiable ("no argmax, no matching, no rule step on the training path") [R16 sec.1; ST l.113; CLAUDE.md].
2. Data: nuScenes subset, 255 scenes (Boston, Singapore, day, dry), scene-disjoint split TRAIN 212 scenes / 8,414 frames, VAL 22 / 873, TEST 21 / 833 (809 with a route label). Not location-disjoint (overlap check still open). The long report's "323 scenes" is wrong, use 255 [ST l.110; PRO l.6; E2E sec.1; LIT sec.8]. Loop 16 triage used a fixed 250-frame VAL subset; full VAL from rung 2 [R16 sec.1; PRO l.7].
3. Foundation: frozen map-pretrained GaussianCaR (earlier CRN), cached features: 32 PCA decoder channels + 7 map logits = 39 channels on 200 x 200 cells of 0.5 m, plus heat + direction of a dense U-Net head (2.7 M) = 42 channels; the foundation and (mostly) the dense head are frozen [E2E sec.1/2; R17 sec.1]. Map pretraining gave lane F1 0.867 vs 0.624 with detection pretraining (+0.24) [E2E sec.3 E27].
4. Setting of every number: exact ego poses, simulated ADASIS-like SD map (error 0-3 m translation sigma, yaw 2 sigma, dropped roads, wrong map = map of another place, no map), synthetic sensor failures (night, blur, lost cameras, fog, radar off, extrinsics 3 deg), open loop [PRO l.3; E2E sec.1].
5. Graph metrics: point F1 / P / R at 0.5 / 1 / 1.5 m (F1@1 = at 1 m); J = mean of split-F1 and merge-F1 at 6 m (junction score); vertices per 100 m (Douglas-Peucker oracle needs 14.3 at 0.3 m, Imai-Iri floor about 13); FL = false-length fraction (share of predicted length not on a lane); lanes found = share of ground-truth lane length matched within tolerance; direction accuracy [R16 sec.1; R17 "Terms"].
6. Composite S (fixed before the first loop-16 run): S = 0.30 F1@1 + 0.20 F1@0.5 + 0.20 J + 0.15 Sp + 0.15 (1 - FL), Sp = min(1, 14.3 / vertices per 100 m), so being sparser than the oracle earns nothing and S rewards sparsity; noise band 0.010 (differences below are ties); no confidence interval exists for S [R16 sec.1; R17 sec.3, REV17a U4]. S is used from loop 16 on only; loops 10-15 report F1, split/merge F1, route success.
7. Route success (E59 definition): per frame the route points are covered AND precisely covered (1.5 m) by the flagged edges, both coverage and precision >= 0.8 [R16 sec.7 caption; R17 Terms]. Denominator differs between loops: loops 11-14 score every frame (an empty graph flags nothing and counts as 0) [T11 sec.7.29]; loop 17 drops frames without a graph (night single frame: 111 of 137 frames) [R17 sec.4.6, REV17a M4]. Map error cells 0 / 1 / 2 / 3 m, wrong map, no map. Consumer metric: error of the predicted path point at 20 m arclength against the driven path (small consumer, 93,314 parameters, 546 TEST frames with driven path >= 20 m; 82 frames per cell in loop 17) [T14a Terms; R17 sec.4.7e].
8. Noise: trace-network seed 0.001-0.002 F1 (E111); control/builder noise band 0.010 S; route head seed spread 0.05-0.09 route success (first stated "up to 0.03" in loops 11-15 and in the loop-17 plan, corrected in loop 17); scene-level interval about +-0.03 on a success rate and +-0.035 on F1 with 21 scenes; paired scene bootstrap 2000 draws [T12 sec.7.35; PRO l.11-13; REV17a W1; DEC sec.1].
9. TEST discipline: the rule is "TEST once per finished design (winner + control), with the user's OK, logged". The log contains ONE entry: loop 16 (champion vs control) [TUL]. BUT loops 10-15 reported TEST numbers as their main results, selected only some settings on VAL (route threshold 0.5), and compared failure/memory variants on TEST only (E105: 7 variants x 4 failure types, roughly 60 comparisons, no correction; E108-E112 hold variants also TEST only) [I11 "Protocol exceptions"; I12; T11 sec.7.27; E2E sec.1]. Loops 16b and 17: validation only. So "TEST once, VAL otherwise" holds for loops 16-17, not for loops 10-15.
10. Unit u = 1,200 iterations of 8 frames (control: 600 of 16); out-of-fold = the 22 VAL scenes split in two folds of 11 scenes, a learned part trained on one, evaluated on the other (loop 17); "control E94" = the loop-10 learned trace network (1.67 M, wavefront driver), "champion" = loop-16 builder D7 f1; "system A" = modular rule pipeline of loops 8-9 (accuracy reference), "system B" = learned chain (trace network + cross-attention route head + consumer) [R16; DEC sec.2; E2E sec.1].

### Loop 10 - the learned trace network and the registration-free route head (2026-10-17 20:15 -> 2026-10-18 01:45)

**Dates and request.** User re-invoked /loop with the E2E task and gave no answers to the three open decisions, so defaults: arm A first, rings 12.5 m, steps {2, 4, 6}; matching the rule pipeline acceptable [ST l.94]. **Hypotheses** [T10a sec.7.16-7.20; T10b]: (a) one learned network can replace tracer + assembler (+ key-point cut + Bezier connectors) at equal F1; (b) growing the graph near to far, conditioned on the finished near graph, reduces far errors; (c) far steps need a range-aware threshold; (d) wrong-direction training teaches orientation; (e) the existing assignment network (E87) works on the learned graph; (f) the navigation attribute can be produced inside the network without a hand-built registration; (g) cross-attention beats sampling for reading the SD map.

**Built.**
- E92: ground-truth expert + ring wavefront driver (rings 12.5 / 25 / 37.5 / 50 / 70 m) + vertex-to-piece assembly; tests T1, T5, T7 pass [T10a sec.7.17].
- E94 trace network (1.67 M parameters): reads 39 foundation channels + dense-head heat/direction; stem pyramid (200 / 100 / 50 grids) with seed and direction heads; per active head a fan of 27 sampled points (9 headings x look-aheads 2/4/6 m), last 6 vertices, a state vector and a covered crop (16 x 16 cells of 1 m with the already emitted graph); block 1 (3 transformer layers) predicts heading bin, step class {2,4,6 m}, residuals; block 2 (2 layers) samples the cross-section (7 offsets) and predicts offset, on-lane logit, event (continue/end/fork/merge/border), fork angle and a merge pointer. Seeds = 192 strongest heat peaks, NMS 5 cells, two heads per seed. Imitation training (10,000 steps, 16 frames x 32 states, noisy GT states, 20 % negatives, ~85 min, disk-bound) [T10a sec.7.18]. Discrete parts: argmax heading/step, peak seeds, event bookkeeping, teacher forcing (stated honestly only in loop 15) [R15 sec.1].
- E102-E104: E87 assignment network applied to learned graphs (zero-shot, retrained); route heads on stored 128-d step tokens + rasterised SD map: a/b vertex-local head, c graph transformer, d/e pose head and correlation-volume localisation, E104 cross-attention from vertex tokens to SD-map tokens (2,500 tokens at 2 m cells) with gated input fusion (0.69 M), three folds of tokens, 40,000 steps [T10b sec.7.21].

## 3. Story of the week

**How the work evolved.**
(1) Loops 10-11 (10-17 evening .. 10-18): the red hand-built blocks leave the main path. A learned trace network (E94) replaces tracer + assembler, a cross-attention route head (E104b) replaces registration + assignment; both come out slightly worse than the modular pipeline A (F1 -0.008 VAL / -0.017 TEST; route success 0.007-0.026 below A's single network at the VAL-selected threshold), and a training-free memory in front of the extractor brings the learned chain to about the robustness of A's own coasting (night F1 0.73 vs 0.69).

Calibration and a frame-level route confidence for the planner interface, a monitor-free spatial hold (E112), learned junction/piece verifiers (modest, harmful under failure unless gated), and a first learned consumer with trust inputs and ego motion (ego motion helps, trust inputs and a learned gate do not).
(3) Loop 14 (10-19 .. 10-20): the planner consumer becomes the test of "usable interface": B equals A on a one-point path-error metric (0.34 vs 0.36 m), memory + failure training protect it under failure, the planner loss into the route head gives nothing.

Successive halving of eight designs yields a pieces-and-links builder with teardrop sampling and survival read-out: 38 % fewer vertices at equal-ish quality, 20-40x faster after loop 16b engineering; the fork score and lane recall stay behind; the route gap turns out to be a representation problem.
(6) Loop 17 (10-24): robustness of that champion.
