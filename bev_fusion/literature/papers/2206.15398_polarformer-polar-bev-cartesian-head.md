**What it does** [checked]: Multi-camera detection. Each image column is a ray; cross-attention from polar queries (azimuth x radius) to the column features builds a polar BEV map at three scales ((64,256), (32,128), (16,64)); a polar-feature / Cartesian-prediction variant exists (PolarFormer-PC); the conversion from the polar map to the Cartesian head is not described on the page.

**Results that matter** [checked, nuScenes val, mAP / NDS, Table 2a]: CenterPoint-type Cartesian / Cartesian 37.8 / 45.4; PolarFormer-CC 38.1 / 45.5; PolarFormer-PC (polar features, Cartesian prediction) 38.5 / 45.0; full polar / polar 39.6 / 45.8. Table 4: Cartesian loss with polar prediction 39.6 / 45.8, polar loss 31.5 / 38.2 (slow convergence, azimuth discontinuity suspected). By distance: polar beats Cartesian by +3.1 mAP / +0.3 NDS near and +1.3 / +0.7 at medium range (Figure 5c, as stated). No latency or FPS; trained on 8 V100.

**Transferable technique**: polar features followed by a Cartesian head cost nothing in accuracy (38.5 vs 38.1 mAP, NDS within 0.5, single-run numbers); and the loss should live in the output domain (Cartesian loss: +8 mAP over a polar loss). For us: train the radar branch through the Cartesian BEV loss; if an auxiliary polar loss is used keep its weight small.

**Cost and fit**: attention core, no cost figure on the page; not usable as a model.

**Doubts**: camera, not radar; one run per row; differences of 0.4 to 0.5 mAP are inside plausible noise.
