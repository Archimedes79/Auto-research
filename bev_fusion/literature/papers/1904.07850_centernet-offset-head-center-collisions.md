# 1904.07850 CenterNet (Objects as Points): the sub-cell offset head and how often two centres share a cell

**What it does**: Objects are keypoints at stride R = 4: a heat-map peak at the centre cell, an L1 local-offset head (weight 1) trained only at the keypoints that recovers the discretisation error of the rounding, plus size heads. The decoded centre is the peak cell plus the offset. FFT-RadNet (2112.10646, collected) uses the same code in polar cells of 0.8 m x 0.8 deg (occupancy + range / azimuth offsets; range error 0.11 m, angle error 0.17 deg).

**Results that matter** (checked): on COCO train, 614 object pairs out of 860,001 objects fall on the same centre cell at stride 4, so "<0.1 percent" cannot be predicted; 715 pairs have box IoU above 0.7, which anchor-based assignment would put on two anchors, so centre assignment has fewer collisions. Even with ground-truth heat-map, size and offset the pipeline misses about 0.5 percent of the objects, which the authors attribute to discretisation and the Gaussian rendering of the heat-map.

**Transferable technique**: the loss is only evaluated where a detection exists, so the offset head cannot be diluted by empty cells; the decoded position is exact up to the regression error (no information is lost by the grid if the cell holds one point). The statistic does not transfer to radar: objects at stride 4 in an image are sparse, detections in a 0.5 m radar cell from five sensors and several sweeps are not. The collision rate (and the loss for K = 1, 2, 3, 4 slots) has to be measured on the nuScenes radar cache; a read-only script for it is `temp/radar/collision_stats.py` (written by the scout, not yet run: no shell was available).

**Cost and fit**: free (two extra output channels).

**Doubts**: images, object centres (not raw returns); the collision count is for COCO only; the 0.5 percent miss floor shows the Gaussian target, not the offset, can limit the recall.
