# comparison - the one place where a prediction is compared with the ground truth

`autoresearch/evalsuite/comparison/`. Two files do the comparing, a third joins them to the suite. Nothing else computes a comparison: `render/figure.error_counts`, the minimal and the toy adapter and the BEV system's `bev_fusion/evaluation/metrics.py` call this core.

| file | compares | read it for |
|---|---|---|
| `maps.py` | two pixel maps (a predicted mask against a ground-truth mask) | confusion counts, iou / precision / recall / f1, the tolerant version for thin structures |
| `boxes.py` | two lists of boxes (detections against ground truth) | matching, true-positive errors, average precision |
| `metrics.py` | (the join) `MapMetric` and `BoxMetric`: ready-made suite `Metric`s on the two files above | how an adapter plugs in |
| `mutation_check.py` | (the proof) breaks the core one rule at a time and checks that the tests notice | how well the tests guard the core |

**Not here, on purpose.** Parsing a dataset or a network output (an adapter's `extract` function does that), thresholding a probability map, plotting (`render/figure.py` only draws), lane polylines and graphs (`../lanes/measures.py`), and everything specific to one problem: the BEV system's range bins, field of view, classes and dt keys stay in `bev_fusion/evaluation/metrics.py`. That file used to carry its own copies of the comparison; since 2026-10-31 its `match` (= `boxes.match_frames`), `ap_nuscenes`, `ap_all_points`, `tp_errors` and `dilate` are this core's, `SegMeter` counts with `maps.tolerant_counts` and `DetMeter` builds its rows with `boxes.match_flags` and reduces them with `boxes.detection_numbers(..., ties="list")`. The former copies are frozen as `_REF` in the selftest. The switch was checked three ways: the same numbers bit for bit on random worlds with ties (16 `DetMeter` worlds, `SegMeter` with tolerances, masks, known / unknown and lines), `bev_selftest.py --golden` (the 3738 stored numbers of the former `evaluate_run.py` reproduced to 1e-9, with the old file and with the new one) and the BEV selftests.

## Rules the core keeps
1. **Plain inputs.** numpy arrays (boolean or 0 / 1 integer maps) and dicts. No `Sample`, no `Prediction`, no torch, no dataset. Float maps are refused: threshold first (`prob > 0.5`), a nonzero probability is not a set cell; so are integer maps with other values (an 255 = "ignore" label belongs in `valid`). `render/figure.error_counts` is the lenient caption helper: it casts any array to bool before it calls this core.
2. **Counts first.** One frame gives additive counts (summing the counts of two frames gives the counts of both together); numbers are computed from the counts of any set of frames. So a dataset number is a sum over frames, never a mean of per-frame numbers.
3. **Nothing to judge is nan.** A ratio with denominator 0 is nan, never 0 and never 1 (nothing to find: recall is nan; nothing predicted: precision is nan). f1 needs both precision and recall, so a model that predicts nothing has f1 nan (and iou 0, recall 0): look at recall. Summing counts first means nan shows only where there is truly nothing.
4. **No hidden constants.** Thresholds, tolerances and the range of a metric are arguments.
5. **Wrong shapes are errors.** Maps of different shapes (also ones numpy would broadcast), a mis-shaped flags array, more true positives than ground-truth boxes: `ValueError`, not a plausible number. Inputs are never changed.

## maps.py
Maps are boolean arrays of one shape; `valid` (optional) restricts what is counted.
- `confusion(pred, gt, valid)` -> `[tp, fp, fn, tn]` (int64, any rank). `scores(counts)` -> iou = tp / (tp + fp + fn), precision = tp / (tp + fp), recall = tp / (tp + fn), f1 = harmonic mean of the two.
- `tolerant_confusion(pred, gt, tol_cells, valid)` (the dilation and `tolerant_counts(pred, gt, near_gt, near_pred, valid)`, the counting) -> `[p_hit, p_miss, g_hit, g_miss]` for thin structures that cannot be hit cell by cell: a predicted cell is a hit if a ground-truth cell lies within `tol_cells` of it (centre distance, a disc), a ground-truth cell is hit if a predicted cell lies within `tol_cells`. Tolerance 0 is the plain comparison and works for any rank; a tolerance above 0 needs 2-D maps; a negative one is refused. The dilation uses the whole maps, `valid` only chooses what is counted. `tolerant_scores(counts)`: precision = p_hit / (p_hit + p_miss), recall = g_hit / (g_hit + g_miss), f1 from both, iou = tp / (tp + p_miss + g_miss) with tp = (p_hit + g_hit) / 2.
- `dilate(mask, radius_cells)`: the disc dilation both use (2-D; a radius that is an integer up to float noise, like 0.3 / 0.1, is that integer).

## boxes.py
A box is a dict: `cx`, `cy` (m), `length`, `width`, `yaw` (rad) or `radius` (a circle, for pedestrians), `vx`, `vy` (m/s, optional), detections also `score`, and `group` for the callers that split by class. Every function sees ONE class.
- **`match(dets, gts, thr)`**, one frame. Detections are taken best score first. Each takes the nearest ground-truth box that no better detection has taken, if its centre lies within `thr` metres; otherwise it is a false positive. Returns the ground-truth index per detection (-1 = false positive). A distance of exactly `thr` is a hit; of two free boxes exactly equally near the later one is taken; a box with a nan centre is never in reach; a nan score is refused. **Equal scores are served in list order, and that order can decide which of two detections becomes the true positive** (ground truth at 0.0 and 1.9, threshold 2.0, detections at 0.4 and -0.3 with the same score: AP 0.10 in one order, 1.00 in the other). A detector that gives many detections the same score has an average precision that depends on the order of its output.
- `match_frames(frames, thr)`: `match` over many frames, rows in global score order. Frames do not compete, so this equals one global matching.
- `match_flags(dets, gts, thresholds, tp_threshold)`: the rows of one frame: a 0 / 1 flag per detection and threshold, and the `tp_errors` of the matches at `tp_threshold`.
- `tp_errors(d, g)` of a matched pair: **ate** distance of the centres; **ase** 1 - IoU of the two boxes after aligning centre and heading (circles: 1 - (r_min / r_max)^2, a rectangle counts as a circle of radius max(length, width) / 2); **aoe** smallest yaw difference in [0, pi] (nan for circles); **ave** length of the velocity difference (nan if a velocity is missing on either side); **biou** oriented BEV IoU as the boxes are (shapely; a circle is a polygon of 128 vertices). A pair with a circle is compared as two circles in every measure, biou included. A box of size 0 gives ase nan and biou 0; a nan in a box's geometry gives nan where it is used (biou nan), never an exception.
- `ap_nuscenes(flags, n_gt)`: the nuScenes devkit's average precision. `flags` are 1 / 0 per detection in descending score order. Precision at the 101 recall values 0, 0.01 ... 1 by linear interpolation (`np.interp`: 0 beyond the last recall reached, no monotone envelope; on a recall plateau that sits on a grid value it takes the precision after the last detection of the plateau), recall up to 0.1 dropped, 0.1 subtracted from the precision (below 0 counts 0), mean over the rest divided by 0.9. `ap_all_points(flags, n_gt)`: the area under the precision-recall curve with the monotone envelope. Both: nan without ground truth, 0 with ground truth and no detection, an error if the flags hold more true positives than `n_gt`.
- `detection_numbers(scores, flags, errors, n_gt, thresholds, tp_threshold, ties)`: the numbers of one class from the rows of ANY set of frames put together: `ap@t`, `ap_all@t` per threshold, the plain mean of the TP errors at `tp_threshold` (nan skipped), `n_tp`, `n_gt`, `n_det`. Rows with equal scores have no natural order and the average precision depends on it: `ties="pessimistic"` (default) puts the false positives of a score before its true positives at every threshold, so the numbers are a function of the set of rows whatever the order of the frames (which detection of a frame is a true positive was decided by `match`, see above); `ties="list"` keeps the given order (frame order, then detection order), which is what the BEV system's `DetMeter` does.

## metrics.py
`MapMetric(extract, name, tolerances)`: iou, precision, recall, f1 (key suffix `@t` for a tolerance t > 0); support of a frame = its ground-truth cells plus its false positives (a hallucinated frame counts, an empty one does not). `BoxMetric(extract, classes, name, thresholds, tp_threshold, ties)`: per class `car/ap@2`, `car/ap_all@2`, `car/ate` ..., and over the classes `mAP`, `mAP_all`, `mATE`, `mASE`, `mAOE`, `mAVE`. The mean TP errors are plain means over the true positives at `tp_threshold` and over the classes - **not the devkit's TP metrics** (a cumulative mean over recall) and not comparable with published numbers. A class with ground truth and no true positive counts 1.0 (the devkit's value), so that a class that is not found does not drop out of the mean and improve it; a class whose error is nan by definition (aoe of a circle) is skipped. Boxes of classes not listed are ignored.

## Using it
```python
from evalsuite.comparison.metrics import MapMetric, BoxMetric

def extract(sample, pred):                    # the parsing: yours
    return pred.outputs["mask"], sample.reference["mask"]          # or (pred, gt, valid)
metrics = [MapMetric(extract, name="seg", tolerances=(0, 2))]      # iou, precision, recall, f1 and iou@2 ...

def extract_boxes(sample, pred):
    return pred.outputs["boxes"], sample.reference["boxes"]        # lists of box dicts of ONE frame
metrics = [BoxMetric(extract_boxes, classes=("car", "pedestrian"))]    # car/ap@2, ..., mAP, mATE ...
```
Without the suite, the functions are used directly: `maps.scores(maps.confusion(pred, gt))`, `boxes.ap_nuscenes(flags, n_gt)`.

## How it is checked
`python -m evalsuite selftest comparison` (`../selftest_comparison.py`). Every function is checked by hand cases, against an independent brute-force implementation written in plain loops (no code shared with the core: distance search for the tolerant counts, the textbook all-point AP, the devkit's interpolation written out), against the real nuScenes devkit's `accumulate` and `calc_ap` (skipped if the devkit is not installed), and against `_REF`, a frozen copy of the code the BEV system used before this core existed. The random data have ties on purpose (integer coordinates, scores in fifths). Two `Metric`s run through the whole suite and equal the core applied by hand, including every aggregated number. `mutation_check.py` (slow, run it when the core changes) breaks one rule at a time in a copy of the suite - deliberate mistakes such as a swapped fp / fn, a strict instead of an inclusive threshold, a missing recall bin, optimistic ties, a mATE built from the wrong error - and demands that `selftest comparison` fails every time with a failed check (not a crash).

## What a reviewer should look at
- **Where the rules differ from the nuScenes devkit** (all three only matter at exact ties; on data without them the average precision is identical to the devkit's, tested on random frames): a distance of exactly the threshold is a hit here (the devkit's `<` says no); of two free boxes exactly equally near the later is taken (the devkit takes the first); equal scores are served in list order here (the devkit serves the later one first). The first two are the BEV system's rules, pinned by its own tests.
- `ties="pessimistic"` is new; `ties="list"` is what the BEV numbers have always used (and what `DetMeter` passes). The mean TP errors are summed in rank order, which keeps the BEV numbers bit for bit (pinned by an exact-equality test and a mutant).
- `maps.tolerant_counts` exists for callers that count one pair of maps under many `valid` selections (the BEV range bands): they dilate once. Its dilations are the caller's responsibility, only the shapes are checked.
- The mean TP errors are not the devkit's (see `metrics.py` above); the "class not found = 1.0" rule is `BoxMetric`'s, `DetMeter` drops such a class from the mean.
- `tp_errors` needs shapely only for `biou`. The circle polygon (shapely `buffer(r, 32)`, 128 vertices) approximates the circle from inside, its area is 0.04 % too small; the IoU of concentric circles is exact (measured), of offset circles it is off by about that much at most.
- `ase` for rectangles ignores height (bird's-eye view); the devkit's scale error includes it.
- `f1` of a model that predicts nothing is nan (rule 3), as in the BEV evaluator; the count formula 2 tp / (2 tp + fp + fn) would give 0 there.
