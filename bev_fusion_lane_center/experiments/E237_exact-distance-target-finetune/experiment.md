- **Statement**: Fine-tuning j1 192 / 96 for 4 u at recall weight 1 with the CPU-exact distance map as the seed / direction / builder target gives a Q on VAL 873 (fork pruning 0.4) at least +0.005 above the same fine-tune on the stored TF32 map, mean of two seeds.
- **Mechanism**: the stored `train_gt_dist_exact.npy` has errors up to about 4.5 px (2.2 m) on 3-14 % of pixels near lines (E235.chk2/chk3), in both directions: it puts false line pixels and moves true ones. The distance map is the target of the seed loss, the direction loss and the builder's own loss, and the same damaged file supervised the dense heads. Wrong targets within about 1 m of the lines blur exactly the margin that decides F1@1 and the coordinates of seeds; correcting them should help F1@0.5 / F1@1 slightly. The effect has never been measured: every loop-16 to loop-18 number, champion and the recall variants included, shares the damage, so the comparison with b456 (exact) later would confound data size with target quality.
- **Prediction**: Q(a) - Q(c) = +0.002 (mean over seeds; a tie is the most likely outcome because the base j1 was trained on the stored map, only the 4 u fine-tune sees the corrected target, and the dense-head heat that enters the builder as input stays trained on the damaged map); F1@1.0 +0.003. The seed twin gives the noise: j1eq Q 0.735 vs j1eqs1 0.731 (spread 0.004).
- **Decision rule**: KEEP (exact targets matter; D10 option b: switch all training to the exact file, re-train the controls on it) if Q a - c >= +0.005 with both seeds on the same side (decide.py `--experiment`) and F1@1.0 not lower by more than 0.005; CUT if Q a - c <= -0.005 (then first look for a loader error, see kill); TIE otherwise: keep the stored map for the history (D10 option c is cheap), state that the finding is closed only for the fine-tune stage and not for the dense head, and that b456 and b123 targets differ by this amount at most. INCONCLUSIVE (seeds on different sides beyond the band) means a third seed pair, not adoption.
- **Test design**: arms a (exact, seeds 0 / 1) and c (stored, seeds 0 / 1; already trained, the recipe is the one in `experiments/E219_recall-weight-finetune-under-pruning/code/_run_j1eq.sh`, same init `e123_D7_r3_j1`, lr 0.0005, stem_lr 0.3, warm_frac 0.4). Controls: equal budget and matched reference = j1eq / j1eqs1 on the same 873 frames and the same assembly; seed twin = the two seeds; null = j1 itself (Q 0.728, fast); oracle-style sanity = layer-1 test that the switched loader pointed at the STORED file returns bit-identical batches to the unswitched loader. Step 0 (CPU, 10 min): share of supervised pixels (distance below 4 m) that differ between stored and exact by more than 0.25 px, per frame, over the train part, and the same weighted by the loss region; this measures the exposure and goes into the summary whatever the result. Fidelity rung: layer 3-4 (VAL 873, two seeds, paired scene bootstrap).
- **Cost**: 2 x 27 min = 0.9 GPU h (two jobs side by side if the 9 GB cap allows, else sequentially) + evaluation 10 min CPU; CPU for the new train-part map (`make_dist_gt.py --cpu`, tens of minutes, a NEW file; the old stays). Coding: 0.2 day (the loader switch, an ar-reviewer pass in mode code because `p16_data.py` is shared). Risk: a null result is the likely one, which closes D10 cheaply.
- **Kill criterion**: stop after the first seed if the loader test (stored file through the switch) fails, or if the arm's Q on val250 at the end of training is below j1eq - 0.02 (suspect the file / orientation of the new map before blaming the target); do not start the second seed then.
- **Inputs**: ready: j1 init, j1eq / j1eqs1 cards, p16_train.py, p18_variant_prune.py.
