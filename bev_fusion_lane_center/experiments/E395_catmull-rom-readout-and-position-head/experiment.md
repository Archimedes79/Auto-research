# E395 - Catmull-Rom curves through the nodes: the read-out (step 1), a position head trained on the curve (step 2), soft neighbours (step 3)

**Version 1 (2026-11-24, system clock), the owner's order D142 (the analysis of 2026-11-23: `tools/curve_repr_check.py`, memory note lane-catmull-rom-check-2026-11-23); written BEFORE any step runs; nothing run yet.** The idea of the owner: every lane section is a Catmull-Rom (CR) spline whose control points are the nodes, the nodes exchange information along the spline and move so that the spline is right, trained end to end on the curve. The analysis found: CR needs 22 - 29 % fewer nodes than a polyline for the same tolerance and Hermite with the TRUE heading about 65 % fewer; at 7 m spacing the CR curve is 58 % more accurate than a polyline for exact nodes and 4 % worse at node noise 0.5 m; the B' token position error (VAL, 37 627 nodes) is lateral rms 0.48 m (0.36 m at 0 - 15 m, 0.65 m at 50 - 100 m ego range) and correlated between neighbours (0.52 at 2 m, 0.34 at 10 m) and between lanes (0.26 - 0.33 at 2 - 6 m). So the geometry error of the nodes, not the curve family, limits the system; this card tests whether the curve view (read-out, curve loss, neighbour information) lowers it.

## 1. Card text
### 1.1 The change in detail
- **Catmull-Rom curve (uniform, tau = 1/2), the one function of the card (`jcr_eval.cr_segment` / `jtoken.cr_points`):** a segment from node P1 to P2 with the ghost nodes P0 (before P1) and P3 (after P2): `C(t) = 0.5 * ((2 P1) + (-P0 + P2) t + (2 P0 - 5 P1 + 4 P2 - P3) t^2 + (-P0 + 3 P1 - 3 P2 + P3) t^3)`, t in [0, 1]: it passes through P1 (t = 0) and P2 (t = 1), the tangent at P1 is (P2 - P0) / 2. A missing ghost is the reflection (P0 = 2 P1 - P2, P3 = 2 P2 - P1). The curve is linear in the nodes.
- **Step 1 read-out (`jcr_eval.step1`, CPU, no training):** for every delivered link (i -> j) of the prediction (`jtoken_eval.frame_prediction` at the D115 cell): P0 = the delivered predecessor k of i (a link k -> i) with the smallest turning angle between (P_i - P_k) and (P_j - P_i), else the reflection; P3 = the delivered successor l of j with the smallest turning angle between (P_l - P_j) and (P_j - P_i), else the reflection; the curve is sampled with max(2, ceil(chord / 0.5 m) + 1) points uniform in t and given to the scorer as `links['curves']` (the scorer uses a given curve instead of the Hermite one, `qgraph_eval` line 88). Modes: **H** the record (curves None), **P** the straight chord sampled at 0.5 m (the null: does the curve shape matter at all), **CR**. Oracle modes on the cache dump of c (the tokens carry `gt_id`): **OLAT** every delivered token with a GT node (`gt_id >= 0`) moved to P + ((G - P) . n) n with n = the rotation by 90 degrees of the token's `dirv`, **OFULL** moved to the GT node G; each read with H and with CR.
- **Step 2 position head (`jtoken.JTokenHead(pos_head=True)`, default off = the champion bit for bit, no extra parameter and no extra output key):** built LAST (a seeded init of every other parameter is unchanged): `dpos = 3 m * tanh(MLP(xn) / 3 m)` on the final features after the last layer (an MLP d -> d -> 1, GELU, the last Linear zero-initialised: the head starts at the B' position), `out['dpos']` (B, K); the refined position `P' = pos + dpos * n`, n = the rotation by 90 degrees of the token's `dirv` (an input, no gradient into it). Only the normal offset moves: sliding along the lane does not change the curve to first order, and the lateral error is the one that is large (rms 0.48 m, longitudinal 0.30 m).
- **Curve loss (`jtoken_loss(curve_w=)`):** per frame, per GT link (u -> v) of the frame's GT table with the GT ghost nodes (the GT predecessor of u and the GT successor of v that continue most straight, reflection when missing) and with the best token of every GT node (the valid token with `gt_id` = that node and the smallest `gd`; a link with a missing node is left out): the refined positions P' of the four tokens give the predicted curve, the four GT nodes the GT curve (both Catmull-Rom); at t in {0, 1/4, 1/2, 3/4, 1}: `rho(((C_pred(t) - C_gt(t)) . n_gt(t)))`, n_gt = the normal of the GT curve at t, rho = smooth L1 with the knee at 0.5 m; mean over the links and the five t. The loss is quadratic in the node errors of four neighbours (the curve is linear in the nodes), so a node is pulled by the errors of its two neighbours on each side: the gradient is the sum of the residuals of the four incident segments, weighted by the Catmull-Rom basis. `--node-w W` instead: `rho((P'_g - G_g) . n_g)` per best token (t = 0 only, no neighbours). The weight 0.5 is ONE value, not tuned.
- **Data (`lane_ptok_data`, new label keys only):** per frame `gt_pos` (Ng, 2) the GT node positions, `gt_dir` (Ng, 2), `gl_u`, `gl_v`, `gl_pre`, `gl_suc` (Lg,) the GT links and their ghost nodes (-1 = none), `gt_btok` (Ng,) the best token of every GT node (-1 = none), all padded to 512 and masked; no model input reads them (like `gt_id` / `gd`).
- **Dump and scoring:** the dump carries `dpos` per token (additive key); `jcr_eval.py step2 --run p0_s<S> --seed S` writes the refined positions into the tokens before `frame_prediction` and scores H and CR connectors at the D115 cell with the standard scorer (`score_preds`); the jarm cards of the same run (unmoved nodes) are the topology of the head and are reported next to them.
- **Not changed:** the wiring read, the types, the decode thresholds (D115), B', the caches, the data order.

### 1.3 The verdicts (by hand, written before any run)
- **Step 1 (per connector X in {P, CR} against H, both seeds, deciding metric F1@1.0, guard topo F1):** D = F1@1.0(X) - F1@1.0(H) from the same dump, with the paired scene-bootstrap interval of `QE.paired`. **CR-GAIN:** D >= +0.010 on both seeds with the interval above 0 and topo F1 not below H by more than 0.010. **CR-LOSS:** D <= -0.010 on one seed and not >= +0.010 on the other, or topo F1 below H by more than 0.010. **TIE:** everything else; on a TIE the Catmull-Rom read-out is the SIMPLER one (no heading, no handle scale needed for the curve) and is reported as 'replaces the Hermite connector at no cost' only when D >= -0.003 on both metrics and both seeds. The oracle modes are read for the HEADROOM, no verdict: H10 = F1@1.0(OLAT + CR) - F1@1.0(H), H05 = F1@0.5(OLAT + CR) - F1@0.5(H) (cache dump, per seed).
- **Step 2 (arm X in {p0, p2} against its control c / r2, both seeds; scored with the same connector as the control, H, nodes moved by the head):** D05 = F1@0.5(X) - F1@0.5(c), D10 = F1@1.0(X) - F1@1.0(c) with the paired intervals. **The bar** (derived from step 1 before any training; the E391 form: the strongest null plus a quarter of the headroom): **D05 >= 0.25 x H05** and **D10 >= 0.25 x H10** on both seeds, both paired intervals above 0. **KEEP-quality:** the bar on both seeds, the guards hold (topo F1 not below c by more than 0.010, lanes found by more than 0.010, junction F1 by more than 0.015) and the kill is clear. **CUT:** D10 <= -0.010 on one seed (the refinement hurts) or a guard fails on both seeds. **INCONCLUSIVE:** a kill other than the cut ones fires, or the two seeds disagree beyond the band (one D10 >= +0.010, the other <= -0.010). **TIE:** everything else. The node-error read (`jcr_eval.py nodeerr`: lateral rms of the matched nodes before and after, by ego range 0 - 15 / 15 - 30 / 30 - 50 / 50 - 100 m, and the correlation of the remaining error between nodes 2 - 10 m apart) is reported for every arm and is NOT a verdict.
- **The ladder of the position arms (what carries the gain):** p0 - p0n is the effect of the CURVE loss against plain node regression (a diagnostic: D05 >= +0.005 on both seeds = 'the curve loss helps beyond regression'); p2 - p0 is the effect of the message rounds (same reading; r2 itself was not adopted because of its cost, +2 ... +4 ms, so a p2 gain is reported with the cost of the rounds). Adoption of any arm needs its own cost check (ms per frame, `jtoken_eval.py timing`, as E392 section 1.3) and is the owner's.
- **Cost:** the position head is d x d + d parameters (about 4 k) and one MLP per frame; measured in the same session as c when an arm is a KEEP candidate.

### 1.4 Predictions (guesses of the author, before the runs)
- Step 1: CR and H differ by at most 0.004 in topo F1 and 0.006 in F1@1.0 (P(TIE) about 70 %, CR-GAIN 10 %, CR-LOSS 20 %: a derived tangent is worse than a learned heading at the long links); P differs from H by less than 0.01 (the curve shape matters little at the present node accuracy). H05 (lateral oracle): F1@0.5 from about 0.64 to 0.80 or more, H10: F1@1.0 from 0.846 to about 0.90 (the lateral error rms 0.48 m is the cause of the F1@0.5 / F1@1.0 gap, F1@1.5 is 0.92).
- Step 2: p0 recovers about a fifth of the lateral headroom (D05 +0.03, window 0.00 ... +0.07; D10 +0.02, window -0.005 ... +0.04); the guards hold (topo F1 +0.005, window -0.006 ... +0.01); p0 - p0n small (+0.00 ... +0.01); p2 - p0 +0.01 (window -0.01 ... +0.03). P(KEEP of p0) about 35 %, TIE 45 %, CUT 10 %, INCONCLUSIVE 10 %.
