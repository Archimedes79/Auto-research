# 2504.00559 AttentiveGRU: recurrent radar BEV memory without ego-motion input

|---|---|

| verdict | watch (a GRU memory on a radar BEV with learned alignment; one author is the user, Mirko Meuter) |

**What it does**: A memory BEV buffer, the present BEV frame and M=32 learnable latent queries enter a fusion block (3 blocks, 96 queries, width 64). Each query attends to present and memory features jointly ("Concurrent Cross Attention"); a sigmoid output thresholded at its median gives binary gates that pick locations from each state per query. Overlapping regions are fused with 1x1 conv gates, non-overlapping regions with a deformable conv (kernel 3) whose learned offsets follow the object's motion. No ego pose or motion input: the learned sampling is said to adapt to both object and ego motion. The fused output becomes the next memory (one buffer, recurrent).

**Results that matter** (nuScenes radar-only, car class): CenterPoint Transformer 32.4 mAP / 43.4 AP4.0; AttentiveGRU on an FPN 36.9 / 46.7 (+14 % relative); with CenterPoint Transformer 39.2 / 50.4 (+21 %). T=2 on nuScenes, T=12 on a proprietary set; one 2080Ti, batch 1. The gain is largest for moving classes (bikes); the transformer baseline is better for large and stationary vehicles. No numeric ablation, no latency, parameter or memory figure.

**Transferable technique**: per-query gated state integration with a deformable offset instead of a fixed warp; a recurrent radar-BEV memory that does not need an ego pose (useful when odometry is noisy). The authors note that the premise fails under sudden acceleration or braking.

**Cost and fit**: Small channel width (64), one memory buffer; cost not reported. Radar-only, sparse BEV, detection (cars), not lanes.

**Doubts**: nuScenes evaluated on the car class only; no ablation numbers; no cost; ego-free alignment is weaker than an exact ego warp when the pose is known (as in our case).
