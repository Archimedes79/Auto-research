# evaluation - metrics of the BEV system (plan.md 8.3 "Metrics", 8.4 "Metrics reported next to the losses", 10)

Metric code only, never used for training; every number of a model comes from here (no private metrics in tests or scripts). Plain numpy (+ shapely for the oriented BEV IoU, torch only for the latency helper). Run the self-test from the bev_fusion folder: `wsl ~/miniconda3/envs/gcar/bin/python evaluation/metrics.py`.

| file | content | self-test (known answers) |
|---|---|---|
| `evaluate_run.py` | the evaluation of a training run (`runs/<name>`): last checkpoint under its EMA weights, every val keyframe (or `--n` spread over all val scenes) at dt -0.5 / 0 / +0.5 s with the true keyframe gap; SegMeter on the camera cells (`fov`) and on the camera-or-radar cells (`seen`): areas, line masks, line zero crossings, dense objects, known / unknown by splat mass; DetMeter on the decoded object head (threshold 0.05, top 100); `--prior N`: the prior-map baseline (per-cell GT mean over N train keyframes); `--images N`: result images (camera, GT, prediction at dt 0 and +0.5 s with boxes, drivable error map, splat mass); `--time`: batch-1 latency (only valid on an idle GPU; the GPU load is recorded); `--compare a b`: paired scene bootstrap of the headline numbers (drivable IoU, lane-divider zero-crossing F1, vehicle coverage IoU, vehicle / pedestrian AP@2). Output: `runs/<name>/eval/` (metrics.json, table.txt, scene_records.pkl, images/) | uses the metrics above; tested end to end on a 3-step and the t1 checkpoints (2026-10-26) |
| `observe_run.py` | observability of a run (`runs/<name>/observe/`): every N-th val frame (`--every 20 --max 12`), or the middle keyframe of each scene (`--per-scene --max 30`), through the model with forward hooks on the stages; per frame `stages.png` (input, camera-head depth and uncertainty, lift energy and heights, camera BEV before / after temporal fusion, radar raster and branch, trunk PCA, GT boxes dashed on every BEV panel) and `outputs.png` (GT, prediction, drivable error, vehicle footprint, dt +-0.5 s with unknown cells, splat mass, scores, GT vs predicted speed); a table of automatic plausibility checks (heuristic flags); `index.html` with a guide to every panel. `--video SCENE` (or auto): all keyframes of one scene in order with the world memory carried over, one dashboard per frame, `video.mp4` | run by eye on the t1 runs (2026-10-30); no known-answer self-test (a viewer, not a metric) |
| `metrics.py` | `SegMeter`: tolerant IoU per layer, range bin (0-20 / 20-40 / 40-60 m by cell x), tolerance (0 / 0.5 / 1.0 m, dilation), defined-cell mask, known / unknown cells from the splat mass (dt != 0); `add_lines`: line cells decoded from the distance field (minimum across the line), F1 / precision / recall at the same tolerances and the field error near the line. `DetMeter`: nuScenes-style detection in the front field of view up to 60 m - AP per class at 0.5 / 1 / 2 / 4 m (nuScenes 101-point AP with the 0.1 clips, and the plain all-point AP), TP errors at 2 m (ATE, ASE, AOE, AVE, BIoU), per range bin and per dt; circles for pedestrians. `ms_per_frame`: latency (warm-up, CUDA synchronize, median over N, batch 1; only on an idle GPU). `report` / `format_table` / `flatten` / `unflatten`: flat dict `task/dt+0.00/.../metric` and a printable table. `gt_boxes_from_meta`: training/gt_bev.py boxes -> box dicts | perfect -> IoU 1, AP 1, errors 0; 1-cell shift: IoU 90/110 at 0 m, 1 at 0.5 m; mask, known / unknown split; line F1 perfect / shifted; empty prediction AP 0; 90 deg rotation: AOE pi/2, ASE 0, BIoU 0.25; ASE by hand (box, circle); two-detection ranking: nuScenes AP 8.2/81, all-point 0.25; range bins of cells and boxes; field of view; dt-keyed round trip; latency runs. The all-point AP equals `tests/test_object_head.py` evaluate() on random synthetic detections (difference 1e-16) |
