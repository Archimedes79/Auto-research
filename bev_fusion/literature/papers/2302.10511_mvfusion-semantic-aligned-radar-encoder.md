**What it does**: Radar points are expanded to 3 m high pillars and projected into each camera view. The input per view is a 5-channel radar map: a position mask, distance, RCS, and radial velocity along X and Y (compensated velocity is not described). The back view receives blank radar because there is no coverage. A semantic-aligned radar encoder (SARE) concatenates a 1-channel foreground-mask-like indicator, computed from multi-scale image features, with the radar channels; the radar-guided fusion transformer uses concatenated radar + image features as queries and image features alone as keys / values (radar-only queries with image keys were unstable in training).

**Results that matter** (nuScenes val, NDS / mAP): baseline 0.457 / 0.406; SARE only 0.467 / 0.415; RGFT only 0.465 / 0.414; both 0.475 / 0.421. Semantic indicator alone 0.470 / 0.419. Test 51.7 NDS / 45.3 mAP (V2-99, DD3D pretrained). No ablation of radar attributes.

**Transferable technique**: the per-view radar image keeps sensor direction by construction (the radar is rendered in the camera's own pixel grid, so azimuth equals image column) - the one place in this set of papers where the viewing direction is explicit. Using image-derived foreground evidence to gate radar channels is a cheap cross-modal alignment (+1.0 NDS).

**Cost and fit**: small; needs the front camera view of a single image only. Gains are modest (+1.8 NDS in total).

**Doubts**: baseline is a PETR-style camera detector at 0.457 NDS; no timing; velocity compensation unspecified.
