# nuScenes - raw data shared by all problems

This folder (`datasets/NuScenes/`: the README and the tools are in git as recipes, the data itself is not: it is on D:) describes the raw nuScenes data and holds the download / copy / check tools. Licence: nuScenes is for non-commercial use; downloads only with Mirko's OK.

## Rule (Mirko, 2026-10-25)
- RAW data only on D:, in `D:\Auto-research\NuScenes` (WSL: `/mnt/d/Auto-research/NuScenes`): exactly what the nuScenes archives contain, plus the archives themselves. Nothing generated is written there.
- DERIVED data (info files, filtered radar, GT, caches) belongs to the problem that makes it, in its project folder on C: (e.g. `bev_fusion_lane_center/data/nuscenes_additions/`, later `bev_fusion/data/`), listed in that project's `data/README.md`.
- The bird's-eye GT made from this data (map layers, objects, velocity / flow) is generated by `autogt/` (repository root): `autogt.generate("~/data/nuscenes_full")` reads a nuScenes folder and writes the GT of every keyframe to `data/autogt/<signature>/` (or `out=`).
- Existing code reads `~/data/nuscenes_full` and `~/data/nuscenes` (mini). These are WSL "views": folders of symlinks only, raw entries -> D:, the lane project's additions -> its project folder. Built by `tools/link_views.sh`; re-run it after the repository folder or the D: root moves (the links are absolute).

## Tools (`tools/`)
Google Drive helpers (2026-10-26): `list_gdrive_folder.py <folder id>` lists a public Drive folder (names, ids; listing only), `gdrive_size.sh <file id>` gives a file's size from a header request, `get_gdrive_file.sh <file id> <dest>` downloads one file resumably and checks its size (and gzip integrity); `history/get_occ3d_labels.sh` is the one-off that fetched the Occ3D labels.

| tool | what it does |
|---|---|
| `list_nuscenes_bucket.py [filter]` | lists the archives of the public bucket `motional-nuscenes` with size and ETag (no download) |
| `get_blob_part.sh <part> <camera\|lidar\|radar>` | downloads one part (resumes a partial archive), checks the S3 ETag, unpacks it with `extract_blob.sh`, marks it `.unpacked`; environment `NUSC_DL` (download root, required) and those of `extract_blob.sh` |
| `get_parts_parallel.sh <kind> <part>...` | several parts in parallel (one connection gets 1-2 MB/s, six together about 6 MB/s) |
| `extract_blob.sh <tgz> [--delete]` | path check (no absolute or `..` paths), then unpack; `NUSC_DEST` target (required, on D:), `NUSC_MEMBERS` (e.g. `sweeps`), `NUSC_WINTAR=1` unpacks with Windows `tar.exe` (fast on D:; WSL writes small files there at only about 50 per second) |
| `verify_s3_etag.py <file> <etag>` | checks a file against a plain or multipart S3 ETag |
| `link_views.sh` | builds the WSL views (above); moves the former WSL copies to `~/_to_delete/`. It refuses while a process has a file of a view open; the guard matches the link targets (`/mnt/d/Auto-research/NuScenes/nuscenes_full/*`, `.../nuscenes_mini/*`, the additions folder), because an open file reached through a view resolves to them in `/proc/*/fd` (fixed 2026-10-31: the former guard matched `~/data/*` only and never fired); `--selftest` holds a mini-view file open and checks that the guard sees it |
| `stop_downloads.sh` | stops running downloads (partial archives are kept) |
| `datasets/NuScenes/_to_delete/` (not the one on D:) | moved out on 2026-10-31, listed in its README: `move_additions.sh` (superseded by `link_views.sh`) and the identical copies of `list_nuscenes_bucket.py` / `verify_s3_etag.py` from `history/` |
| `history/` | one-off scripts of 2026-10-25 (first download run, D: speed test, copy to D: / C: with manifests, `verify_copy.ps1`, `sample_checksums.sh`, self-test of `extract_blob.sh`) |
