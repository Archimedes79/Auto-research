## Front GT (hashed): findings for the NEXT front version (each edit re-signs `6a7aa7864a`, rebuilds the front store (5-8 h) and the BEV GT cache; needs Mirko's decision)
Verified correct (no action): box left / right against the image (614 / 614), time base, `records_in_patch` = devkit, float16 (no overflow, error <= 0.016 m/s), no NaN, speeds <= 20.7 m/s.
Output defects (all change the stored GT; none hurts a current consumer):
1. `nuscenes_gt.py:359` `yaw - yaw_e` is not wrapped: 25 - 30 % of boxes have |yaw| > pi (range +-2 pi); consumers that use sin/cos or remainder are fine. Fix: `math.remainder(..., 2*pi)`, or state the contract.
2. `:313` stationary boxes return "ok" before `o.flag` is read: `stationary_but_moving` never reaches the GT (0 of 10,585 stored boxes), 455 of 2,573 stationary objects are unobserved but "ok".
3. `:100` `flow_sigma = 0` on cells of observed boxes with unknown velocity (flow_weight is 0 there, 1/sigma would be inf).
4. `:318` unknown velocity is stored as (0, 0) with vel_sigma NaN (42 of 10,585 boxes): `bev_fusion/evaluation/metrics.py:222` passes vx = 0 on without looking at vel_known (AVE numbers not checked).
5. meta["boxes"] holds every box of the 3 classes (59-65 % lie outside the grid), AGENTS.md says "in range": doc fix. 6. velocity at the border of two moving boxes is a blend (0.14 % of cells). 7. centreline_dir is a mean, not a unit vector, where
lines cross (norm down to 0.04). 8. theoretical misses (a divider without a node in the patch; radar pass 2 gating out all detections).
Speed (output identical, measured on mini, ~270 ms per keyframe): C1 lane_connector falls back to the devkit for all its records every keyframe: bounds from `extract_polygon` = -22 % (digest-identical on 16 keyframes of 4 maps);
C2 `coverage.blocked` only for cells on the grid and seen by the camera, one clip for the 3 heights = -13 % more; C4 prefetch the next keyframe's radar files (not measured). C1 + C2 together: about 0.78 x 0.87 = 0.68 of the time (1.5x), i.e. the 5 - 8 h trainval run takes 3.5 - 5.5 h; a thread that writes the files was measured and gives nothing (see above).
Not worth it: shapely `contains_xy` for the area layers (13 % SLOWER), a bbox prefilter for radar boxes, caching `discretize_lanes`.
Dead code (removal re-signs): `flow.py` `displace`, `_rasterise`, `FlowGT.flow_obj/weight/sigma/flow` + the grid branch, `_synthetic` / `_selftest` (110 lines, hashed for nothing: move to unhashed modules), `radar(only=)`,
`_radar_cache` (0 hits in 497 lookups), `map_offsets` (never set), `stationary_fix=False`, odd-ss branches, `RADAR_FOV` re-export, `GridSpec.centres` duplicate, `except Exception` that hid the biggest hot spot (catch ValueError).

## Lane GT (hashed): findings for the NEXT lane version l6 (new lane_center store; coordinate with the Spurmitte chat, D61)
Invariants with 0 violations on 1,708 frames x 2 rigs: unique ids, succ/pred symmetric, no dangling links, window events = open ends and on the border, points in the window, no NaN, tier_src <=> tier 1, tier_info sums,
left / right sides (left-hand traffic), visibility = brute-force rays (1 of 18,000 grazing).
1. **[GT] tiers depend on the window cut** (`lane_tiers.py:184, 209, 237` use the length of the cut part and `end_open` / `start_open`): 6,778 of 1.004 M shared points (0.67 %) differ between the rigs, 1->3 and 3->1 mostly cut artefacts. Fix: tiers on the

2. [GT] 31 % of pieces carry zero-length segments (repeated arc joints: `discretize_lanes`, `lane_graph.py:152`): "pts every 0.5 m" is false, `STEP*count` lengths over-count: drop points closer than 1e-3.
3. [GT] `lane_count` / `lane_index` are 0 on every connector-only piece (43 %): inherit or None. 4. [GT] `to_frame` uses `T[:2,:2]`: with pitch / roll the event `dirs` are not unit (5.5 % of rows off by > 1e-3, max 1.04 %).
5. Events at map gaps: 48 `in` / 20 `out` junction positions > 1.5 m from a branch end (worst 4.8 m); 9 natural ends without succ / event / window flag; 5 stop / exit events with empty in / out (the selftest claims none). 6. [GT] segment off-by-one at joints (1.3 % of
   multi-token parts). 7. 27 road / 13 intersection polygons are not valid OGC geometry (touching rings; rasterising is harmless). 8. left / right asymmetric in 0.35 %, opposite in 1.2 % of links. 9. 195 pieces re-enter the window: `piece` is not unique per frame
   (`qgraph_eval.py:178` builds ids from `piece`). Properties: blind zone < 4.5 m (tier-1 points visible 14.5 % / 0 % for lane_center / bev_fusion), tier 1 not connected in 8-9 % of frames (lane changes), no tier 1 in 1.1 - 1.8 %.
