**What it does**: Voxel features feed two MLPs, density and semantic logits. Along camera rays (nonlinear Mip-NeRF-360 sampling) transmittance and opacity give a rendered depth and rendered semantics. Depth is supervised with SILog against lidar-projected depth, semantics with cross-entropy against projected lidarseg labels; about 25,600 pixels per batch, adjacent frames add rays, moving-object classes are filtered. With 3D labels also present the rendering weight is 0.1. A depth-aware teacher-student uses unlabelled frames.

**Results that matter** (Challenge validation, mIoU): BEVStereo R50 256x704, 3D occupancy loss only 19.6, rendering only 20.2, both 21.9 (+2.3). Cumulative recipe: 19.6 -> 36.1 (visibility mask) -> 39.7 (rendering, roughly +3.6 if that row adds only rendering) -> 45.2 (bigger setting) -> 50.4 (teacher-student) -> 51.5 / 52.1 with TTA; leaderboard 51.27, 3rd place. Rendering overhead at inference: none stated, speed not reported. No split into geometric versus semantic rendering.

**Transferable technique**: rendering supervision is additive to dense labels (+2 to +4 mIoU), costs only training time, and needs only projected sparse lidar in the image (no 3D labels). Weight 0.1 next to the main loss.

**Cost and fit**: modest; ConvNeXt-B setting is large. For us the rendering has to be defined from a BEV (+ height) volume: the camera ray passes through the volume at several heights, which works for a camera-aligned BEV only with a lift MLP.

**Doubts**: checkmark layout in the tables is ambiguous; gain of rendering over a visibility-masked loss is not isolated cleanly; challenge validation split, not Occ3D val; a technical report.
