# 2211.17111 BEVPoolv2 - frustum-free pooling for deployment

| groups | F4: 2; A1: 1 |

| verdict | watch (an implementation trick, not a model) |

**What it does**: improves the LSS/BEVDet view transform by never materialising the big frustum feature (depth x channel x H x W); the pooling kernel reads the depth distribution and the image feature directly and accumulates into BEV cells with precomputed indices. Depth uncertainty is the usual per-pixel depth categorical, used as weights.

**Results that matter**: view transformation 0.82 ms at 640x1600 input, "15.1 times the previous fastest implementation" (abstract; GPU not stated on the page). BEVDet4D-R50-Depth-CBGS: 52.3 NDS nuScenes val, 16.4 FPS in PyTorch.

**Transferable technique**: if we keep a categorical-depth lift for one camera, avoid the frustum tensor: memory and time scale with (pixels x kept bins) instead of dense. Gaussian splatting (see 2504.01957) removes the depth axis altogether and is the cleaner version of the same saving.

**Fixed-geometry record**: precompute = per-(pixel, depth bin) -> BEV cell indices, computed once from intrinsics and extrinsics (as I understand the method; the page read is the abstract only); runtime = 0.82 ms view transform at 640x1600 (GPU not named); along-ray distribution = categorical depth bins (BEVDepth style); flat-ground error: none (3D bins).

**Cost and fit**: CUDA extension (custom op, needs a compile on the 3060 WSL setup); no extra data.

**Doubts**: no GPU named for the 0.82 ms; the contribution is engineering, accuracy equal to LSS by construction.
