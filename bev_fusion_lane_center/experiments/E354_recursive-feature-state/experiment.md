**What the earlier measurements say (the honest starting point).** Time was tried at OUTPUT level and closed by data, never trained: E299 step 0 (re-scoring the pairs with the warped previous logits: +0.011 pair precision at fixed recall, +0.0005 / +0.0001 snapped topo F1; three quarters of the pairs lost between two keyframes are lost because an END has no keypoint at t), step 0b (a previous keypoint, ego-warped, matches 4.83 % of the GT ends of t that are missed; a carry-over adds 5.5 false ends per true one), step 0c (adding the warped previous heat: net +0.009 end recall, 11.5 false keypoints per true one). E336 (this design) was closed on those numbers without a run. What none of them measured, and what E299 section 5c names as open: a LEARNED state at feature level, where the network decides what of the past is informative. D103 orders exactly that. The expectation is therefore modest: a small gain in topo F1 if any, and the larger effect in temporal stability (of the true pairs, 35.2 % / 33.2 % are delivered in exactly one of two consecutive keyframes on the base of this card, E341; E312: 33.1 % / 34.1 %, E299 section 4; recomputed by the critic with `jtime.py`'s functions on the stored dumps).

**Design (simple on purpose).** The junction maps head `JMaps` computes `c0 = p2(feat2)` (64 channels on the 2 m grid, 50 x 50), four dilated blocks, then the 1 m branch. New, in one module `StateFuse`:
- state `s_{t-1}` = the 2 m feature map AFTER the dilated blocks of the previous keyframe (64 x 50 x 50), kept by the caller;
- `w = warp(s_{t-1})`: bilinear `grid_sample` at `p_prev = R^T (p_cur - t)` for every cell centre of the current 2 m grid (relative pose of the two lane frames from `poses_{train,val}.npz`: `R = Rc^T Rp`, `t = Rc^T (tp - tc)`), zeros outside the old view; `valid = warp(ones)`;
- `c0' = c0 + g * conv3x3([c0, w, valid])` with `g` a per-channel gate initialised at ZERO (the start is the network without a state, bit for bit);
- the blocks, the 1 m branch, the pair head read `c0'` as they read `c0` today; `s_t` = the block output of this frame.
One input per step (the cached features of the current keyframe); the first frame of a scene has `w = 0`, `valid = 0`. Nothing else changes: the keypoints, the pair head, the read-outs and their named selections are those of E341. Cost of the module: 129 x 64 x 9 + 64 = 74.4 k parameters, 0.186 GMACs at 50 x 50 (+2.9 % of the 6.478 GMACs of the base E341; the full E312 system has 7.955), one warp, a state buffer of 64 x 50 x 50 and the ego pose of the last step as an input (odometry); no second forward pass. The warp, the state and the module run in float32 (the trainer's bf16 autocast is switched off inside them).
**Training (the gradient through time).** A training sample is a SEQUENCE of K = 3 consecutive keyframes of one TRAIN scene (never across a scene start; rows whose lane GT is missing break a sequence). Batch = 4 sequences = 12 frames (E341: 8 frames). Frame 1 runs cold (no state), frames 2 and 3 get the state of the frame before; the loss of E341 (pair loss + maps loss, `--e2e --scales --maps-w 1.0`) is taken over all 12 frames as ONE batch (a mean, as E341 takes it over its 8 frames; not a sum over the frames, which would triple the gradient: E341 trained near its clip); the backward pass goes through both state transitions (no detach). So a third of the frames train the cold start and the loss of frame 3 reaches the features of frame 1. Named difference to E341 that the control z shares: a batch holds 12 frames of 4 scenes instead of 8 independent frames. No state noise, no pose jitter (the poses are the data set's ego poses; named below as not covered).

## 1. Card text
