**What it does**: a dense transformer with two branches. The vertical branch expands backbone features into a volumetric lattice (C x Hk x Wk -> Zk x C x Hk x Wk) with 3D convolutions guided by a spatial occupancy mask and collapses height to C x Z x W; the flat branch uses an IPM homography plus a learned error-correction module. Depth is a lattice of Z bins; no explicit depth distribution, no uncertainty output. EfficientDet-D3 backbone.

**Results that matter** (nuScenes, front camera frames): semantic mIoU 33.65, road IoU 77.32, car 40.53, panoptic quality 19.84. 9.9 M parameters, 39.8 G MACs, about 240 ms per frame (roughly 4 FPS, GPU not named in the part read); the authors say the 3D convolutions are the main cost.

**Transferable technique**: flat (IPM + learned correction) branch for the road plane, which is exactly where lane centre lines live. The volumetric branch is the part to avoid.

**Cost and fit**: too slow for the "super-efficient" goal as published; useful as proof that nuScenes front-camera only is evaluable with a standard protocol.

**Doubts**: front image vs. six cameras not clear; GPU not read; no lane/divider class.
