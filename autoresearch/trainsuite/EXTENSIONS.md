## 1. Another layout of the run directory
A `trainsuite.json` in the run directory names what differs; every key is optional:
```
{"log": "metrics.jsonl", "text_log": "run.log", "loss": "loss", "steps": 3000, "progress": "it "}
```
`log` is the metrics stream, `text_log` the text output (crash detection, skipped steps), `loss` the optimised value, `steps` the total (else `config.json["steps"]`), `progress` how a progress line of the text log starts (default `"step "`, the bev_fusion trainer): a traceback counts as a crash unless such a line follows it, so a trainer that logs a handled exception and goes on is not reported failed when its own prefix is named here. Rows must be flat or nested one level (`{"val": {...}}` becomes `val.total`); strings, lists and booleans are ignored. A row without `step` is skipped. Without `t` in the rows the speed is the trainer's own `s_per_step` (an average since the process start, so a slowdown shows late).

## 2. Thresholds
Module constants in `health.py`: `SPIKE_K` 8, `RISE_K` 3, `SHIFT_K` 5 / `SHIFT_REL` 0.3, `RAMP_FRAC` 0.5, `SLOW_FACTOR` 1.5, `GPU_LIMIT_GB` 11, `DEAD_GRAD` 1e-10, `GRAD_MODULE_K` 10, `UPD_LOW` / `UPD_HIGH` 1e-7 / 0.2, `DATA_BOUND` 0.30, `REF_TOL` 0.10 / `REF_K` 3 / `REF_ROWS` 50, `MIN_ROWS` 40; `TS_STALE_S` (environment) 900 s for `stalled`, raised automatically to 10 row intervals when the rows are far apart. A validation pass or a checkpoint of a large model can be quiet for longer: raise `TS_STALE_S` for that project. The age of the last output is the file mtime against the clock of the machine running the suite: after a host sleep the WSL clock can be off by minutes and show a false `stalled` (or hide a real one); the stop protocol does not depend on clocks. Every test compares window means and uses the spread of the window, because the loss of one batch is noisy (bev_fusion: sd about 2 on a mean of 11).

## 3. Kill rules and `watch` in an agent loop
Write the kill criterion of the card as a rule in `<run>/kill.txt` before the run starts (the run directory may not exist yet: `--kill` on the command line works too). Start `watch <runs> --enforce` as a Monitor: it prints a line only on a change, so the agent is woken by a kill hit, a crash, a stall or a finished eval, not by the clock. An enforced kill writes `CONTROL` (only when the run's code snapshot has the stop check), the trainer stops at the next step with a checkpoint and exit code 75; the run is then `stopped`, never `done`. A lane script that starts the next job after a run without `.done` goes on with the next run: a stop frees the GPU for it, it does not pause the lane. The ledger note and the provisional decision (CUT) are written by the agent, not by the suite: the suite does not know the ledger. Events are also appended to `<run>/trainsuite_events.jsonl`.
Runs from a code snapshot older than this contract (no stop check in the trainer, i.e. everything pinned before commit 5d3bdae of 2026-10-31) ignore `CONTROL`: the suite reports them, refuses to write the request and says so. Rows of such a trainer have no time `t`: the speed is the trainer's own average (startup and evals included) and there is no slowdown check.

## 4. Reading curves: the bev_fusion case
`curves A B` draws `total`, every `group.*` and `grad_norm` of both runs (moving mean of 10 rows, raw faint). In the bev_fusion runs `total` is the Kendall-weighted sum with warm-ups: it falls to about 8.5 at step 500, rises to about 12.5 at step 1300 and stays there, in the reference runs too. That is not a failure (the warm-up of the dt = +-0.5 loss terms, steps 600-1200 of 3000, explains it; the timing matches, no ablation was run). The question to ask is whether a run follows its **reference** (`health --vs`), per group, and the reference must have the same ground truth and code: `t8_bevfeat_s0` is to be compared with `t8_ctl_s0`, not with `t2_ref_s0` (another ground-truth signature). Training curves are not results: the numbers come from the evaluation.

## 5. Early advice: what the calibration can and cannot say
`early.py`, roadmap P10. A hand-written kill threshold (`group.lines@1000 > 1.48`) is a guess; `early` measures instead how well "behind at f" predicted "behind at the end" on the finished pairs of the same runs root. What it does not do: it does not stop anything (advice, exit 0), it invents no threshold below 6 usable pairs (a pair whose early or final gap is exactly 0 is counted as tied, not as agreement), and it does not know whether two runs share code and ground truth: the automatic pairing is "same step total and same name prefix before the first `_`", so `--pair variant:control` is the safe way and the prefix pairing is a first look. Pairs share runs (N runs give N(N-1)/2 pairs), so the count overstates the independent evidence; the printed Wilson lower bound is the more honest number, and the agreement is conditional on the pairs that were far apart already (many arms of one tree differ by a large gap: the calibration then says little about a close call; use a `--band` of the size of the seed noise of the key, the lines of a calibration show how many pairs and how many distinct runs lie beyond it). 'Consider stopping' therefore needs the Wilson lower bound (not the point estimate) of the agreement beyond the band >= 0.8, at least 15 pairs from at least 8 distinct runs (4 runs make 6 pairs, 2 of them seed twins); with less the verdict says `not enough independent evidence`. The Spearman value is taken on pairs oriented by their final gap, so it does not depend on which run of a pair is called the variant. The key is a logged curve, not the decision metric of the card, and the verdict says so. Direction and band have no default (a loss is not higher-is-better; the lane default band 0.010 is the S band); a calibration file records both and `early` refuses a file without them or a `--band` that differs.
A `val.*` key is compared at an evaluation step both runs have (the last one at or before f of the steps; the fractions really used are printed, a run with evaluations at 1000 / 2000 / 3000 of 3000 gives nothing at f = 0.1 and 0.25 and 33 % for f = 0.5); any other key as the mean of the last 10 logged values up to f. The final gap is taken at the last common evaluation at or after 90 % of the steps. The calibration file (`--out`) records the direction, the band and, per key and fraction, the counts; `early` uses an entry only when its direction equals `--better` and its evaluation fractions lie within 2 % of the run's. The more often a trainer evaluates (every 250 steps instead of every 1000), the finer the calibration. Replay of the E241 lesson (lanes found separates at 25 %, Q does not) needs run directories of the lane project with eval rows per key: the lane `runs/` hold none with a `log.jsonl` today, the bev_fusion `val.*` keys are losses.
`--as-rule` (only for `consider stopping`) turns the lag into `key@step > control value + band` (lower is better) or `key@step < control value - band`, the form `kill.txt` takes; review it, a rule written after the control was seen is not a prediction written before the run.
