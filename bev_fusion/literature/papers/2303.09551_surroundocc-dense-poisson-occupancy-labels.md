# 2303.09551 SurroundOcc: dense semantic occupancy labels by Poisson meshing of accumulated lidar (0.5 m, +-50 m)

**What it does**: Generates dense occupancy for nuScenes from existing 3D boxes and lidar semantic labels, no extra human annotation (checked). Movable objects are cut out of every frame's lidar with the boxes; static scene and objects are stitched separately in world coordinates (objects matched across frames by box instance). Poisson surface reconstruction on the stitched points (lidar at 20 Hz, about 400 frames and 13 M points per 20-second scene) fills holes; the mesh is voxelised to a dense occupancy; each occupied voxel takes the label of its nearest labelled point voxel (the authors note that nearest-neighbour is sensitive to noise in the lidar labels).

**Format and coverage** [checked]: 0.5 m voxels, x, y in [-50, 50] m, z in [-5, 3] m, 200 x 200 x 16, 16 semantic classes + empty (class 0). The generation script is `tools/generate_occupancy_nuscenes/process_your_own_data.py` (`--to_mesh --with_semantic`); the README (2023/5/19) also releases the generated mesh vertices ("downsample it and generate occupancy labels with arbitrary resolution"). Hosting: Baidu Pan for data and models (README as fetched 2026-10-26; an older README mirror listed Tsinghua Cloud); no size stated; whether the frame is lidar or ego is not stated on the pages (OpenOcc, a sibling set, says lidar coordinates).

**Results that matter** (radar, from OccFusion 2403.01644, nuScenes val, SurroundOcc labels): adding radar to the camera model raises IoU of barrier 18.39 -> 20.46, manmade 11.49 -> 16.16, vegetation 18.47 -> 21.81, mIoU 18.88 -> 20.73. Radar helps the static structure classes at least as much as the dynamic ones.

**Transferable technique**: the label grid is the same 0.5 m as ours and x reaches 50 m (83.3 % of our 60 m x 52 m area, computed), so after one lidar-to-ego transform and a half-cell shift a column rule gives the stationary-structure map without interpolation artefacts. The mesh vertices allow any resolution but still stop where the lidar stops.

**Cost and fit**: Baidu Pan needs an account and a client; size unknown; if Baidu is not usable the script plus lidar (80.2 GB, Option B) reproduces it. Labels are dense by construction (Poisson), so far cells are less reliable than near cells.

**Doubts**: no visibility mask is released with it (no known / unknown split), so far-range cells that nobody saw are filled by the mesh; semantic noise from the nearest-neighbour step; frame and timestamp convention unverified.
