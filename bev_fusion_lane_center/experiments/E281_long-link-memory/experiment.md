# E281 Memory for the long links: the link head sees the previous keyframe's links (baseline B, D55 / D58)

Card of 2026-11-08, written by the lane chat at Mirko's pick ("Long-link memory"), revised the same day after a fresh critic pass (`ar-critic`, mode cards: REVISE, five blocking points, all checked against the sources and taken, section 8). Status: **CLOSED on 2026-11-08 by its own gate, before any code or GPU hour: the CPU pre-check P12 (section 3) gave STOP on both seeds, result in section 3a.** The previous keyframe adds at most +0.013 AUC (pooled) and +0.025 (decision band) to the current frame's long-link probability (needed +0.05), and no hand-made fusion lifts the long-link persistence by 0.10 without losing lanes found. Nothing coded, no GPU job queued. (The critic's read-only rehearsal, run before the gate was fixed, had pointed to STOP; section 8.) GPU only in Mirko's windows. No TEST. Nothing pushed.

**Why this card.** The long links (the connectors across a junction) are the weak spot of the delivered graph (E276, section 7a, P5b / P9 / P10, baseline B, VAL 873, in-sample): they are 7 - 8 % of the delivered links but 27 - 32 % of the wrong ones; their precision is 0.169 / 0.194 (the scorer's own `link_long_P` says 0.167 / 0.191); without them the topo F1 falls by 0.12, so they cannot be cut; no threshold, short or long, lifts the topo F1 above the read-out at 0.5 (P10); and **between two keyframes 0.5 s apart only 64 % / 65 % of the delivered long links persist** (both ends moved by the ego motion, a delivered link with both ends within 2 m in the next keyframe), where the GT keeps 98 %. Near an intersection all links flicker four times as much as elsewhere. This is what Mirko saw in the videos. The head looks at one frame at a time and decides each long link again from nothing. The card lets it see the previous frame's links.

**Two readings, and the pre-check tells which holds.** **H1** the errors of a long link are partly independent from one frame to the next (noise of the features): the previous frame's probability for the same link carries information about whether it is right, so a memory improves the quality AND the stability. **H0** the errors are systematic (the same wrong link is predicted frame after frame): a memory would make the graph more stable but not more correct. Under H0 a stability gain is still possible and is what Mirko asked for, but then it is a smoothing of the output that a hand-made read-out can do without any training (arm h); the learned memory is only worth building under H1. **Competing lever (prior art):** E274 arm p trained a dual-softmax competition loss over the long-link candidates and raised the long-link precision from 0.18 to 0.22 and the topo F1 by +0.025 / +0.020 over arm r, without a junction gain and with the exact-map guard broken against c (E274 section 7); it was not adopted. A memory is a different way to the same goal and has to beat B, not E274.

**D55 status.** The forward path in the current frame stays end-to-end differentiable and trained by the existing losses; the memory is an extra INPUT of the link head: the previous keyframe's own output (nodes and long links), moved into the current frame by the ego motion and reduced to four numbers per long-link candidate. That input is data from the previous step, like the ego pose: it is detached, no gradient runs back in time (named, as the card of a recurrent design must). The association of a candidate with a previous link (nearest within 2 m, a hard lookup on detached data) is a selection outside the gradient and is named as such; a soft (Gaussian) association is the alternative if the cliff at 2 m shows in the pictures. No rule step is added to the delivered graph. Outside the network stay what B already has: the threshold 0.5 and the ego-motion warp (a fixed transform, not a decision).

## 2. Design (outline; the detail plan is written only if the pre-check says GO)
- **Where the memory enters.** Only the long-link candidates of `qlinks.py` get a memory term: the pairs of the top `KL` = 64 nodes by `uout` times the top 64 by `uin` (the default of `LinkHead.forward`; the docstring says 32, which is stale), 8 m < distance <= 100 m, forward cone, at most 4,096 pairs per frame, and, in training, the GT pairs that are forced into the candidate list. The link flag is `is_long = distance > 8 m` for every candidate, also for the pairs of 8 - 11.4 m that come from the short mask (14 - 16 % of the delivered long-flag links): the memory term covers every candidate with the flag, as `long_persist` does. The cost of the association (candidates times previous long links, per frame) is measured in the smoke. Per candidate (u, v): m1 = the highest probability among the previous keyframe's long links whose two warped ends lie within 2 m of u and v (0 if none), m2 and m3 = the existence probability of the nearest previous node within 2 m of u and of v (0 if none), m4 = 1 if the frame has a previous keyframe. The term is added to the link logit through a 4 -> 16 -> 1 MLP whose last layer starts at zero.
- **The warp.** The pose files `~/exp_gcar_b123/poses_{train,val}.npz` (`R`, `t`, `scene`, `prev`; outside git, built with the B123 features; their path, size and date are written into every result file); the convention "the pose acts on the lane frame" was found from the GT nodes in E276 (median alignment 0.49 m); the first keyframe of a scene has `prev = -1` and gets m4 = 0.
- **Training.** Phases 4 5 6 7 from the phase-3 checkpoints as in the E273 recipe. The previous keyframe goes through the whole network under `no_grad`, **with `gt=False`** (the default `gt=True` of `QGraph.forward` forces the GT nodes and links into the candidate lists and would leak labels into m1 - m3), with the current weights and without memory (a one-step truncation); the current frame runs with memory. Phase 4 trains the memory term on the final-to-be node outputs; phase 5 retrains the whole node head afterwards and phase 6 trains only the section encoder and the assignment (`PHASE_FROZEN` freezes the links in 5 and 6, so the memory term is trained in 4 and 7 and phase 7 must repair what phase 5 changed). The previous-frame pass is also needed in phases 5 and 6, where the links are frozen but their input changes.
- **Inference.** One buffered output (the previous keyframe's nodes and long links); the first frame of a scene runs with m4 = 0.
- **Not in this card:** a memory over several frames, memory for nodes and sections, memory for the short links, a recurrent state in the features, a soft association. They stay candidates if v helps.

The previous keyframe of a frame is `prev` of the pose file (851 of the 873 frames have one, all inside VAL; the 22 first frames of a scene have none and run as 'no previous' in the read-outs and are left out of the AUC test). **Disclosure:** the critic's rehearsal (section 8) ran approximations of tests 1 and 2 BEFORE this gate was fixed and the author has seen its numbers (AUC gains of at most +0.013 pooled; persistence of the variants V1 - V5 between +0.04 and +0.09); the gate and the variants below were fixed after that, so this pre-check is not blind; the persistence band of 0.10 and the gate level of 0.05 are the values of the card before the rehearsal.
- **The memory features of a link of frame t** are computed from the previous frame's dump only (the raw probabilities, never a fused value, so there is no recursion in test 1): both ends of the previous frame's long links moved into frame t (the convention is re-found on 40 pairs from the GT nodes and must align them below 1.5 m), m1 to m3 as in section 2.
- **The label** is the P9 pair rule of E276: a long-flag link whose two ends are delivered nodes (e >= 0.5), each matched one-to-one to a GT node within 2 m, is RIGHT when the two GT nodes are joined by a GT link; links with an unmatched end are left out of the card's AUC (neither right nor wrong; they are 43 % / 46 % of the delivered long-flag links and ARE in `long_persist`), and the alternative label 'right against everything else' is reported. The pair rule is a lower bound of what the graph scorer calls right; it has no access to the previous frame.
- **Test 1 (is there information?).** AUC for 'right' among the long-flag candidates (p >= 0.05, both ends delivered, both matched) of gradient boosting on S1 = (p, link length, e at both ends; the current frame only) against S2 = S1 plus m1 to m3; two folds by scene (fit on one half of the scenes, score on the other), per seed, **pooled and in the decision band p in [0.3, 0.8]** (the pooled AUC is dominated by easy negatives). Reported: a strong current-frame baseline (S1 plus directions, flags, handle scales, the competing candidates at each end) with and without the memory.
- **Test 2 (what a hand-made read-out does).** The long-link decision replaced by a function of the frame's p and the previous frame's m1 (short links unchanged), scored by the E273 scorer on CPU like the P10 read-outs (topo F1, junction F1, F1@1.0, lanes found), together with `long_persist` (between the consecutive frames' read-outs of the same variant), the number of delivered long links and the pair-rule precision of the delivered long links (the stand-in for `link_long_P`, which the dump-based read-out does not produce). The variant `none` must reproduce the stored E275 card of B to 0.0000 (as P10 and P11 did). The family, declared now: V1 average, deliver if (p + m1) / 2 >= 0.5; V2 filter, p >= 0.5 and m1 >= 0.3; V3 hold, p >= 0.5 or (p >= 0.25 and m1 >= 0.5); V4 wide hold, p >= 0.5 or (p >= 0.1 and m1 >= 0.5); V5 strong filter, p >= 0.5 and m1 >= 0.5; V6 recursive average, f_t = (p_t + f_(t-1)) / 2 with f_(t-1) the fused value of the matching previous link (0 if none), deliver if f_t >= 0.5 (the chain, like v).
- **Arm h is picked by this rule, written now:** among V1 to V6 the one with the largest `long_persist` gain over `none` (mean of the two seeds) whose topo F1, F1@1.0, junction F1, lanes found and pair-rule long precision lose no more than the floors of the verdict rule on BOTH seeds; if none qualifies, h is V1 and is reported as 'with loss'.
- **Outcome:** **GO** (learned memory) if the gain AUC(S2) - AUC(S1) is at least 0.05 in both folds on both seeds, pooled OR in the decision band. **STOP-HAND** (no learned memory) if GO fails but some variant gains at least +0.10 in `long_persist` on both seeds within the floors: the finding goes to Mirko as a candidate read-out (a rule step on the output, D55 gap named), the card is closed for the learned part; the neighbours of the chosen variant are reported because the bar is close to the effects seen. **STOP** otherwise: the card is closed with the reading of section 1 ("the previous frame does not tell right from wrong, and a hand fusion does not stabilise enough"). In-sample VAL, a design check, not a verdict. Cost: CPU only, about 30 min per seed, the two seeds in parallel.
