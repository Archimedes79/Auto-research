# 2205.02833 Cross-view Transformers (CVT) for real-time map-view semantic segmentation

| | |
|---|---|
| source | https://arxiv.org/abs/2205.02833 (CVPR 2022 oral) |
| fact status | checked (abstract page, GitHub README, search snippet); IoU table not read |
| groups | F4: 3; A1: 2 |
| code / licence | https://github.com/bradyz/cross_view_transformers, MIT (README) |
| verdict | use (fast camera-to-BEV baseline with a pretrained backbone) |

**What it does**: Per-camera pretrained EfficientNet-B4 features at two scales (1/8 and 1/16; snippet), camera-aware cross-view attention maps them to a learned BEV query grid. Position embeddings depend on intrinsics and extrinsics, with no depth and no explicit projection. Output is a 200 x 200 map for a 100 m x 100 m area (0.5 m cells, i.e. our grid) with vehicle and road/lane classes.

**Results that matter**: abstract: state of the art on nuScenes with about 4x faster inference; README: 45 FPS demo. Per-class IoU not read here. RoboBEV (RB17 in the table) gives CVT 0.348 IoU clean.

**Transferable technique**: calibration-conditioned attention replaces lifting; a small cheap trunk gives a BEV at exactly 0.5 m. For a front-camera-only input one camera view with a learned query grid reduces the transformer to a single cross-attention. Radar BEV could be concatenated after the map-view features.

**Cost and fit**: small enough for a 3060; MIT licence; the loss is focal/BCE per class (not verified here). Vehicle-only and road classes, no thin-lane classes.

**Doubts**: low-resolution features limit thin structures; no velocity or boxes; front-only coverage untested.
