# training - code of the camera + radar BEV system

Plain PyTorch (env `gcar`: PyTorch 2.8, Python 3.12, no mmcv). Every module has a self-test with known answers (`python training/<module>.py`).

| file | what it does | self-test |
|---|---|---|

| `radar_encoder.py` | radar block that keeps the information (plan.md 3.4): delta-coded slot raster (K = 3 exact slots + remainder mean + count; per slot valid, dr = r - \|c - s\|, dpsi = psi - bearing(c - s), Doppler code, rcs, age, sub-cell offset, ray origin s; position = cell index + offset, r and psi decoded exactly from cell + origin + residual) -> two 3 x 3 convs, LeakyReLU, C >= inputs, pass-through start; `aux_loss` = tolerance-weighted reconstruction as a SIDE loss with `aux_weight(step)` decaying to a floor (the task losses are the goal), `kept_fraction` = measurement of what the features still hold (no gradient), `forward(..., with_state=True)` = the lossless raster as explicit stream; `rasterize_delta_slots` / `unpack` / `decode_slots`, `new_decoder` for probing frozen features, `static_weight(state)` = a parameter-free static prior of every cell from the Doppler of the raster (exp(-(vr / sigma)^2), count-weighted over the slots; 1.0 for an empty cell; necessary, not sufficient: a crossing object reads about 0) for a radar memory, to be multiplied with the learned static map | exact round trip of eight fields (two frames, several sensor poses), residual bound, overflow + remainder mean, Doppler wrap, supplied ray origin, module shapes, side-loss gradients, pass-through start has the lower side loss than a default start, Doppler static weight (static 1, moving 0, mixed cell, overflow cell with a moving remainder, empty cell 1.0, frames do not mix) |

| `motion_block.py` | velocity field at time k from two camera BEVs (current + an older frame ego-aligned to k) + the fixed radar raster (count, linear Doppler, ray, age) in a small pyramid (2 / 1 / 0.5 m): backward warp with the coarser v, Doppler residual u . v - vr, ray / range channels, a zero-init update per level; returns every level (deep supervision); the fused flow model of plan 7.4 without correlation, on model features; `block_inputs` builds its inputs from the model's own camera frames, ego steps and radar (t15 joint form: `ModelConfig.motion_block`, `motion_strides`, `box_vel_from_field`, wired in `model.py`) | warp sign with a known v, radar raster means and pooling, zero start, gradient to all 42 tensors after one step, learns a blob velocity (0.53 m/s after 150 steps), `block_inputs` (older frame ego-aligned, dt, raster, one frame refused); 294 k parameters at 64 input channels, 120 x 104; `tests/test_slots.py` rows `motion_block`, `motion_strides` and the combinations with `box_vel_from_field` |
| `temporal_fusion.py` | per-branch temporal fusion, ONE class for camera and radar: current planes + the last K original frames brought in by `splat_window` (aggregated with mass x exp(-age / tau) x a learned relevance; summed mass and mean age as channels) + a static memory in a WORLD-ALIGNED grid (written once and read once per frame, never resampled, so nothing blurs or lags; lossless re-centring by whole cells; moving content kept out through a velocity-derived static weight) -> conv3x3.
