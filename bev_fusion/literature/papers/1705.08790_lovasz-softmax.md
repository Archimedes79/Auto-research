**What it does**: loss(f) = (1 / |C|) sum_c Delta_Jc(m(c)), the Lovasz extension of the per-class Jaccard loss evaluated on the vector of pixel errors m_i(c) (1 - p if the pixel is class c, else p) sorted in decreasing order; piecewise linear, exact for hard labels, convex-extension gradient via cumulative FP / FN along the sorted order. Per-image vs per-batch IoU matters; the authors average only over classes present in the batch. Binary version: Lovasz hinge.

**Results that matter** (paper): Pascal VOC multi-class test mIoU (DeepLab-v2, multi-scale + CRF) cross-entropy 76.44, + equibatch 78.05, Lovasz-Softmax + equibatch 79.00; binary VOC image-IoU 77.14 (CE), 75.8 (hinge), 80.5 (Lovasz hinge); Cityscapes ENet fine-tuned class IoU 58.29 -> 63.06 (iIoU 34.36 -> 34.06). Cost: sort O(p log p) per image or batch.

**Transferable technique**: only as a final fine-tune of the IoU of the 3 dense-object groups and the area layers on hard thresholded GT; our coverage targets are fractional while the loss is formulated for hard class labels (the error vector m is built from the label) - the soft-label-correct alternative is JML2 of 2303.16296.

**Cost and fit**: a sort over all cells of a channel (a 200 x 200 grid = 40k elements per channel per frame, cheap on GPU); ignore labels are removed before the sort in the common implementations (index 255), which maps onto weight 0 cells; no per-cell weights between 0 and 1.

**Doubts**: networks were fine-tuned from a CE model (no from-scratch result); gains arrive late in training; per-image optimisation can hurt dataset mIoU; piecewise-linear loss may destabilise SGD; the paper does not discuss ignore labels.
