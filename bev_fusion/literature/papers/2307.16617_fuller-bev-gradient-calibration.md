**What it does** [checked]: two calibrations on a BEVFusion-style camera + LiDAR model (VoxelNet + Swin-T + LSS, 2-layer FPN fusion, DETR-style detection head and query-based segmentation head). Inter-gradient (between tasks): IMTL-G, the closed-form weights that give the aggregated gradient equal projection on every task gradient, computed at the LAST layer of the shared backbone only (cheap). Intra-gradient (between sensors): gating factors from the LiDAR and image gradient norms, smoothed with momentum (alpha 0.1, m 0.2), scale each modality branch's gradient before it is propagated. The paper's abstract: +14.4 % mIoU for map segmentation and +1.4 % mAP for detection on nuScenes.

**Results that matter** [checked, nuScenes val, Table 3, multi-task with shared head]: BEVFusion-adapted multi-task baseline (losses 1:1) mAP 59.1 / NDS 65.0 / map mIoU 44.0 -> FULLER 60.5 / 65.3 / 58.4; Delta_MTL against single-task models 18.3 % (1:1) -> 5.4 %. Single-task references of the same lightweight models: detection mAP 62.1 / NDS 66.6, segmentation mIoU 62.3; the original BEVFusion single-task models are 68.5 / 71.4 and 62.7. A three-task variant (foreground segmentation added): baseline 59.9 mAP / 65.8 NDS / 46.9 map mIoU / 58.1 foreground mIoU, FULLER 58.6 / 64.6 / 57.1 / 62.0, so mAP falls by 1.3. The ablation of IMTL-G against other balancing (PCGrad, uncertainty) is deferred to an appendix and compared only against GradNorm in a figure [checked: no PCGrad or uncertainty-weighting baseline in the text read].

**Transferable technique**: take the gradients at the shared BEV feature, not at the parameters. For our four groups: `g_k = torch.autograd.grad(L_k, bev_feat, retain_graph=True)` (k head backward passes, no trunk), form the 4 x 4 Gram matrix, solve IMTL-G (closed form) or a UPGrad / CAGrad projection, then ONE backward of the combined direction through the trunk: `bev_feat.backward(sum_k w_k g_k)`. Log the cosine between the four g_k every N steps first: it shows whether groups conflict at all (areas against lines against objects against motion) before any method is paid for.

**Cost and fit**: no overhead figure in the paper ("to save computation, we select the last layer of the shared backbone"). IMTL's own timing for the feature-level trick (2021 paper): 1.776 s / iteration against 1.201 for equal weights on Cityscapes (+48 %), against 2.769 for parameter-level IMTL-G. For us the cost is 4 head backward passes + 1 trunk pass; the memory is the four feature-gradient tensors (K x B x C x H x W floats; at C = 64, 128 x 256 cells, B = 4: about 0.13 GB per 4 groups) [memory: arithmetic, not measured].

**Doubts**: the baseline (1:1 loss weights, map mIoU 44.0 against 62.3 single-task) looks badly weighted; a hand-tuned weight (BEVerse uses [1, 10, 1] for detection / map / motion) was not tried, so part of the 14.4 % may be a weighting effect (compare 2209.11379); camera + LiDAR, no radar, no motion or distance-field task; three-task variant loses detection; no code.
