**What it does** [checked]: ResNet-18 on a 360 x 480 input; the last two stages use stride 1 with dilated 3 x 3 convolutions, one Transformer layer follows; feature map F is 45 x 60 x 64 (stride 8). Anchors are straight 3D rays: origin (x_s, 0, 0) with x_s spaced 1.3 m, 17 yaws (0, +-1 .. +-30 deg), 7 pitches; each anchor carries 10 points (20 on OpenLane) at fixed forward positions (5 to 100 m on ApolloSim and OpenLane). Each 3D point is projected with K and the ground-to-camera transform, u = Wf/W * u~/d and v = Hf/H * v~/d, and F is sampled bilinearly there; the sampled features of an anchor are concatenated and regress class, x / z offsets and visibility. The anchor is updated and re-projected (1, 2 or 3 iterations, Table 6). An equal-width loss and a global refinement are applied to "the challenging distant parts due to low resolution" (the authors' own words).

**Results that matter** [checked, tables as returned by the summariser]: OpenLane val F1 53.1, X error near / far 0.300 / 0.311 m, Z error near / far 0.103 / 0.139 m; EfficientNet-B3 version F1 56.0. ApolloSim balanced scene: AP 97.2, F1 95.6, X near / far 0.052 / 0.306 m, Z near / far 0.015 / 0.223 m. ONCE-3DLanes F1 74.44. Table 5: sampling the raw front-view features gives F1 53.1 against 47.6 for sampling a BEV image or BEV features (-5.5 F1 for building a BEV first). Speed on one 2080 Ti: 87.29 FPS, 38.1 GFLOPs, 12.2 M parameters (PersFormer 5.58 FPS, 572.4 GFLOPs, 54.9 M). The only backbone comparison is R18 vs EfficientNet-B3; there is NO feature-resolution or input-size ablation.

**Transferable technique**: (1) a pull from a stride-8 feature map at a 360 x 480 input is enough for far lanes of an OpenLane-type benchmark (far X error 0.31 m versus 0.30 m near, matched lanes only); (2) stride 8 is reached on a pretrained ResNet-18 by setting the stride of the last two stages to 1 and dilating, no decoder needed (cost: FLOPs of the late stages, 38 GFLOPs in total); (3) the sample is taken from the front-view map directly, the paper's argument and ablation say a BEV intermediate loses context ("original FV features retain richer context around lanes"); (4) iterative re-projection (anchor moves, features are re-sampled) is an unrolled pull that refines far points; (5) pitch and yaw anchors are an explicit geometry prior for thin structures. Our lift is the same op plus a depth weight; this paper has no depth distribution at all (the geometry is the anchor's explicit 3D position).

**Cost and fit**: small and fast; output is anchor-based lane polylines, not a dense BEV, so only the sampling pattern and the stride choice transfer, not the head. Dilated late stages are a drop-in change of our light encoder if we want stride 8 without an FPN.

**Doubts**: OpenLane / ApolloSim (Waymo-based images, a different camera and a 100 m forward range), not nuScenes; near / far errors are computed on matched points only, so far RECALL (our 0.17 vs 0.81 problem) is not shown; no resolution ablation, so "360 x 480 is enough" is a statement about this benchmark's F1; the claim that sampling FV beats BEV is confounded by the anchor design; the original image size 1920 x 1280 is from memory, not from the page read.
