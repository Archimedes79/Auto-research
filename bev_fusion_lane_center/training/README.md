# training - the system (models, data, losses, training, inference)

Long-lived code of the lane-graph chain. All modules are imported flat (`import p16_builder as PB`); the launcher `tools/env/_py14.sh` puts every folder on `PYTHONPATH`, so a module can move between the folders below without breaking imports. **New model code goes here; one-off analysis does not (that is `temp/`).**

> **Reference system (D89, 2026-11-13): kept, marked, not developed.** The route-graph chain of loops 8 - 18 (`p8_*` / `p10_*` / `p13_*` - `p18_*`: builder, route heads, junction head, assignment, map registration, the loop-16 pipeline and `p16_*` / `p17_*` / `p18_*` drivers and trainers, `grid/chain*.py`, `train/dense_head.py`) stays in the tree so that the prototype of record (`recall_sp0_dp`, TEST 0.740) and the E272 chain can be re-scored and compared (`evaluation/evaluate.py`, `vertex_eval.py run_ref`, `qgraph_run_eval.py chain_vertices`). **New work does not build on it:** the lane head of E273 and later (`grid/`, `train/qgraph_train.py`, `jends` / `jmaps`) is the system; the reference system gets bug fixes only. The question of removing it (decoupling the scorers first) is D89, option B, not chosen.

## Ground rules
- Everything that trains must be resumable and must write `log.txt` / `train.log`, `log.jsonl`, `config.json`, `status.json`, `model.pt` into `runs/<name>/` (use `trainer.fit`: that is the Training contract; retrofit `p17_mapft.py` first - its crash at 3500 / 4800 steps lost 2 h).
- Metrics are not defined here - call `evaluation/` (`sparse_lanes`, `lane_grid`).
- Cached foundation features are read from the WSL home (`~/exp_gcar_b123`, `data/README.md`); nothing here writes there except `prep/`.
- Speed is a criterion: a change of the pipeline keeps the graphs identical (`evaluation/drivers/p16_fast_check.py`).
