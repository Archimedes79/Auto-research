# tools - the few reusable helpers

Python tools run through `tools/env/_py14.sh <script>` (conda env `gcar`; the script is found by name; `PYTHONPATH` covers all code folders). Code of the system is in `training/`, metrics in `evaluation/`, report builders in `reports/build/` - not here.

| tool | use |
|---|---|
| `env/_py14.sh`, `_pyr.sh`, `bflc_env.sh` | the launchers: run a script in `gcar` (`_pyr.sh` retries on CUDA 'unknown error'); `bflc_env.sh` sets the module search path (sourced by both). `export_env.sh` -> `environment_gcar.txt` / `.yml` (package list of 2026-10-24) |
| `env/setup/` | one-time scripts that rebuild the GaussianCaR environment and its rasteriser: `setup_gcar_env.sh`, `gcar_nvcc.sh`, `gcar_build_rast.sh`, `gcar_patch_rast.sh`. Not run day to day. The other setup scripts (WSL, DNS, CRN env, downloads) are in `../_to_delete/cleanup_2026-10-24b/tools/env/`. |
| (moved) | the general tools - launcher `run.py` (ledger row, commit + tag per run, `--after`, TEST guard), `ledger.py`, `schedule.py`, `decide.py`, `check_numbers.py`, `check_structure.py`, `clean_temp.py`, `selftest.py` - are in `../../autoresearch/tools/` (README there); they read this problem's paths from `../project.json` |
| `viz/render.py` | result images of lane graphs: `render_frame`, `render_compare` (several methods, same frame), `render_grid`, `frame_array`, `montage`; built on `viz_graph.py` (arrows, split triangles, merge diamonds, raster background). `viz/selftest.py` |
| `viz/assign_view.py` | picture + video of the assignment of the sparse lane vertices to the SD-map roads (real VAL frames: delivered graph of a registry system + its SD map, `training/grid/assign.py` with start values): map roads with direction, vertices coloured by road, dustbin crosses, the assignment matrix, perceived mass per road against ground truth. `assign_view.py recall_sp0_dp --scene 7 --frames 16 --every 2 --video` |
| `viz/grid_view.py` | pictures + video of the grid chain on real VAL frames (E271): the 1 m centre-lane map, the head's vertices against the prototype's node ids and the ground truth with per-frame cov5 / prec1 / vertices per 100 m, the assignment of the vertices to the SD roads (start-value assigner), the front camera. `grid_view.py e271_a_s0 --scene 7 --frames 16 --every 2 --video` (CPU is enough; run it with `CUDA_VISIBLE_DEVICES=` while a training holds the GPU) |
| `prototype/` | the ready-to-use prototype (D28): `lane_prototype.py <registry name> [--scenes ...] [--frames N] [--video] [--fresh]` writes the delivered lane graph planner-ready (one JSON per scene, ego frame x forward / y left), summary.json / .md with the numbers of `evaluate.py` on those frames and the stored ms per frame; `make_results_video.py` (results video, moved from `temp/loop21/`); `test_lane_prototype.py`. README there (JSON fields) |
| `video/make_video.py` | result videos: `graphs_to_video`, `frames_to_video`, `side_by_side`; mp4 (OpenCV) or gif by file extension; no ffmpeg needed |
| `catalogue/` | experiment catalogue and table: `e2e_catalogue.py` (what / result / tag per experiment), `e2e_basis.py` (building blocks, K ids), `build_experiment_table.py` (-> `experiments/EXPERIMENT_TABLE.*`, `experiment_execution/plans/Experiment_Table_EN.md`), `p16_catalogue.py` (`dump_catalogue_json.py` and `lit16_merge.py` had no reader / no input left: moved to `../_to_delete/cleanup_2026-10-31_review/` on 2026-10-31) |
| `literature/catalogue.py` | literature catalogue: `render` (404 notes + register + `literature/papers.csv` -> `CATALOGUE.md`, the one paper reference with the code table at its end, and the generated blocks of `OVERVIEW.md`), `check` (ids, links, extraction files, verdict and reason codes, port cards), `all`, `selftest`. Plain python 3 (`wsl python3 tools/literature/catalogue.py all`), no GPU. Described in `../literature/OVERVIEW.md` section 5 |
| `literature/code_digest.py` | factual skeleton of a read-only repository checkout: licence files, version pins, file inventory with heavy-dependency flags (mmcv, spconv, custom CUDA), outline of classes / functions with line ranges and first docstring line, keyword index (loss, assign, merge, decode, metric ...); parses with `ast`, never imports or executes, reproduces no bodies, reads the commit from `.git/HEAD` without running git. `python3 tools/literature/code_digest.py <checkout> --paths <sub-paths> --out literature/code/<repo>.skeleton.md`; `selftest`. Process: `../literature/code/README.md` |
| `maintenance/` | `run_all_tests.sh` (every self-test of the product, the evaluation and the general tools), `CLEANUP_LIST.md` (open cleanup items with sizes and recommendations); `make_structure.py` writes `../temp/STRUCTURE.md` (folder tree with sizes, on demand) and regenerates `../models/REGISTRY_ALL.md`; `reproducible.py` (D11) answers: would things work if the working folder were deleted? (git policy, imports of untracked modules, rebuild manifest `../data/rebuild.json`, clone of HEAD + cheap checks; `selftest` included) |
