**What the three do** [checked abstracts]:
- 1705.08781 (submitted 2017-05-24, v2 2017-11-07): a Bayesian filter builds a DOGMa (occupancy + per-cell velocity estimates), a deep CNN predicts its future; the input is a single time step of the grid of spatially distributed velocity estimates, no raw sensor sequences, and the grid format does not depend on the sensor set-up; labels are generated fully automatically (past and future DOGMa estimates separate dynamic from static cells); a pixel-wise loss balancing handles the static / dynamic imbalance; compared against a Monte Carlo simulation; the section outline shows "Filtered Dynamic Input", "Automatic Output Label Generation", "Spatial Balancing Loss", multi-modal scene evolution in the evaluation.
- 1802.02202 (2018-01-30): single-stage CNN from ONE DOGMa to object hypotheses (shape, position, orientation, existence score); offline forward / backward tracking labels with misdetections handled by a custom loss; AP 75.9 % (abstract), several objects found that the labeller missed.
- 1805.08986 (2018-05-23): adds a recurrent network on a DOGMa TIME SERIES for static / dynamic separation and object tracking; AUC 0.946 for dynamic / static segmentation; better occluded-object detection (abstract; laser scanners).

**Transferable technique**: (1) evidence that a CNN on a velocity-carrying grid can learn context-dependent behaviour that the particle filter cannot (interaction, multi-modal evolution); (2) automatic labels from forward / backward tracking (the label recipe for velocity when a dataset has no per-cell velocity: nuScenes has box velocities and tracks, see plan.md section 7.2 on CRT-Fusion's recipe); (3) class-balanced pixel loss for the rare dynamic cells.

**Cost and fit**: laser inputs only; the filter runs outside the network, so no gradient reaches the velocity estimate, the very thing our block avoids. None of the three uses radar Doppler.

**Doubts**: abstract-level reading; the numbers of 1705.08781 are not in the abstract and were not read.
