# 2011.04841 CenterFusion: center-based radar and camera fusion for 3D detection

| | |
|---|---|

| fact status | checked (abstract page) |
| groups | F4: 2; A1: 1 |
| code / licence | https://github.com/mrnabati/CenterFusion, licence not checked |
| verdict | context (front-camera + radar baseline; image-plane, not BEV) |

**What it does**: A CenterNet-style image detector gives 3D box proposals; radar returns are associated to each centre by a frustum, and the associated radar features (depth, velocity, RCS) are fed to secondary heads that refine depth, rotation and velocity.

**Results that matter**: nuScenes NDS improved by more than 12 percent over the camera-based baseline (abstract); velocity error improves significantly without temporal input. No absolute numbers on the page.

**Transferable technique**: radar gives velocity and depth at the object centre; in a BEV system the same effect comes from rasterised radar channels (Simple-BEV, SN06) under a CenterPoint head. Useful as the single-camera + radar baseline.

**Cost and fit**: single-camera pipeline, DLA backbone; cheap. Image-plane association cannot give a BEV lane head.

**Doubts**: older, weak depth; the frustum association is a rule step that breaks end-to-end gradients.
